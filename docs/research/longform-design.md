# 8分を超える横型動画は、どう設計すべきか(2026-08-17)

ユーザー指示:
> あと2本長尺の横動画を次は作りたい。アップロード日は21, 23日を予定してる。
> やはり一本はNISAに関連した動画を作るのが良いかも。8分を超える動画はどのようで
> あるべきか。これまでの動画作りの経験を活かして(特に褒められている箇所)案を出して欲しい。

ショートの設計は `docs/research/plot-playbook.md` にある。
**長尺はショートの引き伸ばしではない**ので、何が変わって何が変わらないかを先に決める。

---

## 1. ショートと長尺で、決定的に違う1点

**ショートは押し付けられて見られる。長尺は選ばれて見られる。**

この1点から、ほぼ全部の違いが出る。

| | ショート(縦・60秒) | 長尺(横・8分) |
|---|---|---|
| 視聴者は | フィードで**偶然**出会う | タイトルとサムネで**選ぶ** |
| 冒頭の仕事 | 指を止めさせる | **選んだ判断が正しかったと確認させる** |
| 専門語 | 入口では使えない | **タイトルで使ってよい**(むしろ争点を明示する) |
| 構造 | 1本 = 1つの鎖(L1) | **章 = 1つの鎖**。それを3〜5章 |
| 離脱 | 最初の3秒 | 各章の**継ぎ目**(90秒ごと) |
| 図 | 縦なので棒2本が限界 | **横なので6本並ぶ**。表・折れ線が主役になれる |

**冒頭で出し惜しみをしない。** ショートでは結論を最後まで引っ張るが、長尺では逆で、
最初の60秒に**答えを1つ出してしまう**。視聴者はサムネの問いに答えが返ってくるか
確認したくて開いており、返ってこないと90秒で閉じる。
出した答えのあとに「ただし条件がある」を置くのが、8分を持たせる本体になる。

## 2. 構造 — 「章 = ショート1本」にする

これまで褒めていただいた箇所は、全部**同じ形**をしていた。

| 回 | ご評価 | 何をしていたか |
|---|---|---|
| S014 | 「プロットの流れ自体はとても良い」 | 問い→数字で答え→**具体的な行動3つ** |
| S016 | 「良いね」 | 問い(いつの所得?)→答え(去年)→**実害**(辞めた翌年も来る) |
| S011 | 合格 | 種の数字2つ→全部そこから導出→**75歳という1点** |
| ループ62 | 「どっちが得して、どっちが損か、そこまで落とし込みたい」 | (要求) |

共通しているのは **問い → 自前計算 → 損得の判定 → 実害か行動**。
これは60秒でも8分でも変わらない。だから長尺は、**この形を章として3〜5回くり返す**。

### 章の型(1章 = 90〜150秒)

```
① 章の問い を1文で言う        (10秒)
② 前提を置く(誰で・いつの制度で計算するか)  (15秒)
③ 数字を1本の鎖で積む          (60〜90秒)
④ 損得の判定を1文で言い切る     (10秒)  ← ここが章の出口
⑤ 次の章の問いを立てる          (10秒)  ← ここが継ぎ目の橋
```

**④を毎章置くことが、長尺でいちばん効く。** 90秒に1回「で、結局どっちが得なのか」
の答えが返ってくる状態にする。これが無いと、章の継ぎ目がそのまま離脱点になる。

**⑤で次の章の問いを立てる。** 「では、◯◯の場合はどうなるのか」と**問いの形**で
橋を架ける。章のあいだに「まとめ」を挟まない(まとめは離脱の合図になる)。

### 全体の型(8〜10分)

```
0. 冒頭            60秒   問い + **答えを1つ出す** + 「ただし条件が3つある」
1. 章1             120秒  いちばん多い場合(基本ケース)
2. 章2             120秒  条件が変わる場合(逆転する場合)
3. 章3             120秒  いちばん損する場合
4. 章4(行動)      120秒  **で、どうすればいいのか**を具体案で
5. 締め            40秒   3章ぶんの判定を1枚の表にして、時点表記と免責
                  ─────
                  約 9分
```

章4を必ず入れる。ループ61のご指摘(「『減らすのを止める』って具体的にどうすれば
いいのか案を出す」)は長尺でも同じで、**8分見た人は行動を期待している**。

## 3. 長尺で変わらないもの(ショートのルールをそのまま持ち込む)

- **L1 章 = 1つの鎖。** 章の中で数字は導出でつながっていること(`check_ikko.py` を章単位でかける)
- **W7 専門語は略さない。** 「変動金利」を「変動」にしない(`check_ryakugo.py`)
- **W8 尺のために助詞と動詞を削らない。** 長尺は尺に余裕があるので、むしろ守りやすい
- **時点表記。** 「2026年8月時点の制度です」を冒頭とテロップの両方に
- **すべての数字を verify.py で再計算**
- **断定しない・個別商品を出さない**(戦略§6)

## 4. 長尺で新しく要る道具

### (a) チャプター

概要欄に `0:00 / 1:00 / 3:10 …` の形で章を書く。**章題は目次ではなく問いにする。**

```
悪い: 0:00 はじめに / 1:00 NISAの制度 / 3:10 損益通算とは
良い: 0:00 NISAで損したらどうなるのか / 1:00 まず、税金がどう決まるか
      3:10 課税口座なら取り戻せる分がある
```

チャプターは平均視聴時間を上げる方向に効くという報告が実務側に複数ある(確度B。
数値の上げ幅はソースごとにばらつくので、期待値としては使わない)。
**それより確実な効果は「章の出口を自分で決めさせられる」ことで、
その規律がこちらの構成を締める。**

### (b) 横型の図(1920×1080)

縦型では棒が2本しか置けなかった。横型では**6本置ける**。だから長尺では:

| 見せたいこと | 横型で使う型 |
|---|---|
| 3ケース以上の比較 | 横並びの棒(縦型では不可能だった) |
| 時間で変わる | 折れ線。横幅があるので30年ぶんの目盛りが打てる |
| 条件ごとの損得 | **表**(行=ケース、列=金額・税・手取り)。締めの1枚に使う |
| 全体と部分 | 帯1本の塗り分け(S012 で使った形) |

`production/shortlib.py` は 1080×1920 決め打ちなので、
**横型は `production/longlib.py` として別に作る**(共通部分は切り出す)。

### (c) 尺の見積もり

`SEC_PER_CHAR = 0.152` はそのまま使える。
**8分 = 480秒 ≒ ナレーション3000字 ≒ 170ユニット**。ショート1本(320字)の約10倍。

レンダリング時間もおよそ10倍(1本あたり2〜3時間)。
**2本作るなら、企画とレンダリングを直列にしない**。企画→台本→検証まで2本ぶん
先に終わらせ、レンダリングは連続で回す。

## 5. タイトルとサムネ

セクション1のとおり、長尺は**選ばれる**。だからタイトルで争点を明示する。
`competitive-positioning.md` の結論(後発は「大手が言えないこと」で戦う)をそのまま適用:

| 避ける | 採る |
|---|---|
| NISA完全ガイド | **NISAで損したらどうなるのか** |
| 新NISAの始め方 | NISAが**課税口座より不利になる**たった1つの場面 |
| 住宅ローンの基礎知識 | 変動金利は**何%まで上がったら**固定金利に負けるのか |

サムネは**数字を1つだけ**。ショートのカバーで効いている形(大きい数字1つ+問い)を
そのまま横に伸ばす。

## 6. 確度と限界(research-standards.md)

| 主張 | 確度 | 根拠 |
|---|---|---|
| 長尺は選ばれて見られる → 冒頭で答えを出す | **B** | 視聴導線の構造からの推論+実務通説が一致 |
| 章ごとに損得の判定を置くと継ぎ目で落ちにくい | **C** | このチャンネルで褒められた形からの一般化。**自チャンネルで検証する仮説** |
| チャプターは平均視聴時間を上げる | **C** | 実務ブログが中心で数値がばらつく。方向としては一貫 |
| 横型では比較の図が主役になれる | **A** | 画面比の物理的な制約。自分で確かめられる |

確度Cは順序付け(何を先に試すか)にだけ使う。2本出したあとのアナリティクスで検証する。
