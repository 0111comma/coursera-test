# 長尺(横型8分前後)の設計(2026-08-17 全面改訂)

**この文書は一度捨てて書き直したもの。** 初版は「ショートのルールを持ち込む」
「章 = ショート1本」という**引き伸ばしの設計**で、それで作った L001 は
ユーザー判定が「**ゴミ**」だった。何を間違えたかは
`docs/research/longform-loop-2026-08/REPORT.md` に残してある。

いま書いてあることは、13フェーズの調査と実測から出た結論だけ。
各項目の根拠は `longform-loop-2026-08/01〜13` の各ファイルにある。

**そして機械ゲートがある。** 台本を書いたら、焼く前に必ず通す。

```
python3 production/check_long.py videos/<ID>-<slug>
```

音声が無くても字数から推定して走る。**2〜3時間焼いたあとに落ちるのでは意味がない。**

---

## 0. 前提 — ショートと長尺で決定的に違う1点

**ショートは押し付けられ、長尺は選ばれる。**

- ショートはスワイプの流れに割り込むので、**指を止めさせる**のが仕事
- 長尺はサムネとタイトルを見て**選んで再生される**。だから
  - 入口に専門語を使ってよい。むしろ**タイトルで争点を明示する**
  - 速さで気を引く必要がない。**話速を上げない**(§4)

## 1. 尺 — 8分は視聴者のための数字ではない

- **8分はミッドロール広告を入れられる条件**(確度A)。視聴者側の根拠ではない
- **5〜10分の維持率が31.5%**という報告はあるが実務ソース(確度B)
- **60秒で55%以上が離脱する**(確度B)

**尺は内容で決まる。** 企画書に「尺の見込み」を書き、
**場面が3つで終わるなら6分で出す。** 8分に届かせるために薄めない。

> **これは実際にやってしまった失敗である。**
> `check_video.py` に「推定尺8分以上」を**不合格条件**として入れた結果、
> L002 は66ユニット(3.65分)で書き終えたあと**尺の理由だけで+89ユニット足した**。
> **自分で作ったゲートに、自分で内容を薄められた。**
> いま8分の下限は WARN であって不合格ではない。

## 2. 冒頭 — 40秒で答えを出し切る

| 区間 | 置くもの |
|---|---|
| **0〜5秒** | 数字で割り込む。**答えの金額を先に出す** |
| 5〜15秒 | 具体的な約束。何が手に入るか |
| 15〜30秒 | 引っかけ。「ただし条件がある」 |
| 30〜40秒 | 全体量の予告(「4つの章で確かめる」) |

**守ること**(すべて `check_long.py` が落とす)

- **最初の数値は15秒以内。最初の図は20秒以内**
- **定義を冒頭に置かない。** 「価値の約束より先に前提を置く」のが実務側の禁則3番(確度B)
- **章の切れ目を45〜75秒に置かない。** 離脱の山と重なる
- **冒頭で上げた勢いを本題でリセットしない。** 寄り道の章を60秒付近に置かない

## 3. 構成 — 章は4つ。1章100〜130秒

**初版の「章 = ショート1本」は間違いだった。**
研究側では「**60〜90秒ごとの拍**」と「**章という話題のまとまり**」は別物で、
拍は**章の中に**置く(確度B)。拍の間隔を章の長さにすると、
**話題のリセットが90秒ごとに何度も起きる。**

```
冒頭     0〜40s     答えを出し切る。章にしない
章1     40〜160s    本題の第1問
章2    160〜280s    次の問い
章3    280〜380s    次の問い
章4    380〜470s    自分の場合の出し方
締め   470〜500s    表 + 次に見るもの。章に含めない
```

- **章は4つ。9分で5つ以上に割らない**
- **1章100〜130秒。** 60秒未満は前後に吸収し、150秒超は2つに割る
- **締めは独立ブロック。** 章の中に埋めない
- **章の中は PREP**(結論 → 理由 → 具体例 → 結論)。
  起承転結は結論を最後に置く型なので**説明に向かない**(確度B)

### 章の継ぎ目 — 同じ問いを2回言わない

| | 悪い例 | 良い例 |
|---|---|---|
| 前章の出口 | では、来年の利益からも引けないのだろうか。 | (同じ) |
| 章札 | では第4章。来年の利益からは、引けるのか。 | 第4章。**ここで差が2倍になる。** |

**前章の出口が問いを開き、章札は答えの側を予告する。**
初版は6つの継ぎ目のうち5つで同じ問いを2回読み、**28.5秒(全体の6%)を捨てていた**。

章札には **「第N章 / 全4章」** を出す(合図の原則・確度A)。
進捗バーやゲージは作らない(YouTube 自体が進捗バーを持っている)。

## 4. 話速と間

**日本語の話速の目安**(確度B)

| 区分 | 速さ | 場面 |
|---|---|---|
| ゆっくり | 200〜250字/分 | 朗読 |
| **標準** | **300〜350字/分** | **アナウンサーのニュース読み** |
| 速め | 400字/分〜 | ショート・TikTok |

**長尺は標準の上限(約330〜345字/分)に置く。**
`shortlib.use_landscape()` が `SPEED_SCALE` を **1.15** に下げる
(ショートは 1.3 のまま。ループ58のユーザー指摘の結果なので触らない)。

実効 speed と字/分の対応(この環境での実測・確度A):
`1.56 → 427` / `1.45 → 395` / `1.25 → 340` / `1.15 → 311` / `0.90 → 243`

### 止め(間)

**重要な部分の前に間を置くと、その語が強調される**(確度B。ただし秒数の根拠は無い)。

| 場所 | pad |
|---|---|
| ふつうのユニット | 0.15s |
| **章の出口の判定の直前** | **0.6s** |
| 章札の直前 | 0.5s |

**`pad ≥ 0.5` の区間はBGMも切れる**(`LONG_STOP_PAD`)。
これが無いと、ダッキングの release(300ms)のせいで
**間の最中にBGMが戻って盛り上がる**。実測で声より4.6dB下まで上がっていた。
止めは**最低3箇所**。ゼロは不合格。

## 5. 画面 — 基本形は「図 + 語り」

**冗長性の原則**(確度A): 人は**図と語り**から学ぶほうが、
図と語りと画面の文字からよりよく学ぶ。

**境界条件**(確度A): **図の中の短い語句は保持テストで効く**(d=0.47/0.70)。
語りと画面の文字に**わずかな差**があると良く、**差が大きすぎると潰れる**。

- **図のあるユニットを6割以上**(WARN。飾りの図を足して通さない)
- **数字は図の上で言う。** 図なしで言うのは1割以下(**不合格条件**)
- **図が出ない時間を25秒以上続けない**(**不合格条件**)
- **図には文を貼らない。語句(9文字以内)だけ置く。**
  文はナレーションが言う。図の文が字幕と同義になると `check_figure` が落とす
- **図は3〜5ユニット持たせる。** 絵を差し替えるのではなく `step` で数字を足す。
  文字カードは1〜2ユニットで切る。これで絵の持続に緩急が出る

横型でしか描けない図を使う(`production/scenes_long.py`):
左右2列の比較 / 棒6本 / 年をまたぐ帯 / 曲線 / 表 / チェックリスト。

## 6. 立ち絵 — 図の回は消す

**メタ分析(確度A)**: 講師が映っていると保持に小さくプラス、転移は有意差なし、
**社会的存在感・動機づけにプラス**、**認知的負荷は増える**。
**視線計測(確度A)**: 立ち絵があると**図への注視時間が減る**。

**効くものと損なうものが方向が逆。** だから場面で切り替える。

```
文字カードのユニット → 立ち絵を出す
図が主役のユニット   → chara="none"。図に注視させる
章の出口の判定       → 立ち絵を出し、表情を変える
```

図の上に立ち絵がいるのが**5割を超えると不合格**。
初版は 66/66本(100%)で、しかも表情は `normal` が87%だった
(**害だけ受け取って、効きを受け取っていない**状態)。

**ショートには当てはめない。** 55秒の縦型では立ち絵が「話している人」として
機能しており、公開済み11本はそれで通っている。

## 7. 音 — 足さずに抜く

**一貫性の原則**(確度A): 余分な語・絵・音を除いたほうがよく学べる。
Moreno & Mayer (2000) では **BGM+環境音で保持・転移が悪化、効果量1.66**。

だから:

- **章ごとにBGMを変えない。** 章の切れ目は音を足すのではなく**抜くこと(止め)**で作る
- **SEを増やさない**(9%が上限の目安)
- **BGMは外さない。** 研究は**テストの点**の話で、こちらが要るのは**視聴時間**。
  公開済み11本はすべてBGM入りで、ユーザーは一度も指摘していない。
  実測でBGMは声より26.9dB下で、ダッキングも効いている。
  **ただし長尺2本でBGMあり/なしを比べて検証する**(未実施)

## 8. 進行感 — 章の出口に必ず判定を置く

- **各章の出口に損得の判定を1文。** **問いは判定ではない**(不合格条件)
- 出口の1文は**12字以下で言い切る**(ゲートにはしない。書き方の手順)
- **繰り返すのは「積み上がる数字」にする。**
  初版は動かない40,630円を12回言い、積み上がる121,890円は1回しか言わなかった
- 冒頭60秒までに**全体量(何章あるか)を予告する**

## 9. 締めと回遊

- **終了画面は最後の5〜20秒に出せる**(確度A・公式)。**目安は10〜15秒**(確度B)
- **免責を終了画面の枠に置かない**(不合格条件)。
  「以上です」「ありがとう」型の退出の言葉は「**もう価値は来ない**」と伝える(確度B)。
  免責は消せない(戦略§6)ので、**1文に圧縮して画面のバッジに寄せ、位置を前に移す**
- **次に見るものを名指しする**(不合格条件)。名前と、見ると何が分かるかを言う
- 締めにも図を置く(図なし25秒の制約に引っかかる)
- **概要欄の先頭にチャプターを置く。** 目次ではなく**問い**にする。
  時刻は `sl.chapter_lines()` が出す。`make_upload_kit.py` が長尺用のキットを生成する
- 見る指標はショートの「スワイプ継続率」ではなく、
  **平均視聴率 / 30秒地点の残存率 / チャプター別の維持率 / 終了画面のクリック率**

## 10. 日本語の文の組み方

`production/check_bunsho.py` が見る。詳細は `longform-loop-2026-08/04b-japanese-prose.md`。

- **読点は修飾の境界に打つ**(本多勝一の第一原則・確度A)。
  **接続語のあとに読点を打たない。** 初版は読点の78%が主題・主語の直後だった
- **同じ指示語で始まる文を3つ以上続けない**(不合格条件)
- **なくても済む言葉を書かない**(木下是雄・確度A)
- 修飾は**節を先に、句をあとに / 長い修飾語を先に**
- **文末は触らない。** 「〜のだ」の割合はずんだもんの口調で、
  ユーザーが合格させたショートのほうが高い(72%)

## 11. 変わらないもの(ショートと共通)

- 欲求 → 場面 → 決定 → 数字 の順で設計する(`yokkyu-map.md`)
- 1動画1つの問い。鎖は1本(`check_ikko`)
- ラジオテスト(音だけで意味が通る)
- 専門語は使う前か直後に言い換える。一度フルネームで呼んだら略さない
- 数字はすべて `verify.py` で再計算する
- コンプライアンス(戦略§6)と独自性要素2つ以上(戦略§8)

## 12. 確度と限界

**この文書のいちばん大事な限界**:

> **`check_long.py` の15の不合格条件は、まだ人の合否で検証されていない。**
> ユーザーが合格させた長尺は1本も無い。
> 「全部通れば合格する」とは言えない。

- 研究の多くは**学習テストの成績**を測っており、**視聴時間ではない**
- 実務ソースの数値(維持率・クリック率)は**確度Cで、行動を変えていない**
- **自チャンネルで検証すること**: 30秒地点の残存率 / チャプター別の維持率 /
  話速と維持率の関係 / BGMあり・なしの比較 / 終了画面のクリック率

**合否とゲートの結果がずれたら、ゲートの閾値を直す。**
人の判定が上位にある(ループ51の約束)。
