# 横動画(長尺解説・L系)展開プラン — 調査とループ改善計画

作成日: 2026-08-13 / ステータス: 計画(L001着手前)
ショート(S001〜S021)のパイプライン資産を横動画に展開するための調査結果と実行プラン。

## 1. 横動画に必要なもの(ショートとの差分)

| 項目 | ショート(現行) | 横動画(L系)で新たに必要 |
|---|---|---|
| 解像度 | 1080x1920(9:16) | **1920x1080(16:9)** — shortlibの横版レイアウト |
| サムネイル | 冒頭カバーフレームで代替(フィードでは非表示) | **カスタムサムネイル必須**(下記§2) |
| 尺 | 〜60秒 | **8〜12分**(8分以上でミッドロール広告が解禁され収益1.5〜2倍の余地) |
| 台本 | 1文=1ユニット・15前後 | **起承転結 10/70/10/10%**・PREP(結論先出し)・1文20〜30字は共通 |
| 冒頭 | 数字フック1.5秒 | **冒頭30秒が勝負**(大半の離脱がここ。結論or問いの先出し・前置きゼロ) |
| 構成要素 | なし | **チャプター**(概要欄タイムスタンプ)・終了画面・カード・目次画面 |
| キャラ演出 | 立ち絵1体+口パク | **掛け合い(茶番2往復程度)が視聴維持に有効** → 2話者体制を検討 |
| 目標指標 | スワイプ継続率60%+ | **視聴維持率40%+(10分級)、冒頭30秒通過40〜60%+、CTR 4%+** |

- 収益面: ミッドロールは8分以上で有効化(2020年に10分→8分に緩和)。L系は**8分30秒〜12分**を標準尺とする
- 台本量の目安: ショート15ユニット(約250字)に対し、10分なら**約2,800〜3,200字**(現行の話速換算)。verify.py/precheck/kana照合のゲートはそのまま流用可能
- 2話者化: VOICEVOXの四国めたん等を追加すれば掛け合いが可能(ライセンスは同一ガイドライン系)。ずんだもん=ボケ/生徒役、めたん=ツッコミ/先生役の役割分担が定石

## 2. サムネイル(最重要の新規要素)

### 2-1. 必要性の確認

- 横動画はブラウズ(ホーム)・検索・関連動画面でサムネイルがクリックの主戦場。Shortsフィードと違い**サムネなしでは戦えない**
- ただしShorts用の「冒頭カバーフレーム」設計思想(数字ドン+3語)はそのまま横サムネの原型に使える

### 2-2. 技術要件(確認済み)

- 推奨 **1280x720px(16:9)**・**2MB以下**(PCは50MBまでだが2MBに収める)・PNG/JPG
- 設定には**電話番号によるアカウント確認だけでOK(YPP不要)** — Shortsのカスタムサムネ(YPP後)とは条件が別
- 電話番号1つで年間2チャンネルまで確認可能

### 2-3. デザイン原則(調査の要点)

1. **教育系は文字主体**: デザインより言葉。文字を大きく・少なく(メイン7〜13字+補助)。スマホの小さい表示で読めることが基準(視聴の主戦場はモバイル)
2. **ジャンプ率**: 数字を最大サイズでドンと置き、説明語との大小差を極端にする(ショートのcoverと同じ思想)
3. **色は3〜4色に制限**: YouTube UIの赤・白・黒と同化しない**青・黄・オレンジ・緑**を軸に。現行ブランド(紺地+金GOLD+白INK)はこの原則に適合
4. **顔・キャラの感情**: 人の顔(キャラ顔)は視線を集める。ずんだもんの表情パーツ(驚き/困り/ドヤ)をサムネ感情として使う
5. **1サムネ1メッセージ**: 情報を盛ると全部が読まれなくなる。「数字+疑問or逆説」の1本勝負

### 2-4. 本チャンネルのサムネ型(3テンプレ)

ブランド一貫性のため、ショートのcoverシーンを横に再設計した共通テンプレを作る:

- **A. 数字ドン型**: 左=巨大数字(GOLD)、右=ずんだもん表情大、下帯=補助文言。例「178万円|『103万の壁』はもう古い」
- **B. 比較型**: 左右2分割(vs構図)+中央に差額の数字。例「25歳 1,526万 vs 35歳 832万」
- **C. 逆説・疑問型**: 全面テキスト(2行)+キャラ小。例「退職金2000万、税金は?→ 0円」

### 2-5. 制作とA/Bテスト運用

- **production/make_thumbnail.py を新設**: matplotlib/PIL で1280x720を生成。ずんだもんPSDパーツ(gen_zunda_parts.pyの18状態)を流用。文字の可読床はショートの28pt床に相当する**サムネ最小48px床**を設ける
- 各動画で**3案(A/B/C型から)を自動書き出し** → YouTube公式の**「テストと比較」**(最大3枚・視聴時間ベースで勝者判定・結果まで数日〜2週間)にそのまま投入
- 運用ループ: 3案投入 → 勝者のパターンを記録 → 次動画のデフォルト型を更新(= サムネのループ改善)

## 3. 台本・構成の型(L系プレイブック草案)

1. **冒頭30秒**(起): 結論の数字を先出し+「なぜそうなるかを◯分で」の約束+目次チラ見せ。自己紹介・挨拶はゼロ
2. **本体70%**(承): ショート1本分の粒度のブロックを4〜6個連結(例: L001新NISAガイド = S002+S003+S017の知識を再構成)。ブロック毎に小さい数字フック→図解→早見表
3. **転10%**: 誤解・落とし穴・反直感(「ただし…」)。茶番(掛け合い2往復)をここに配置
4. **結10%**: 全体早見表1枚+行動の一歩(申請・確認など事実ベース)+ループ締め
5. チャプターはブロック境界に付与(概要欄タイムスタンプ)。SRTは make_srt.py を流用
6. コンプラ(戦略§6)・時点表記・出典・verify.py必須はショートと完全共通

## 4. ショート資産の再利用マップ

- shortlib.py → **longlib化**(座標系とCHARA_RECTS、字幕帯、BGMループを16:9に再配置。描画関数は共通化済みのscenes_common.pyを横対応)
- ずんだもん状態PNG・口パク・SE・BGM3種: そのまま流用
- ネタ: L001=新NISA完全ガイド(S002/S003/S017を統合)、L002=給与明細の読み方(S004拡張)、L003=ふるさと納税失敗しない(S005拡張)、L004=複利(S001/S006/S018統合) — backlogの解説動画#101〜104と一致
- Shorts→横動画の導線: ショートの「関連動画リンク」に対応するL系を指定(公式の推奨機能)
