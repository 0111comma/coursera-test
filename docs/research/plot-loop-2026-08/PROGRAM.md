## 進め方の約束

- **1時間に1フェーズ**。毎正時にトリガーが発火し、次の未完了フェーズだけを実行する
- 各フェーズは**成果物のファイルを1つ以上残す**。残っていなければ、そのフェーズは未完了
- 各フェーズの終わりに、このファイルの「進捗」表を更新してコミット・プッシュする
- **ユーザーは寝ている。質問で止まらない。** 判断が要る所は決めて、理由をここに書く
- レンダリング(1本15〜20分)はバックグラウンドで走らせ、待っている間に次の作業をする

## 何を直すのか(着手前の診断)

S013 は、フィードバックのたびに**足す**だけで、**引く**をしなかった結果こうなった:

| | S011(ユーザー合格「このクオリティと面白さなら良いよ」) | S013(現行) |
|---|---|---|
| ユニット | 19 | 21 |
| 初出の数値 | 14 | **17(全21本で最多)** |
| 独立した話の数 | **1**(払った額 vs もらう額 → 元が取れる年齢) | **6** |

S011 の14個は**1本の計算で全部つながっている**:
1万7920円 ×12×40年 = 860万円 / 7万608円 ×12 = 85万円 / 860÷85 = 10年 /
65+10 = 75歳 / 81歳−75歳 = 6年ぶん = 525万円。種になる数字は2つだけ。

S013 の17個は**6つの独立した話**に分かれている:
(1) 総額の差1377万円 (2) 75%が変動 (3) 昔8.5% (4) 2024年から上昇
(5) 1%で毎月1万4728円 (6) 5年後3.83%で並ぶ。
どれも事実だが、**互いに導かれない**。だから聞いている側は毎回リセットされる。

**仮説: プロットの分かりにくさは「独立した話の数」で説明できる。**
このプログラムはこの仮説を検証し、機械チェックにし、既存の本に適用する。

## 判断ログ(質問できないので、決めた理由をここに残す)

### フェーズ1(16時台)

- **仮説は裏づけられたが、形を変えた。** 「独立した話の数」より
  **「因果の鎖に載っているか」**のほうが正確。物語理解の研究では、
  出来事の重要さを予測するのは「直接の因果的つながりの数」と
  「冒頭から結末までの鎖の上に載っているか」の2つ。
  数値の個数だけでは合否が分かれない(S011は14個あるのに合格)ことも、
  この形なら説明できる
- **速度と密度はセットで考える。** 話速を1.3倍にしたのだから(ループ58)、
  1秒あたりに投げる新情報はむしろ減らすべきだった。S013はその逆をやっている
- フェーズ2で機械化する基準を L1〜L4 として 01-research.md にまとめた。
  L1(種になる数字は3つまで)を機械チェックの中心に据える
- 計測スクリプト count_nums.py を scratchpad から docs 配下に移した
  (このプログラムの成果物として残すため)

### フェーズ2(17時台)

- **鎖の本数を閾値にし、単発の個数は捨てた。** 単発はユーザー合格判定の S015 に
  5個出る(画面の丸めのせい: 17万円と言うが実額176,700円なので、そこから
  1万4700円を導くと3.8%ずれる)。許容誤差を5%まで緩めると誤爆は消えるが、
  今度は S013 の鎖まで偶然つながって見逃す。
  **誤爆と見逃しを同時に避けられる閾値が無い指標は、閾値にしない**と判断した
- **上限は鎖2本**とした。合格作は1〜2本、問題のS013だけ4本できれいに分かれる
- 現状これで落ちるのは **S013 の1本だけ**。公開済みのS001〜S009も含めて他は全部通る。
  「ユーザーの判断だけを再現し、それ以外を巻き込んでいない」状態を確認した
- 限界も 02-calibration.md に書いた。**これは分かりにくさの検出であって面白さの検出ではない**。
  却下された債券の回(「純粋におもんない」)は鎖1本で通ってしまう。面白さはF1〜F5の担当

### フェーズ3(18時台)

- **絞り込む問いを「変動はどこまで上がったら、固定に負けるのか」に決めた。**
  ループ62のユーザー指摘「どっちが得して、どっちが損か」に答えるには、
  過去の話(75%・8.5%・2024年)を並べるより、**逆転する金利を1つ出す**ほうが直接的。
  しかも答えの3.83%は自前計算(二分法)で出せるので、鎖の終点になる
- **削ったのは3つ**: 「75%が変動」「1991年は8.5%」「2024年から上昇」。
  どれも事実だが、この問いの答えに寄与しない。**別の動画のネタとして plan.md に記録した**
- 毎月の内訳(8万5036円 → 9万9764円)も声で言わないので図からも外した。
  差の1万4728円だけを言う。内訳は概要欄に残す
- 結果: **鎖4本 → 2本**(1377万円→3571万円→4948万円 / 3.14%→3.83%)。
  残った2本は「総額の差」と「それが並ぶ金利」で、同じ問いの表と裏
- 6ゲート(ikko/teinei/flow/figure/overlap/yomi)すべて通過。20ユニット・推定55秒
- **レンダリングはバックグラウンドで開始済み**(18:22)。フェーズ5で検証する

### フェーズ4(19時台)

- **3本とも機械ゲートは上限内。作り替えはしない**と決めた。
  S012 に改善余地(#4「その中身は年金と健康保険」・#5「病気や老後にそなえるお金」が
  問いに奉仕していない)は見つけたが、**ユーザーから指摘を受けていない本を、
  指摘のないまま作り替えるのはリスクのほうが大きい**。記録に留め、
  次に S012 を触るときに適用する。今夜のレンダリング枠は S013 に使う
- **点検の副産物としてチェッカーを1つ改良した。** S014 の 20.315% が
  「繋がらない数値」に出るのを見つけ、原因が実装(最初に見つかった導出だけで
  打ち切っていた)と分かったので、**見つかった導出を全部つなぐ**ように直した。
  効果: 合格作がすべて鎖1本になり、壊れていた旧S013は4本のまま。分離がはっきりした。
  **回帰確認として旧S013(git から復元)を通し、依然NGになることを確かめた**
- 閾値(上限2本)は据え置き。作り直した S013 の2本は
  「総額の差」と「それが並ぶ金利」で、同じ問いの表と裏なので許容する
- 持ち帰り2つを 04-audit.md に記録:
  A1 機械ゲートを通ることと1つの問いに奉仕していることは別(目視の工程を必ず入れる)
  A2 指摘を受けていない本を、指摘のないまま作り替えない(記録して次に適用する)
