# 図の型の選び方(ループ㊺)

ユーザー指摘:「めちゃくちゃ図がわかりづらい。何を伝えたいのかわからない。
伝えたいメッセージは決まってそうだけど、それを伝えるために適している図が何かちゃんと整理されていない」

**その通りだった。** メッセージは決めていたが、図の型を選ぶ手順が存在せず、
毎回「箱にナレーションと同じ文を入れる」で済ませていた。

## 根拠(調査)

| 出典 | 主張 | 本チャンネルへの含意 |
|---|---|---|
| Larkin & Simon (1987) *Why a Diagram is (Sometimes) Worth Ten Thousand Words*, Cognitive Science 11 | 図が有利なのは情報が**位置で索引される**ため。推論に必要な情報が1箇所に集まり、探索がほぼ不要になる。文章表現は逐次的 | **位置・長さ・向き・面積のどれかが意味を持っていない図は、図ではない。** 箱に入れた箇条書きは文章表現のまま |
| Tversky, Morrison & Bétrancourt (2002) *Animation: can it facilitate?*, IJHCS 57 / Tversky "Cognitive Design Principles" | **一致原則**: 図の構造と内容は、望ましい心的表象の構造と内容に対応すべき。**把握原則**: 一目で正確に知覚できること | 「株とお金が逆向きに動く」を伝えたいなら、**図でも逆向きに動かす**。3つの箱を縦に並べても動きは表現されない |
| Mayer, *Principles for Reducing Extraneous Processing in Multimedia Learning* | **冗長性 d=0.87** — 図+ナレーションに、ナレーションと同内容の文字を足すと学習が落ちる(視覚資源の競合) | **図の中の文がナレーションと同義なら、その図は害。** ただし図中の**短い語句**(ラベル)は有効との報告あり |
| 同上 | **空間的近接 d=0.79** — 対応する語と絵は近くに置く | ラベルは対象の上か中。**別行の凡例にしない**(S020の帯グラフはこれを外していた) |
| 同上 | **一貫性 d=0.70** — 本質でない要素を除くほど学習は深まる(23実験中23で支持) | 図から削っても意味が変わらない要素は削る |
| 同上 | **合図 d=0.46** — 本質的な構造を強調する手がかりを足すと学習が上がる | **強調は1つだけ。** 2色を等しく目立たせない |

補足: ショートはミュート視聴が多く、**字幕**は言葉を運ぶ役割があるため残す(B12)。
禁じるのは**図の中に文章を置くこと**であって、字幕ではない。

## 判定表: メッセージの型 → 図の型

企画書に書いた「この動画の結論」を、まず下表のどの型か決める。型が決まれば図が決まる。

| メッセージの型 | 図の型 | 意味を担う視覚要素 | やってはいけない |
|---|---|---|---|
| **AとBの量が違う** | 共通の底からの棒2本 | 長さ | 数字を大きく書くだけ |
| **全体がこう分かれる** | 積み上げ帯1本 | 面積(幅) | 円グラフ / 凡例を別行に置く |
| **時間で変わる** | 折れ線・タイムライン | 横位置=時間 | 箇条書き |
| **前 → 後で変わった** | 2本の棒 + 差を独立した図形で | 長さと、差の帯 | 矢印だけ置く |
| **物やお金が動く** | **経路図**(主体を位置で置き、矢印で物を移す) | 位置=主体、矢印=移動の向き、色=何が動いたか | **手順の文を箱に入れて縦に並べる** |
| **売買のタイミング**(投資テーマ) | **株価チャート**(横=時間、縦=株価。売買は線上の点) | 横位置=いつ、縦位置=いくら、点=売買、帯=差額 | 抽象的なトークン図・棒グラフに置き換える |
| **積み上がっている** | 積層図(下から積む) | 上下=階層 | 並列に置く |
| **二者が非対称** | 同じ軸に2つ。片方が軸から振り切れる | 共通の軸 | 意味のない高さの棒 |
| **条件で分かれる** | 分岐図 | 分岐点=条件 | 文章 |
| **単独の数字が主役** | ヒーロー数字(図なし) | — | 意味のない棒1本 |

## 図を描く前の3つの問い(F図1〜F図3)

1. **この図から何を削っても意味が変わらないか?** → 変わらないものは全部削る(一貫性)
2. **位置・長さ・向き・面積のどれが意味を持っているか?** → 1つも答えられないなら、それは図ではない(Larkin & Simon)
3. **図の中の文を読み上げたら、ナレーションと同じか?** → 同じなら図は不要か、間違った型(冗長性)

## 図の中の文字の規則

- ラベルは**対象の上か中**に置く。別行にまとめない(空間的近接)
- 図の中の文字は**語句**にする。文にしない(冗長性の例外は短い語句のみ)
- 目安: 図の中の1文字列は**12字以内**。15字を超える文字列が2つ以上あるなら、それは図ではなく文章
- 強調色は**1箇所だけ**(合figure)

## S022 v2の実例(却下された図)

```
┌──────────────────────────┐
│ ① 証券会社から株を借りる      │  ← ナレーション「その株は、証券会社から借りるのだ」と同義
│    自分の株ではない            │  ← 位置にも長さにも意味がない
├──────────────────────────┤
│ ② 借りた株を100万円で売る    │
├──────────────────────────┤
│ ③ 80万円で買い戻して返す     │
└──────────────────────────┘
```
- メッセージの型は「**物やお金が動く**」→ 正しい図は**経路図**
- 実際に描いたのは「手順の文を箱に入れて縦に並べる」= 判定表のNG欄そのもの
- 冗長性違反(図の文 = ナレーション)、位置に意味なし、強調なし

→ 修正: **株とお金を2つのレーンに分け、時間を横位置に取り、実際に動かす。**
   お金のレーンは残高の棒にして、0 → +100万 → +20万 と長さで見せる。

## 投資テーマの既定の土台は「株価チャート」(ループ㊼)

ユーザー指摘:「株価のこのタイミングで買って、どのタイミングで売って、
どのタイミングで買い戻すとか、**チャートで**わかりやすくして欲しい」

**視聴者の心的モデルは「チャート」である。** 株の売買を語るなら、トークンや棒グラフに
置き換えず、まず株価チャートの上に売買の点を打つ。一致原則(Tversky)そのもの。
判定表にも「時間で変わる → 折れ線」と書いてあったのに、株価を軸に取らなかったのが誤り。

実装は `scenes_common.price_chart()` / `price_path()`:
- 横=時間、縦=株価。価格の目盛りは**左**(実際の取引画面と同じ)
- 売買は線上の点(●)+ 背景を敷いたラベル。線と文字を食い合わせない
- 2つの価格のあいだを帯で塗り、差額(もうけ/損)を1つのチップで示す
- `price_path(start, end)` は**ブラウン橋**。乱歩を作ってから両端を start/end に合わせるので、
  **始点と終点は厳密なまま、途中は本物の株価のようにギザギザ**になる。seedを固定して毎回同じ形にする。
  正弦波を重ねただけの滑らかな線は「偽物のチャート」に見える(ユーザー指摘)
- `borrow=(開始, 終了, ラベル)` で**株を借りている期間**をチャートの下に帯で出す。
  空売りの本体は「**借りて**売る → 買い戻して**返す**」であり、
  借りと返しが図にないと空売りの図として成立しない(ユーザー指摘)
- 売買の点のラベルは動詞で書く:「借りて売る」「買い戻して返す」。「売る」「買う」だけにしない
- `reveal` で線を伸ばしながら見せ、同じチャートの上に説明を積む

### チャートの見た目の規則(ループ㊽)

- **目盛りは水平線5本(MUTED alpha 0.16)と左の軸線だけ。**「時間 →」「株価」の軸名は書かない。
  横が時間・縦が株価であることは形で分かる(一貫性 d=0.70)
- 面塗り(線の下の塗り)は**入れない**。`reveal` 途中では塗りが四角い塊に見えて、
  値動きではなく「棒」に読める
- **ラベルは自動で場所を探す。** `chip_free()` が候補位置を順に試し、
  ①画面外に出ない ②見出し・バッジ・他のラベルと重ならない、最初の位置に置く。
  優先順は「差額のチップ(この図の主役)→ 売買のラベル」。
  逃げ場としてグラフ枠の上下を候補に入れる。位置を手で決めると、
  値動きやレンジが変わった瞬間に必ずどこかで重なる
- 価格の目盛りは**売買した価格だけ**を左に出す(INK_2 24pt)。全部の目盛りに数字を振らない

同じチャートを**利益の場合と損失の場合の両方**に使うと、向きが逆になるだけで
損の方が大きいことが形で分かる(S022)。

## 機械チェック

`python3 production/check_figure.py [videos/<ID>]`

- **図形ゼロ判定**: patch/line/arrow が0個でテキストが3つ以上 → 箇条書きなのでFAIL
- **文章判定**: 15字以上の文字列が2つ以上 → 図ではなく文章なのでFAIL
- **冗長判定**: 図の中の文字列が、そのユニットの字幕と6割以上一致 → 冗長性違反でFAIL
- **強調過多**: 強調色(EMPH)の要素が3つ以上 → 合図の原則違反でWARN
