## この調査で見つかった、コードの実測による不具合(先に書く)

1. **まばたきが2分で止まる**(A4-5)。`BlinkSchedule.__init__` の `while t < 120`。

   **残り 284.2秒 = 70.9% のあいだ、ずんだもんは一度もまばたきしない**。
   〔検証者訂正: 調査員は seed=1234(L001 では使われない値)で 119.86秒と書いていた。
   結論は変わらないが、実測と称する数字が実物と違っていた〕

   ADV/ノベルゲームの定石は「暗くする(tint)」であって「半透明にする」ではない。
3. **左の立ち絵が図の描画域に食い込んでいる**(A4-2)。`PLOT_L=0.055` に対し

   〔検証者追記〕左の箱を禁止領域に足して L001 を実際に走らせると **73件**が出るが、

## A4-1 サイズ

- **現状**: `use_landscape()` が `CHARA_RECTS["bl"]=[0.010, 0.200, 0.192, 0.391]`、
  `["br"]` を `[0.798, 0.200, 0.192, 0.391]` に設定。高さ 0.391×1080 = **422px(画面高の39.1%)**。
  ずんだもんの描画箱は 369×422px(素材 800×915 の縦横比 0.874 と一致・歪みなし)。
  めたんは `ART_W/ART_H = 300/290` から幅を出して右端寄せするので実効 **437×422px**。
  〔検証者による再測定〕素材PNGの不透明画素(alpha>8)を rect に写すと、
  **ずんだもん x 0.0117〜0.1806(画面幅の16.9%)・頭頂 y 0.5850・下端 y 0.2000**、
  **めたん x 0.7958〜0.9589(16.3%)・頭頂 y 0.5735**。実効寸法は 437×422px で調査員の値と一致。
  調査員の「0.016〜0.177/16.1%/頭頂0.583」は完成フレームからの差分測定で
  アンチエイリアス端を取りこぼしたぶん、わずかに内側に出ている(結論に影響なし)。
  なお**二人の頭頂は 0.0115(12.4px)ずれている**。A4-2 の「頭のラインが揃っている」は
  この差を指しており、実測でも実害のない範囲。

- **選択肢**:

| 案 | 内容 | 採用例・出典 | 長所 | 短所 |
|---|---|---|---|---|
| 1 現状維持 | 高さ39%・下端を字幕帯の上に接地 | 自チャンネル L001 | 図と字幕の両方に場所を残せている | 横幅16%を左端で恒久的に占有する |
| 2 縮小(33%) | 高さ 0.391→0.33。横幅も13.6%へ | 実動画の観察で1/3前後は普通にある(C) | 図の左が空く | 表情・口パクが読み取れなくなる方向。根拠なし |
| 3 拡大(45〜50%) | バストアップを大きく見せる | ゆっくり実況の実況系は大きめ(C) | 掛け合いの存在感が増す | 図の面積が減る。長尺は図が主役という自方針と衝突 |
| 4 発話者だけ拡大 | 話者 1.00 / 非話者 0.97 の動的スケール | Ren'Py 向け "auto highlight" アセットが「小さなズーム+暗転」を既定にしている(C・itch.ioはWebFetch不可でスニペットのみ) | 話者が一目で分かる | 毎フレーム箱を作り直す実装。効果は微小 |

- **比較の軸**: 視認性 / 図の面積を奪わないか / 実装コスト / 定石の有無 / 自チャンネルの実測。
- **決定**: **維持(高さ 0.391 = 39.1%)**。
- **根拠**: 2回検索しても「画面の何%」という数値の定石は出てこなかった。日本語の情報は
  素材のキャンバス寸法(縦4000px前後など)の話で、画面上の占有率ではない
  ([Vtuberの立ち絵サイズ](https://coro-vtuber.com/vtuber-standing-picture-size/)、
  [立ち絵作成の依頼ポイント](https://coconala.com/magazine/28023))。英語も同じで、
  配信オーバーレイのガイドはキャンバス1920×1080と「頭と手を切らない」までしか言わない
  ([Twitch overlay size guides](https://live3d.io/blog/twitch_overlay_size_guides)、
  [Stream Overlay Design 2026](https://animarts.studio/blog/vtuber-stream-overlay-design-best-2026))。
  「顔を置くこと自体」の効果なら一次に近い実証がある。Guo/Kim/Rubin (2014) は edX の
  690万視聴セッションを解析し、スライドだけの動画より **話し手の顔を挟んだ動画のほうが
  エンゲージメントが高い** と報告している([ACM L@S 2014](https://dl.acm.org/doi/10.1145/2556325.2566239))。
  ただしこれは「顔の有無」であって「顔の大きさ」ではない。
  **サイズの定石は存在しない → 現状値で凍結する**(A/Bには回さない。末尾の節を参照)。
  そして今回の実測では、痛いのは高さではなく**横幅16%が図の左端に重なること**だった。
  そちらは A4-2 で直す。高さを根拠なく動かすのはノイズなので触らない。
- **確度**: **C**(サイズ比の定石は不在。〔検証者〕Guo/Kim/Rubin (2014) は
  dl.acm.org が egress 遮断で開けず、**引用の中身を確認できていない**。
  「顔を出すこと自体の効果はA」は**未検証**として扱い、C に下げる。
  ただし決定は「維持」なので行動は変わらない)

  〔検証者による差し替えの理由〕調査員の手順1をそのまま入れて L001 を走らせると
  **73件中67件が誤検出**になる。`check_overlap.check_video()` は
  `has_chara = key not in cover_keys` としており、**ユニットの `chara` を一切見ない**。
  L001 は 113ユニット中 71が `chara="none"`(26シーン)で、それが全部「立ち絵に重なる」と鳴る。
  この状態のゲートは必ず無視されるか、立ち絵を無意味に動かす方向に効く。
  しかも**本物の6件はすべて見出し系シーン**で、調査員はそこを

     `has_chara = key not in cover_keys and key not in no_chara_scenes` にする。

     これらは立ち絵ありのシーンなので、見出しの左端を 0.202 より右に寄せるか、
     当該ユニットを `chara="none"` にする。
  4. `check_long.py` の「図の上の立ち絵 ≤50%」を強化し、
     **棒(bars)・曲線(curve)・表(table)・左右比較(compare2)のシーンは `chara="none"` 必須(0%)** にする。
     ただし L001 はすでに全部そうなっているので、これは**現状の追認であって不具合の修正ではない**。
  5. 立ち絵の座標そのものは動かさない。
- **根拠**: 横並びの配置は「頭のラインをそろえる」のが基本で、そこは現状すでに満たしている

  **図の列と重なっていること**で、これは検索ではなく自コードの実測で確定した(確度A)。
  ゲートが `br` しか見ていない件も `production/check_overlap.py` の

  [Shot/reverse shot](https://en.wikipedia.org/wiki/Shot/reverse_shot)、

## A4-4 口パク

- **現状**: `mouth_track()` が wav の RMS を **8Hz** のフレームで取り、そのユニット内のピークで
  正規化して `>0.42→2(開)` / `>0.10→1(半)` / それ以外 `0(閉)` の3段階。
  発話の切れ目は1フレーム分だけ 2→1 に伸ばして滑らかにする。
  `CHARA_FPS = 8` はコード内で「アニメ3コマ@24fps相場と同等」と注記されている。

- **選択肢**:

| 案 | 内容 | 採用例・出典 | 長所 | 短所 |
|---|---|---|---|---|

- **決定**: **維持(RMS 3段階・8Hz・しきい値 0.42/0.10)**。案3は次の実装ループの候補として残す。
- **根拠**: 8Hz は日本のリミテッドアニメの標準そのもの。24fps で3コマ打ち = 24÷3 = **1秒8枚**が
  「業界で8fpsと呼ばれる」やり方だと複数の解説が一致する

  [3コマ打ちとは](https://da-rio-pro.com/animation/animation_study/full-limited_and_three-frame_shooting_animation)、
  [アニメのフレームレート8fps](https://ani-emo.com/archives/1939))。
  3段階(閉/半/開)も、音素を「完全に閉じる(m/b/p)」「半開き(e/i)」「大きく開く(a/o)」に
  まとめる一般的な簡略化と一致する([Animationclub](https://animationclub.school/blog/the-secrets-of-lipsyncing-in-2d-animation/))。
  振幅が大きいほど口が大きく開く、という音量連動の前提も裏づけがある(同上)。
  **一方でしきい値 0.42/0.10 には出典が無い**。PSDToolKit の既定値を確認しようとしたが
  一次に近いページが軒並み egress で遮断され、数値を取れなかった。
  ここは「定石は取れていない → いまの見た目が破綻していないので据え置き」が正直な状態。
- **確度**: **C**(〔検証者〕8Hz・3段階の外部ソースを1本も検証できていない
  (WebSearch上限・WebFetch遮断)ため **B → C**。しきい値 0.42/0.10 は元からC。
  `CHARA_FPS=8` / 3段階 / 閾値 / ユニット内ピーク正規化がコードのとおりであることだけは実測で確認済み=A。
  決定は「維持」で行動が変わらないため、Cのままでも research-standards に反しない)

  [RebusFarm](https://rebusfarm.net/blog/squash-and-stretch-in-animation-the-essential-principle-for-lifelike-motion))、
  「気づかれない程度に留める」という方向性は現状の3.8%・0.35秒と整合する。
  ただしこれは方向の一致であって、3.8%という数字の裏づけではない。
  **具体値の定石は存在しない → 現状値で凍結する**(A/Bには回さない。末尾の節を参照)。
  なお「めたんが跳ねない」のは実装の非対称だが、いまのめたんは表情が変わらない静止画なので、
  跳ねだけ追加すると不自然さが増す。素材が入れ替わってから同時に直すのが正しい順序。
- **確度**: **C**(方向性のみB、数値はC)

## A4-10 非話者の減光

- **現状**: `draw_chara(..., alpha=1.0 if z_active else 0.72)` /
  `draw_metan_chara(..., alpha=0.72 if z_active else 1.0)`。
  `alpha` はそのまま `ax.imshow(arr, ..., alpha=alpha)` に渡される。
  **つまり減光ではなく半透明化している。**
  検証: 棒グラフを描いたうえに `alpha=0.72` の立ち絵を重ねて1枚焼いたところ、
  ずんだもんの髪と体を**背後のオレンジの棒とy軸ラベル「0.5」が透けて見えた**。
  〔検証者による独立再現・確認〕matplotlib 3.11.1 で
  **スカラーの `alpha` は RGBA画像のアルファチャンネルに「乗算」される**ことを
  最小例で確かめた(完全透明の背景画素は透明のまま、不透明画素だけが 0.72 になる)。
  そのうえで橙 `#ff7a1a` の矩形の上に立ち絵を重ねて焼くと、
  体の内側の画素が `[247,134,43]`(ほぼ橙そのもの)や `[248,207,175]`(橙との混色)になった。
  **調査員の指摘は再現する。実装の不具合として確定。**
  L001 の本編では図ユニットで立ち絵を消しているため露見していないが、
  見出し系ユニットの背景に模様が入れば同じことが起きる。

- **選択肢**:

| 案 | 内容 | 採用例・出典 | 長所 | 短所 |
|---|---|---|---|---|
| 1 現状維持 | `imshow(alpha=0.72)` | ー | 実装済み | **図の上で透ける。定石(暗くする)とも違う挙動** |

  `arr = arr.copy(); arr[..., :3] = (arr[..., :3] * dim).astype(arr.dtype)` とし、
  `imshow` には `alpha` を渡さない(引数名も `alpha` → `dim` に改める)。

  〔検証者追記・実装上の注意〕2点ある。
  (a) `_img()` が返すのは `_IMG_CACHE` の**共有配列**なので、
  `.copy()` を忘れると減光がキャッシュに焼き付いて以後ずっと暗いままになる。
  (b) L001 は **3230フレーム**あり、毎フレーム 800×915×4 の配列を copy+乗算すると
  そのぶん焼き時間が伸びる。`_IMG_CACHE` のキーを
  `name|flip|dim` にして**減光済みの配列もキャッシュする**こと(dim は 1.0 と 0.72 の2値しかない)。

  定石の有無と関係なく不具合であり、そこだけで変更は正当化される。
- **確度**: **A**(透けの再現は検証者が独立に再現。「定石は暗くする」は**未検証のC**。0.72という値もC)

「自チャンネルのA/Bテストに回す」と結論していた。**これは自チャンネルの実測方針と正面から衝突する。**

`docs/research/hold-rate-2026-08.md` §6「やらないこと」の一行目:

> - 色・フォント・**立ち絵**などの見た目だけの変更を「維持率施策」と呼ばない

そして同 §1 の実測(確度A)が示すボトルネックは:

> **7割は最初の1〜2秒で消えている。**(Stayed to watch 平均 28.9%)
