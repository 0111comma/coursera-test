## 先に書いておく「今回の実測で判明した事実」

**1. サムネイルの左上に、間違った章チップが焼き込まれている(実装バグ。確度A)**

`make_thumbnail()` は `render_video()` の**あと**に呼ばれる(render.py 518行→525行)。
章チップは `shortlib.CURRENT_BAND` というモジュールグローバルで、
`render_video()` のループが最後のユニットの値のまま残す。
その結果 `thumbnail.png` の左上には緑の **「第4章 自分の場合」** が入っている。
動画の第0フレーム(同じ `son__cover` 構図)は金色の「今日の問い」で正しい。
つまり**サムネイルだけが第4章を名乗っている**。

**2. カバーフレームは 0.07 秒しか映らない(確度A)**

`render_video()` の `emit(1.0, 990, 0.07, ...)`(1237行)。30fps で約2フレーム。
実際に ffmpeg で第0フレームを抜くとカバー、0.2 秒ではもう `hero("株で20万円の損")` に変わっている。
**「カバー構図」は事実上、動画の冒頭演出ではなく、フィードの静止表示とサムネイルの土台である。**

**3. サムネイル上の文字の実測サイズ(1920x1080、DPI=100)**

| 要素 | fontsize | 実測インク高 | 画面高比 | 246x138表示 | 168x94表示 |
|---|---|---|---|---|---|
| 問い(INK_2) | 44pt | 56px | 5.2% | 7.2px | 4.9px |
| 大数字(白+黒縁) | 190pt | 302px | 28.0% | 38.6px | 26.3px |
| 補足(EMPH) | 54pt | 72px | 6.7% | 9.2px | 6.3px |
| 注記(MUTED) | 30pt | 38px | 3.5% | 4.9px | 3.3px |

BBC の字幕ガイドライン(HD で最低22px)を小表示に換算すると、
**246x138 で読ませるには画面高の16%以上、168x94 で読ませるには23%以上**が要る。
**現状これを満たすのは大数字だけ。問い・補足・注記はフィード上では読めていない。**

## A8-1 カバー構図

- **現状**: `scenes_long.cover(top, main, bottom, note, brand, main_size=190)`。
  上から 問い(y=0.855、44pt、INK_2、縁取り無し) / 大数字(y=0.560、190pt、
  白+黒縁 outline=fontsize*0.10、block_fit=0.86) / 補足(y=0.320、54pt、EMPH、
  縁取り+同色fatten 2.5) / 注記(y=0.225、30pt、MUTED) / フッターにブランド名。
  加えて背景の章チップ(左上)と角丸パネルが乗る。
  L001 の実値は 問い「株で損したら、税金はどうなるのか?」/ 数字「40,630円」/
  補足「もうけた株の税金が消える。ただしNISAは別」/ 注記「2026年8月時点の制度」。
  **この1枚が (a) 動画の0.07秒のカバーフレーム と (b) サムネイルの土台 を兼ねている。**

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | 1つの painter が動画カバーとサムネを兼ねる | 現状 | 実装が1本で済む。動画とサムネの見た目が一致する | 要件が違う2つを1つの構図で満たしている。サムネ側で読めない文字が3つ乗る(実測) |
  | 2 カバーとサムネを分離 | `cover()` は動画用(問い+数字+注記+ブランド)、`thumb()` は別関数(文字2ブロックのみ) | ゆっくり系テンプレ解説はサムネを専用工程として扱う(`video-elements-2026-08.md` #10 の調査。確度B) | それぞれの制約に最適化できる。サムネから注記・ブランド・章チップを外せる | 実装が2本になる。文言の二重管理 |
  | 3 カバー廃止(コールドオープン) | 0.07秒のカバーを置かず hero から始める。サムネは別途生成 | 「多くのトップ制作者がコールドオープンに移行。ブランド提示は後ろか無し」(Renderforest / Gyre。確度B) | 冒頭の情報量が減り、答えの一撃に集中できる | フィードの静止表示(自動再生前の1コマ)が hero になり、答えの数字が消える |
  | 4 カバーを実尺(2〜3秒)のタイトルカードにする | 表紙を読ませる時間を取る | 「ブランド付きイントロは5秒以内」(Renderforest。確度B)。ただし「冒頭は情報を詰め込むと離脱」(JP実務ブログ。確度C) | 表紙として機能する | Wistia の実測では冒頭10〜15秒の落差が最大。静止画で2〜3秒使うのは逆行 |

- **比較の軸**: 小表示での可読性 / 冒頭離脱への寄与 / 実装コスト(matplotlib のみ) /
  コンプライアンス表記の置き場 / 動画とサムネの要件差。

- **決定**: **変更**。

  1. `cover()` は**動画用のまま維持**(問い44pt / 数字190pt / 補足54pt / 注記30pt / ブランド)。
     カバーフレームの尺は **0.07秒のまま維持**(コールドオープン側の根拠に従い、延ばさない)。
  2. **`scenes_long.thumb(main, word, accent)` を新設**し、`make_thumbnail()` はこちらを使う。
     `thumb()` が描くのは **文字2ブロックだけ**:
     - 主役の数字: y=0.60、**main_size=165**、白 #f2f1e9 + 黒縁 16.5pt、`ha="left"`
     - 語句1つ: y=0.30、**fontsize=131**(現状の補足54ptから)、EMPH + 黒縁 13.1pt、`ha="left"`
     - **注記(30pt)・ブランド(20pt)・問い(44pt)・章チップは描かない**

     > **検証で訂正**: 調査員の「main_size=210 / 語句130(のち133)」は
     > **A9-1 が決めた文字帯 x 0.035〜0.590(幅 0.555 = 1066px)に物理的に入らない**。
     > `text_fit` / `draw_rich_text(block_fit)` は幅超過を**自動で縮める**ので、
     > 210 と書いても実際に焼かれるのは 165pt であり、**「190→210に上げる」変更は
     > 画面上で何も起きない**(むしろ帯を狭めた分、現状の190より小さくなる)。
     > 実測(1920x1080・DPI100・源ノ角ゴシック)の advance 幅:
     > 「40,630円」= 4.63em、「NISAだと払う」= 6.96em、「NISAは払う」= 5.81em。
     > 1066px に収まる上限は 数字 **165pt** / 語句 **6.0em まで**。
  3. `make_thumbnail()` の先頭で **`S.CURRENT_BAND = None` を明示的に代入**して
     章チップの焼き込みバグを潰す(現状 thumbnail.png に「第4章 自分の場合」が入っている)。

- **根拠**:
  - カバーが0.07秒であることと、章チップの誤りは実装とレンダ済み画像から直接確認(確度A)。
  - 小表示で読めない文字サイズは上表の実測(確度A)。BBC字幕ガイドラインの最低22px は
    https://www.clevercast.com/bbc-subtitling-guidelines/ 経由(原典は BBC Subtitle Guidelines 2022。確度B)。
  - コールドオープンの優位: https://www.renderforest.com/blog/how-long-should-youtube-intro-be /
    https://gyre.pro/blog/how-to-make-a-youtube-intro-that-keeps-viewers-watching (確度B)。
  - 冒頭10〜15秒の落差: https://wistia.com/learn/marketing/engagement-graph-learnings (確度B)。
  - サムネを専用工程にする定石: `docs/research/video-elements-2026-08.md` #10(確度B)。

- **確度**: **A**(実装バグとサイズ実測)/ 分離の是非そのものは **B**。

## A9-4 色数

- **現状**: 「4色以内」と記録されているが、**thumbnail.png の実測では設計色は7つ**。

## A9-5 顔の使い方

- **現状**: ずんだもん `draw_zunda(ax, mouth=2, eyes="open", expr="surprised", flip=True)`。
  `flip=True` なので**左右反転**して描かれている(画面左に立ち、体は内向き)。
  四国めたんは **VOICEVOX公式ポートレートの静止画で、表情の切り替えができない**。
  実測では **補足行(EMPH)がずんだもんの顎と、めたんの頭部を横切っている**。
  ずんだもんの顔の実効高さは画面の約20%(立ち絵枠 0.62 のうち頭部)。

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | 驚き顔・正面・左配置・文字と重なる | 現状 | 変更不要 | 顔がCTRの主資産なのに文字で潰している |
  | 2 顔を大きくし、文字と重ねない | 立ち絵 h 0.62→0.78、文字を反対側へ | 「表情のある顔がCTRを上げる」(vidIQ / TubeBuddy 系。確度C〜B)+ 三分割(確度B) | 表情が小表示でも読める | 文字の置ける幅が減る(A9-2 の16字制限と整合する) |
  | 3 表情を回によって変える | surprised / troubled / happy をネタに合わせて選ぶ | 「驚き・喜び・深刻の3つが強い」(複数の英語ガイド。確度C) | 単調さの回避 | `zunda.py` の対応表情の範囲内でしか選べない |
  | 4 顔を使わない | 数字だけ | 改修前の当チャンネル | 実装最小 | 「breakout の69%が顔」に反する(確度C) |
  | 5 めたんも表情を持たせる | パーツ分割素材に差し替える | `metan.py` の TODO コメント | 二人とも表情が付く | **素材が無い。今回の環境では入手できない** |

- **比較の軸**: 小表示での表情の読み取り / 文字との衝突 / 素材の制約 /
  実装コスト / 権利(素材の再配布条件)。

- **決定**: **変更**。

  - **ずんだもんの立ち絵枠を `[0.601, 0.010, 0.384, 0.780]` にする**(現状 `[0.000, 0.020, 0.305, 0.620]`)。
    高さ 0.62 → **0.78**、位置を左端から右側へ。
    幅0.384は素材の縦横比 800/915 = 0.8743 に合わせた値(A9-1 の検証注を参照。
    調査員案の 0.370 だと横に3.6%潰れる)。
  - **`flip=True` → `flip=False` にする**(右に立つので、体を内向き=左向きにするため反転を外す)。
  - **表情は `expr="surprised"` を維持**、視線は正面を維持。
  - **文字は立ち絵の矩形と重ねない**(A9-1 の x 0.035〜0.590 の制約で担保)。
  - **めたんはサムネイルから外す**(A9-1)。動画本編での使用は変更しない。

  **正直に書く**: 「驚き顔が他の表情よりCTRが高い」「視線が正面だと強い」という主張は、
  vidIQ / TubeBuddy を引用する二次記事にしか見つからず、**元データに当たれなかった**。
  さらに **イラストのキャラクターに対する検証は一件も見つからなかった**(すべて実写の人間の顔の話)。
  **これは定石ではない。**表情の選択(surprised 対 troubled)は A/B テストの第2候補にする。

- **根拠**:
  - 顔の採用率と感情の効果(いずれも二次記事): https://vidiq.com/blog/post/youtube-thumbnail-design-tips/ ,
    https://thumbnailtest.com/guides/face-in-youtube-thumbnail/ ,
    https://1of10.com/blog/the-psychology-behind-high-ctr-thumbnails/ (確度C)
  - 「+42.3%(TubeBuddy 120万本)」「65%が視線に注目」といった数値は複数の記事に出るが、
    **TubeBuddy の原典に到達できず、数値の出どころを確認できなかった → 採用しない。**
  - 文字が顔を横切っている事実は thumbnail.png の実測(確度A)
  - めたんの素材制約: `production/metan.py` 冒頭コメント + `assets/metan/policy.md`(確度A)

- **確度**: **A**(現状の衝突と素材制約)/ 表情と視線の選択は **C**。

## A9-6 タイトルとの役割分担

- **現状**: 「サムネ=問い、タイトル=検索語+数字」。
  実物のサムネは **問い17字 + 数字 + 結論22字** で、**問いだけになっていない**。
  L001 のタイトルは `videos/L001-nisa-son/` 側に確定した文字列が無く、
  概要欄のチャプターは `sl.chapter_lines()` が生成する(`longform-design.md`)。
  **サムネとタイトルの重複を止める仕組みは、コードにもゲートにも存在しない。**

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | サムネ=問い / タイトル=検索語+数字(規則だけあって強制なし) | 現状 | 変更不要 | 実物が規則に従っていない。検証もされていない |
  | 2 補完型を明文化+機械ゲート化 | サムネ=数字+損の一語 / タイトル=検索語+争点。**両者に同じ名詞を2つ以上入れない** | 「タイトルと同じ文字をサムネに入れると情報が重複し視認性が下がる」(stock-sun / aainc。確度B) | 重複を機械で落とせる | 形態素解析(janome、既に依存にある)が要る |
  | 3 一致型 | サムネとタイトルを同じ文言にする | 一部の量産チャンネル | 期待とのズレが出ない | 上記の定石と正面から反する。文字数の無駄 |
  | 4 サムネに文字を入れない | タイトルだけに情報を持たせる | 海外の一部大型チャンネル | 画が主役になる | 日本語圏の解説ジャンルでは採用例が薄い。数字主体の当チャンネルと合わない |

- **比較の軸**: 重複の排除 / 検索での拾われやすさ / スマホでの見切れ /
  ゲート化のしやすさ / 実測での検証可能性。

- **決定**: **変更**(案2)。役割分担を具体値まで書き、ゲートにする。

  - **サムネイル**: 主役の数字(7字以内)+ 損の側の語句(8字以内)。**問いは書かない。**
    (A8-2・A9-2 の決定と同じ)
  - **タイトル**: **全角28字以内**。**主要検索語を先頭15字以内に置く。**
    数字を1つ入れる。争点(何と何を比べるのか)を明示する。
    L001 の具体案: **「NISAで損した年の税金 40,630円の差【2026年8月時点】」**。
    先頭15字に「NISA」「損」「税金」が入る(「税金」は12字目で終わる)。

    > **検証で訂正**: 調査員はこれを「28字」と書いているが、
    > `len()` で **33字**、東アジア幅で全角換算すると **25.0字**。
    > **どちらの数え方でも28にはならない。**
    > 「全角28字」という規則を運用するなら、**数え方(素の文字数か全角換算か)を
    > ゲート側で先に決める必要がある。** 現状は規則も例も数え方が未定義。
  - **重複の禁止**: サムネの語句とタイトルに、**同じ内容語(名詞)を2つ以上共有させない**。
    L001 案ではサムネ語句「NISAは払う」とタイトルの共有名詞は「NISA」1つ → 合格。
  - **ゲート**: `production/check_thumb.py` に、janome の形態素解析で
    サムネ語句とタイトルの名詞集合の積を取り、**要素が2つ以上なら不合格**を実装する。
  - **検証**: YouTube Studio の **A/B テスト(旧 Test & Compare)** を使う。
    公開長尺で**最大3つ**のタイトル/サムネの組み合わせを比較でき、
    総再生時間が最大のものが自動採用される。パソコンの YouTube Studio でのみ利用でき、
    詳細機能の有効化が要る。**ショートは対象外**なので、この検証は長尺でしかできない。
    テストする順序: (1) めたんの有無(A9-1)、(2) 結論まで書く/損の側だけ(A8-2)、
    (3) ずんだもんの表情(A9-5)。

- **根拠**:
  - 重複回避: https://stock-sun.com/column/thumbnail/ ,
    https://service.aainc.co.jp/product/letrostudio/article/youtubethumbnail (確度B)
  - タイトル全角28字・キーワードは先頭15字以内・スマホ8割:
    https://re-hero.jp/... , https://yanomakoto.com/youtube-title-word-count/ ,
    https://youtubers.shop/blog/youtube-views/the-best-number-of-characters-in-the-title/ ,
    https://marke-insight.com/youtube-title/ (独立4本で一致。確度B)。

## 2. 実測と食い違い、訂正したもの

1. **冒頭タイミングが全部ずれていた。** 3.4s / 11.3s / 16.4s → 実測 **3.0s / 9.0s / 13.3s**。
   mp4 実尺400.7秒に対し `check_long.py` の推定は419.2秒(4.6%長い)で、
   **推定で並べても11.3秒にはならない**。出どころ不明の数字。
2. **「11.2秒の静止1枚」は二重に誤り。** 実測は8.9秒、しかも字幕が2回入れ替わり立ち絵は動いている。
   この誤りは決定に直結していた:調査員は「L001は不合格になるので `son` を2枚に割る」と
   指示していたが、**自分で決めた10.0秒の閾値を実測8.9秒(推定9.6秒)は下回るので分割は不要**。
3. **A9-1 の文字帯(幅0.555)と A9-2 の fontsize(数字210・語句133)が両立しない。**
   `text_fit` / `block_fit` が自動縮小するので、210 と書いても焼かれるのは165pt。
   **「190→210に上げる」という変更は画面上で何も起きない。**
4. **語句「NISAだと払う」は調査員自身の16%床を割る**(6.96em → 109pt → 13.9%)。
   → 「NISAは払う」(5.81em / 131pt / 16.6%)に差し替え。
5. **ずんだもんの新 rect `[0.615,0.010,0.370,0.780]` は縦横比0.843で素材(0.8743)を横に3.6%潰す。**
   `draw_zunda` は `aspect="auto"`。現状の rect は比が合っていたので、**この提案は改悪だった**。
   → `[0.601, 0.010, 0.384, 0.780]`。
6. **字数の数え間違いが4件。** 注記11字→12字 / ブランド9字→11字 / 計57字→58字 / 75字→78字 /
   「NISAだと払う」7字→8字 / タイトル案28字→33字(全角換算25字)。
7. **MUTED の対 #000000 コントラスト 6.44 → 5.85。**
8. **`demand-2026-08.md` §4 を確度Bで引いていたが、同文書は自ら確度Cと書いている。** → Cに戻した。
9. **「1pt ≒ 1.3px」は小さい文字だけの近似。** 190pt は 1.57px/pt(縁取り込み)。
   結論は変わらないが、換算式をそのまま大数字に使うと外れる。

## 4. **検証できなかったもの — ここが最大の弱点**

**このセッションでは外部の一次資料・二次資料を1件も読めていない。**

- WebSearch はセッション上限(200回)に達しており、検証員の側から1回も投げられなかった。
- WebFetch は egress プロキシに全滅した。試して遮断されたドメイン:
  `clevercast.com` / `thumbifyx.com` / `vidiq.com` / `wistia.com` /
  `en.wikipedia.org` / `support.google.com`。
  **調査員が「未読」と申告した support.google.com だけでなく、
  「確度B」の根拠として挙げた記事群も、この環境からは開けない。**

したがって、次の主張は **今回の検証で1件も裏が取れていない**。
調査員が確度Bを付けているが、**独立ソースの一致を検証員が確認できていない以上、
`research-standards.md` の「独立ソース5本以上+一次資料1本以上」は満たしていない**:

- BBC 字幕ガイドラインの「HDで最低22px」 → **A9-2 の「16%床」の唯一の外部土台**。
  これが崩れると、16%・23%という数字ごと崩れる。
- 「246x138 / 168x94 / 360x202」というデバイス別のサムネ表示サイズ
- vidIQ の「breakout の69%が顔 / overperformer の80%」(調査員も確度C)
- Wistia の「5〜10分尺の nose 平均離脱17.3%」
- コールドオープン優位(Renderforest / Gyre)
- サムネ三分割・右下20%回避(velio / thumbnailcreator / TubeBuddy / thumbifyx)
- 英語圏「0〜3語」(vidIQ / miraflow / growthos)
- 縁取り5〜10%(omniweb / freedoor / video-knowledge)
- タイトル全角28字・先頭15字(re-hero / yanomakoto / youtubers.shop / marke-insight)
- YouTube A/Bテストの仕様(最大3つ・PC限定・Shorts不可)

**さらに、次の4件は URL が `...` で途切れていて、そもそも参照先が特定できない**:
`https://ai-labo-ai.com/...` / `https://ytbs.jp/book2026/...` / `https://re-hero.jp/...` /
`https://mobinc.jp/...`(A9-2・A9-4・A9-6 の根拠欄)。
**検証不能な引用は根拠として数えられない。**

### この節の結論

**外部由来の「確度B」は、このファイルの中では実質 C として扱うこと。**
実装を動かしてよいのは、以下の**自前で測れた**主張だけである:

1. 章チップの焼き込みバグ(A) — **直すべき。ソース不要**
2. インクサイズ・コントラスト・色数・座標・立ち絵の縦横比(A) — **幾何は自前で閉じている**
3. 冒頭タイミングと構図の持続時間(A)
4. 「帯幅とfontsizeが両立しない」という内部矛盾(A)

一方、**「何%を可読床にするか」「サムネに何字置くか」「顔を1体にするか2体にするか」は、
外部ソースが1件も検証できていないので、A/Bテストで決めるしかない。**
調査員の「A/Bテストで決める」という結論自体は正しい。**根拠の強さの表示だけが盛られていた。**
