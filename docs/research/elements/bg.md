## この調査で使った測定手順(再現可能)

1. `ffmpeg -ss <秒> -i L001.mp4 -frames:v 1 out.png` で実フレームを抜く
2. numpy で画素値を直読みし、WCAG 2.x の相対輝度式でコントラスト比を計算
3. 色覚は Vienot 1999 の LMS 射影(P型/D型)でシミュレートし、線形RGB距離で弁別性を比較
4. 480p/360p にダウンスケールして、細線が実視聴解像度で残るかを確認

**この手順で出た数字は確度A(自前の実測)。外部の主張は最大でも確度B。**

## A1-2 テクスチャ

- **現状**(コードから実読): **紙目テクスチャは実装されていない。**
  `_bg_image_rich()` にあるのは放射グラデーションとビネットだけで、粒状ノイズの生成コードは無い。
  「紙目がかった」のは色相の話(#2b2a25 は R>G>B の暖色寄り)であって、質感は無い。
  `element-taxonomy-2026-08.md` は A1-2 を「紙目がかった暖色黒/◯」と書いているが、
  **これは実装と一致していない**(前回の分類が現物を見ずに書かれた箇所)。
  L001 実フレームの局所ノイズは σ = **1.04 LSB**。これは自前で足したものではなく、
  bicubic 拡大と H.264 エンコードの副産物。

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |

  | 2 **静的グレインを焼き込む** | 固定シードのノイズを背景キャッシュに1回だけ合成 | AE「グレイン(追加)」の常套([ss-pas](https://www.ss-pas.com/%E3%80%90grain%EF%BC%88%E8%BF%BD%E5%8A%A0%EF%BC%89%E3%80%91%E6%98%A0%E5%83%8F%E3%81%AB%E8%B3%AA%E6%84%9F%E3%81%A8%E7%A9%BA%E6%B0%97%E3%82%92%E8%B6%B3%E3%81%99/))、Web の grainy gradient([コリス](https://coliss.com/articles/build-websites/operation/work/grainy-gradients.html)) | 質感が出る。バンディングの保険。**フレーム間で不変なので動き補償が完全一致し、ビットレート増がほぼ無い** | 描画コードが1箇所増える |

- **比較の軸**: 実装コスト / 圧縮効率(YouTube の再エンコード後に文字が残るか) /
  バンディング耐性 / 権利 / 「のっぺり」対策としての効果
- **決定**: **変更**。`_bg_image_rich()` の最後に**静的グレインを焼き込む**。具体値:
  - 生成解像度 **960x540**、`np.random.default_rng(20260821)` で固定シード
  - 振幅 **σ = 2.0/255(約0.8%)** の正規ノイズを RGB 共通(輝度ノイズ)で加算しクリップ
  - 拡大は **`interpolation="nearest"`** で 2x2 px 粒にする(グラデーション本体は現行どおり bicubic)
  - **毎フレーム再生成しない**。`_BG_CACHE_RICH` に含めて1回だけ作る

  **【検証者訂正5】この具体値はこのままでは実装できない。** 理由は2つ:
  1. **`interpolation` は `_bg_image_rich()` の中ではなく `new_canvas()` の呼び出し側で
     指定されている**(`bg.imshow(_bg_image_rich(), ..., interpolation="bicubic")`)。
     `_bg_image_rich()` は配列を1つ返すだけなので、**同じ配列の中で
     「グラデは bicubic・グレインは nearest」を分けることは原理的にできない**。
     実装するなら (a) グレイン専用の2枚目の `imshow` レイヤを `new_canvas()` に足す、
     または (b) 背景を最初から 1920x1080 で作って `interpolation="nearest"` に統一する、
     のどちらかが要る。**提案は「1箇所増えるだけ」ではなく `new_canvas()` の改修を伴う。**
  2. 現行配列は幅135 × 高さ240(A1-1 の訂正1)で、拡大率が**横14.2倍・縦4.5倍と異方的**。
     960x540 で作るなら基底配列の解像度ごと差し替えることになり、
     グラデーションの滑らかさ(現在は極小配列の bicubic 拡大で得ている)も作り直しになる。

  **提案の方向(静的グレインを焼き込む)は妥当なので却下しない。具体値と工数見積りだけ訂正する。**
- **根拠**:
  - 実装と記録の食い違いは実読で確認済み(確度A)。まず「書いてあるものを実装する」のが筋。
  - バンディングは**現時点では深刻ではない**。実測でパネル内の隣接差分は最大 0.5 LSB 未満、
    局所ノイズ σ=1.04 LSB が既に段差を隠している。**「バンディングが酷いから直す」は嘘になるので書かない。**
    ただしテレビ視聴(28%)では高ビットレート = エンコードノイズが減る方向で、
    低振幅ディザは保険として効く(確度C・仮説)。
  - 静的にする理由は圧縮。ノイズは動き推定のブロック一致を壊し、イントラでも DCT の
    近傍相関を下げて符号量を増やす。**静的なら次フレームとの差分がゼロなので、この害が出ない。**
    (確度B。複数の符号化文献が「グレインは符号化効率を落とす」で一致)
- **確度**: 実装の欠落と現状のノイズ量は **A**。圧縮への影響は **B**。
  「グレインを足すと視聴維持が上がる」は**根拠が無い。定石は存在しない → 効果測定はしない**
  (質感は目的であって維持率の施策ではない、と割り切る)。

  | 1080p | +4 LSB | **4.0 LSB**(一致) |
  | 720p | (記載なし) | **3.0 LSB** |
  | 480p | +1.2 LSB | **2.0 LSB** |
  | 360p | +1.1 LSB | **1.0 LSB** |

  縮小フィルタ次第で振れる量なので調査員が何を使ったかで差は出るが、
  **少なくとも「480p で +1.2」は Lanczos では再現せず、実際は半減(4→2 LSB)にとどまる。**
  また 480p 1.2 < 360p 1.1 という調査員の並びは、解像度を下げるほど平均化で
  振幅が単調に落ちるという物理と整合せず、そもそも数字として不自然。
  **結論(低解像度では極めて弱い)は生き残るが、「存在しないのと同じ」は言い過ぎ。**
  480p で 2 LSB は「ほぼ見えないが消えてはいない」水準。

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | alpha 0.055 / lw 0.7 / 11本 | 現行 | 何もしなくてよい | 実視聴解像度で不可視。描画コストだけ払って教科書らしさは得ていない |
  | 2 **見える強さまで上げる** | alpha 0.10 / lw 1.6 / 本数を減らす | UI の subtle pattern は「内容を邪魔せず、しかし見える」ところに合わせるのが原則([MagicPattern](https://www.magicpattern.design/tools/grid-background-pattern-generator)、[Toptal Subtle Patterns](https://www.toptal.com/designers/subtlepatterns/tag/grid/)) | 教科書=ノートの識別子が実際に機能する。静止なので圧縮コストほぼ0 | 上げすぎるとグラフのグリッド線と混同される |
  | 3 撤去する | 罫線を消す | Mayer のコヒーレンス原理(装飾は除く)([Risepoint](https://ctl.risepoint.com/principles-of-multimedia-learning/)、[Fox AE](https://fox-ae.com/the-coherence-principle-less-is-more-in-multimedia-design/)) | 認知負荷を最小化 | チャンネルの見た目の identity を捨てる(YPP の独自性要素の観点で不利) |
  | 4 罫線ではなく方眼/ドット | グリッド or ドットに替える | フリー素材・Canva の教育系テンプレは方眼・ノート罫の両方が定番([PIXTA ノート風背景](https://pixta.jp/illustration/120691438)、[Canva 教育系サムネ](https://www.canva.com/ja_jp/youtube-thumbnails/templates/tutorial/)) | ドットは線より圧縮に強く、グラフの線とも混同しにくい | 「ノート」より「方眼紙」の印象になり、教科書モチーフからずれる |

- **比較の軸**: 実視聴解像度での可視性(実測) / グラフのグリッド線との混同リスク /
  圧縮コスト / チャンネル識別への寄与(YPP 独自性) / 認知負荷
- **決定**: **変更**。
  - 横罫: `alpha 0.055 → **0.10**`、`linewidth 0.7 → **1.6**`、`range(1,12)(11本) → **range(1,8)(7本)**`
  - 左縦罫: `alpha 0.10 → **0.14**`、`linewidth 1.0 → **2.0**`
  - **同時に A1-1 の GRID を #454440(1.35:1)に上げること**。罫線 1.135:1 < グリッド 1.35:1 の
    順序が保たれていれば、グラフの線のほうが必ず濃く、混同しない
- **根拠**:
  - 可視性の判定は自前の実測(1080p で +4 LSB、480p で +1.2 LSB)。**外部に「背景パターンは
    何%が正解」という定石は見つからなかった**。検索した限り、素材サイトとジェネレータは
    「内容を邪魔しない範囲で調整せよ」としか書いていない。数値の定石は無い。
  - alpha 0.10 での合成色は `#34332d`、背景比 **1.138:1**(検証者再計算。調査員の 1.135 とほぼ一致)。
    パネル上では `#3b3934` / 1.141:1。字幕(12.6:1)やグラフ(1.35:1以上)
    より必ず薄く、コヒーレンス原理の懸念(装飾が主情報と競合する)には触れない水準。
  - 本数を 11 → 7 にするのは、1080p で罫間 90px → 135px にして、
    ダウンスケール後もモアレを起こしにくくするため(確度C・自前判断)。
- **確度**: 現状が**低解像度で著しく弱い**ことは **A**(ただし「不可視」は言い過ぎ。上表参照)。
  上げ幅 0.10/1.6 の妥当性は **C**
  (定石は存在しない → **自チャンネルの見た目確認と、必要なら A/B テストで決める**)。

## A1-4 ビネット

- **現状**(コードから実読): `vin = 1 - 0.12 * clip((r - 0.70) / 0.40, 0, 1)` を乗算。
  ここだけ見れば「周辺 -12%」。
- **実測での訂正(確度A)**: 見た目のビネットは**放射グラデーションとの合成**で決まる。
  L001 実フレームで 中心 → 左下隅。**「-12%」はビネット項だけの数字で、実効値ではない**
  という指摘自体は正しく、検証者も支持する。

  **【検証者訂正7】ただし相対輝度の数字が違う。** 同フレームの再測では
  中心 (0.5,0.62) = (47,46,39)、左下隅 = (21,19,17):
  - **RGB 平均で -56.8%** → 調査員の「-57%」は**一致**
  - **WCAG 相対輝度で -75.4%** → 調査員の「-63%」は**再現しない**

  (-63% は sRGB の線形化を省いた単純ガンマ等、別の式で出た値と思われる。
  A1-1 と同じ相対輝度式を使う限り -75% になる。)
  `element-taxonomy-2026-08.md` の「周辺-12%」という記載は、この意味で誤解を招く。

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | vin 0.12 / 開始 r=0.70 / 幅 0.40(実効 -57%) | 現行 | 中央集中は成立している。四隅が暗いので左上の章チップが映える | 実効値がドキュメントと食い違う |
  | 2 弱める(vin 0.06) | ビネット項を半分に | 「ビネットは隠して使え」という撮影側の原則([PremiumBeat](https://www.premiumbeat.com/blog/masks-and-vignettes-in-cinematography/)) | やりすぎ感を消す | 実効は依然 -50% 前後。効果が薄い |
  | 3 強める(vin 0.20) | 四隅をさらに落とす | 没入系の演出。VR研究では非注目領域の黒落としが注視誘導に使われる([Attention guidance 研究](https://www.researchgate.net/publication/315874141_Attention_guidance_for_immersive_video_content_in_head-mounted_displays)) | 中央への注視誘導が強まる | 「邪魔な効果は注意を引くが没入を壊す」というトレードオフが報告されている。角丸パネルの四隅の情報が沈む |
  | 4 撤去して均一面に | ビネットも放射グラデも捨てて単色 | Material Design 的な単色面 | 実装が最も単純 | 前回ループで却下された「単色ベタ=手抜き」に戻る |

- **比較の軸**: 中央への注視誘導 / 四隅に置く要素(章チップ・注記バッジ)の可読性 /
  やりすぎ感 / 実装コスト
- **決定**: **維持**。`vin = 0.12` / 開始半径 0.70 / 幅 0.40 をそのまま使う。
  **ただし記録を実効値に直す**: 「周辺 -12%」ではなく
  「**実効 中心→四隅 -57%(RGB)/ -75%(相対輝度)**」と書き換える。
- **根拠**:
  - **ビネットの強さに数値の定石は見つからなかった。** 日本語・英語の両方で探したが、
    Adobe / Lumion / 編集者ブログ / cinematography 系のいずれも「被写体が引き立つよう自然に調整せよ」
    としか書いていない([Adobe](https://www.adobe.com/jp/creativecloud/roc/blog/photography/vignette-effect.html)、
    [bardvision](http://broadcast.bardvision.com/2017/06/09/blog052/)、
    [Boris FX](https://borisfx.com/blog/what-is-a-video-vignette-in-video-editing-software/))。
    唯一の数値らしきものは「強度 -3.0〜-1.3 が甘い所」というソフト固有のスケールで、
    こちらの実装には翻訳できない。**定石は存在しない。**
  - 維持を選ぶ実測上の理由: 四隅が暗いおかげで、左上の章チップ(背景比 5.6〜7.8:1)と
    右上の注記バッジのコントラストが稼げている。弱めると両方が下がる。
  - 中央集中の方向性自体は「四隅を暗くして中心に焦点」で複数ソースが一致(確度B)。
- **確度**: 実効値 **-57%(RGB)/ -75%(相対輝度)** は **A**(検証者が独立に再測して一致/訂正)。
  強さの妥当性は **C**
  (**定石は存在しない → 自チャンネルで A/B テストするか、現状で据え置く**。今回は据え置き)。

## A1-5 背景の動き(¥モチーフ)

- **現状**(コードから実読): `_draw_rich_layers()` が毎フレーム
  `for i in range(7)` で ¥ 記号+円を描く。位置は `sx = (i*0.161+0.07 + t*0.010) % 1.16 - 0.08`、
  `sy = (i*0.379+0.15 + t*0.006) % 1.16 - 0.08`。半径 0.025〜0.051、色 `#c8bfa5`、
  `alpha 0.05`、線幅 1.4、文字サイズ `r*900`。
  **画面全体を覆う**(パネル内も通る)。
  さらに `DRIFT_FPS = 4` により、**立ち絵の無い静止ユニットでも 4fps でフレームを割っている**
  (`shortlib.py` 行1254-1259, 1268-1271)。
- **実測(確度A)**: L001 の 300 秒フレームで、¥ の円が**棒グラフの領域に重なっている**。
  alpha 0.05 の合成コントラストは 1.071:1 だが、円+文字という「形」なので罫線より知覚されやすく、
  960px に縮めた確認画像でも判読できた。

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | 全画面を 7 個が斜行 | 「常にどこかが動く」背景の定石。ゆっくり解説系では動く背景素材の使用が一般的([39sora 動く背景まとめ](https://39sora.com/moving-background-summary/)、[みりんの動画素材](https://miirriin.com/bg-shape01/)) | 静止画に見えない | 図の上を装飾が横切る。静止ユニットを 4fps に割るためレンダ枚数が4倍 |

  | 3 完全撤去し、動きは章の変わり目と図の組み立てにだけ置く | 常時ドリフトをやめる | Mayer のコヒーレンス原理: 無関係な素材を除くと学習が深まる。**23件中23件で支持、効果量の中央値 0.86**([Risepoint](https://ctl.risepoint.com/principles-of-multimedia-learning/)、[Mayer 12原則PDF](https://medicine.nus.edu.sg/medixperience/wp-content/uploads/sites/44/2025/10/2232070290_Mayer_12_principles.pdf))。就学前児の眼球運動研究でも、内容と無関係なアニメ要素は理解を妨げた([PMC11651708](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11651708/)) | 認知負荷が最小。**静止ユニットが1枚で済み、レンダ時間が大幅に減る** | 「常にどこかが動く」という編集側の定石に真っ向から反する |
  | 4 動きを内容に紐づける | ¥ ではなく、その章で扱う数値に関係する図形をゆっくり動かす | 同じ研究群が「内容と整合したアニメは注視をまとめ、理解を助けた」と報告([ResearchGate](https://www.researchgate.net/publication/309134854_Benefits_of_Motion_in_Animated_Storybooks_for_Children's_Visual_Attention_and_Story_Comprehension)) | 装飾ではなく情報になる | 章ごとに作り込みが要る。制作コストが高い |

- **比較の軸**: 図への干渉 / 認知負荷の学術的根拠 / レンダリング時間 /
  圧縮効率(全画面が動くと動き補償が効かない) / 「動いていないと飽きる」という編集側の主張
- **決定**: **変更**(案2 を採り、案3 に寄せる)。具体値:
  - **中央パネル(x 0.030-0.970, y 0.225-0.905)の内側には描かない。** クリップして余白帯のみに置く
  - 個数 `range(7)` → **`range(5)`**
  - `alpha 0.05` → **`0.07`**(余白は暗いので、同じ知覚量を保つのに少し上げる)
  - 速度 `t*0.010 / t*0.006` → **`t*0.006 / t*0.0036`**(1.67倍ゆっくり)
  - `DRIFT_FPS = 4` → **`2`**(静止ユニットのフレーム枚数が半分になる)
- **根拠**:
  - **学術側は「装飾的な動き」に否定的で、これは独立に複数の系統から一致している**
    (コヒーレンス原理、就学前児の眼球運動研究、Web の点滅広告で認知負荷が上がる報告)。
    一方で「常にどこかが動く」は日本の編集系ブログ・素材サイトの慣行で、
    **維持率が上がるという実測を示した出典は1つも見つからなかった**。
  - 自チャンネルの実測でも背景は容疑者に挙がっていない。`hold-rate-2026-08.md` のボトルネックは
    「7割が最初の1〜2秒で消えている」であり、背景の動きの話ではない(確度A)。
  - このリポジトリは既に「図が主役のユニットは立ち絵を消す(図への注視を奪うから)」という
    ルールを持っている。**同じ理由が ¥ の動きにも当てはまる。ルールを一貫させるだけ。**
  - 全画面が動くとフレーム間差分が全域に出るため、動き補償の効きが悪くなる(確度B)。
    余白だけに閉じれば、パネル内は前フレームのコピーで済む。
  - `DRIFT_FPS` を落とすのはレンダ時間の実利。静止ユニットの枚数が丸ごと半分になる。
- **確度**: 「装飾的な動きは理解を妨げる」は **B**(独立複数系統の一致。ただし本文は egress 遮断で未読、
  かつ**対象が就学前児・学習成績であって、YouTube の視聴維持率ではない**)。
  「常にどこかが動くと維持率が上がる」は **C**(出典は編集ブログのみ、実測なし)。
  **どちらが視聴維持に効くかは定石が無い → 案2(余白のみ)と案3(完全撤去)の A/B を自チャンネルで回す。**

- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | 1 現状維持 | 5色をこの順で | 現行 | 変更コスト0 | P型で第2章と第3章が区別できない |

- **根拠**:
  - 全順列を総当たりして、一般/P型/D型の**3条件すべてでの隣接最小距離**を最大化した結果が上記の順。
    0.014 → 0.746(自前計算、確度A)。**色を1つも変えずに 53 倍改善する。実質ノーコスト。**

    **無い場合も過剰な場合も認知負荷が上がった**と報告されている
    ([Behav. Sci. 14(7):560](https://doi.org/10.3390/bs14070560)、
    [Frontiers in Psychology 12:773328](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2021.773328/full))。
    5色は「章の数=4+導入」で内容に対応しており、過剰ではない(確度C・自前判断)。
  - 配色比率の 70:25:5 の慣行から見ても、チップは画面のごく一部でアクセント枠に収まる
    ([DUB DESiGN](https://dubdesign.net/web/ui-design/websight-basiccolor/))。
- **【検証者による追試: 完全に再現した】** Viénot 1999 の LMS 射影を独立に実装して照合した結果:
  - 現行順の隣接最小距離(一般/P型/D型の3条件の最小) = **0.0161**(調査員 0.014。実装差の範囲)
  - 提案順 = **0.7453**(調査員 0.746。**一致**)
  - P型シミュレーション色 紫 `#c39bff` → **`#a0a0ff`** / 青 `#5aa9ff` → **`#a2a2ff`**(**完全一致**)
  - **120通りの全順列を総当たりした結果、提案順(黄→紫→赤→青→緑)は 1位/120。真に最適。**

  **この項は6項目中で唯一、申告どおりの精度で検証を通った。確度A を認める。**

- **確度**: CVD の弁別距離と並べ替えの効果は **A**(検証者が独立実装で再現済み)。
  「色手がかりが保持を上げる」は **B**(複数研究が一致、ただし本文は egress 遮断で未読)。

## 定石が見つからなかったもの(自チャンネルで決めるしかない項目)

1. **背景パターンの適正な薄さ**(A1-3)。素材サイトもジェネレータも「邪魔しない範囲で」としか書かない。
   数値の定石は存在しない。
2. **ビネットの適正な強さ**(A1-4)。撮影・編集の文献はすべて定性的。ソフト固有のスケール値しか無く、
   こちらの実装には翻訳できない。
3. **背景の常時ドリフトが視聴維持に効くか**(A1-5)。「常にどこかが動く」を裏づける実測は
   1本も見つからなかった。学術側は逆(装飾的な動きは理解を妨げる)を示すが、
   対象が学習成績であって視聴維持率ではない。**案2(余白のみ)vs 案3(完全撤去)の A/B が要る。**
4. **章チップの色数の上限**(A1-6)。「多すぎると認知負荷」は言えるが、
   5色が多すぎるのかどうかを判定できる基準は見つからなかった。
