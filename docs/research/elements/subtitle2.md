  画面上の作り分けは `draw_subtitle()` の帯左端の色ラインだけ。実測すると:

| 指標 | 実測値 |
|---|---|
| ラインの太さ | `0.007 × 1920` = **13.4px**(360p換算 4.5px) |
| ずんだもん緑 `#3ecf8e` vs 帯 | 9.37:1 |
| めたんピンク `#f28bb4` vs 帯 | 8.13:1 |
| **緑とピンクの相互コントラスト** | **1.15:1** |
| 2型色覚シミュレーション(Viénot 1999 の LMS 変換を自前実装) | 緑 →(180,180,145) / ピンク →(178,178,177)、**相互コントラスト 1.00:1** |
| 1型色覚シミュレーション | 相互コントラスト 1.51:1 |
| 実フレームで測った 帯の色 | **RGB(18,17,16) = #121110**(字の無い左端を60フレームからサンプル) |
| 実フレームの帯に対する INK `#f2f1e9` のコントラスト | **16.65:1** |

  そして決定的な事実:
  **L001 の 113ユニット中 71本(63%)が `chara="none"`** で、そこでは立ち絵も
  頭上の名前プレート(`draw_speaker_plate`)も描かれない(`render_video` の
  `if chara_on and not no_chara:` の中でしか呼ばれないため)。
  **その71本では、話者を示す視覚情報は13pxの色ラインだけになる。**
  内訳は めたん41本 / ずんだもん30本。

  「長さの規定は台本側にあり二重管理」という前提も検証した。**二重管理ではなかった。**
  `production/check_*.py` を全部当たったが、**話者別の字幕長規定は存在しない**。
  長さに関する規定は `check_video.py` の3つだけで、話者を見ていない:
  「1文35字以内(横型は48字)」「字幕2行以内」「字幕縮小75%未満」。
  実態は **規定が片側(`check_video.py`)にしか無い**である。

- **選択肢**:

| 案 | 内容 | 根拠・採用例 | 長所 | 短所 |
|---|---|---|---|---|
| ① 現状維持 | 13pxの色ラインのみ | 現行 | 追加なし | 2型色覚で相互コントラスト1.00:1。63%のユニットで唯一の手がかり |
| ② ラインを太く | 0.007 → 0.02(13px→38px) | — | 面積は3倍 | 色だけの符号化という問題は解決しない |
| ③ 位置で分ける | ずんだもん=帯の左端 / めたん=帯の右端 | 二者の掛け合いで左右に分ける定石 | **色に依存しない**。色覚でも判別可 | 帯の両端が塞がる |
| ④ 形で分ける | 実線 / 破線、あるいは ▲/● のマーク | ノンカラー符号化の基本 | 色に依存しない | 13pxでは形が潰れる(360pで4.5px) |
| ⑤ `chara="none"` でも名前プレートを出す | プレートの描画条件を立ち絵から切り離す | 現行のプレート実装をそのまま使う | 文字なので誤読が無い | 図に重なるおそれ。ただし y0.80〜0.90 は実測でほぼ空き |
| ⑥ 話者別に字数上限を変える | 聞き手の台詞を短く | — | リズムが作れる | 実測では字数差が0.1字しかなく、直す対象が無い |

- **比較**:
  - ①→③ で 2型色覚での判別可能性は 1.00:1(不可)→ **位置差 1920px 分**(確実に可)に変わる。
  - ②はコントラスト比を1つも改善しない(色は同じ)。面積だけ3倍。
  - ⑤は A3-17 で測った空き領域(y0.80〜0.90 の局所コントラスト最大 0.4〜3.4)に載せられる。
  - ⑥は測定上、直す対象が存在しない(めたん22.7字 / ずんだもん22.6字)。

- **決定(第2ラウンドで書き換え)**:
  1. **「色だけの符号化をやめて二重符号化にする」ことは決定**。
     根拠は自前測定(A): 緑とピンクの相互コントラストは通常視で1.15:1、
     2型色覚シミュレーションで **1.00:1**(= 判別不能)。かつ `chara="none"` の
     **71本(63%)** ではこのラインが唯一の話者手がかりになっている。
     WCAG 1.4.1(色を唯一の視覚手段にしない)は Level A で、複数スニペットが一致(B)。
  2. **どの二重符号化にするかは決めない。案③(位置)と案⑤(名前プレート)を並べて残す。**
     初稿は案③に確定していたが、**その採用理由「二者の掛け合いで左右に分ける定石」に
     裏が取れなかった**。検証員が再検索したところ、日本語のバリアフリー字幕で
     見つかった定石は次のとおりで、**位置ではなく文字**である(独立スニペット3件以上=B):
     - 話者名表記は、その話者が**話し始めた最初の字幕に必ず入れる**のが基本
     - 話者名は()などで囲んで本文と区別する
     - 画面内で話者が明らかに判別できるときだけ省略してよい
     - CM字幕の色分けは 黄→緑→シアン→白 の順(色は**併用**するもので、単独ではない)
     この定石は **案⑤(`chara="none"` でも名前プレートを出す)** の側を支持する。
     案③を推す外部規範は見つからなかったので、**案③の優位は確度C**。
     CLAUDE.md の「確度Cで行動を変えない」に従い、**③か⑤かは A/Bテスト送り**(AB-S4)。
  3. 字数の作り分け(案⑥)は **しない**。測定で差が無いため(めたん22.7字/ずんだもん22.6字)。
  - 変更しない部分: 帯の色・文字色(実フレームの帯 RGB(18,17,16) に対して 16.65:1。
    WCAG AAA を大きく上回る)。

- **根拠**: 相互コントラスト1.15:1、2型色覚で1.00:1、`chara="none"` が63%、
  これらはすべて自前測定(検証員が全部再現した)。
  「色だけで情報を伝えない」は WCAG 1.4.1(B)。
  **決め手は 1.00:1 という自分の測定値**であり、そこは動かない。
  動いたのは「では何に替えるか」で、そこは測れていない。
  「二重管理」という前提はコードを当たって否定した(規定は片側にしか無い)。

- **確度**: 色差・色覚シミュレーション・`chara="none"` の比率・ゲートの有無 **A** /
  「色以外の手がかりが要る」**A+B** / **③と⑤のどちらが良いか C** → 実装案はA/B送り。

2〜3本での比較は意味を持たない。

**さらに強い制約がある。** `docs/research/hold-rate-2026-08.md` の実測では
**7割が最初の1〜2秒で消えている**。平均視聴率(APV)はこの1〜2秒の離脱に支配されるので、
**字幕レベルの差はAPVでは絶対に見えない**。同ドキュメントは
「色・フォント・立ち絵などの見た目だけの変更を『維持率施策』と呼ばない」とも書いている。
したがって AB-S1 / AB-S3 の判定指標から **APV を外し、区間維持率(該当ユニットの
前後10秒)だけを見る**こと。APV を指標に残すと、効果が無いのに「効いた」と読める
ノイズしか取れない。

## 実装のまとめ(この調査で「変更」と決めたもの)

1. **`shortlib.wrap_plain()` を案Dに差し替える**(A3-15・A3-21。同一の変更)
   - 文節境界 ∪ 句読点直後 から、専門語・4字以上の連続名詞の内側を除いた候補を作る
   - `max(左の字数, 右の字数)` を最小化する1点で2分する。同点なら中央寄り
   - 効果(**matplotlib 実測幅**): 縦型の自動縮小 **221本(47%) → 147本(31%)**、
     最小縮小率 **0.727 → 0.750**、
     行長差 平均3.75→2.43(縦)/ 7.50→2.90(横)、文節途中 2→0、専門語分割 0→0
   - 影響範囲: 739字幕中162本(22%)の見た目が変わる。適用は L002 以降と再レンダリング時
2. **`check_video.py` の `_w()` 近似幅を実幅に寄せる**(A3-18。**第2ラウンドの追加**)
   - 約物 `。、…` を 0.6 → **1.0**、数字を 0.55 → **0.61**、`%` を 0.55 → **0.99**
   - いまの近似は幅を小さく見積もるので、**実測では0.75を割っている4行を全部PASSさせている**
   - **1 と同じ回に入れる**(案Dで最悪ケースが0.750に上がるので、直しても落ちなくなる)
3. **`check_long.py` に「字幕の数値が図にも出ているか」の照合を足す**(A3-20)
   - 落とさずに一覧を出す。L001 の現状は 54〜57/70(**約8割**)一致
4. **`use_landscape()` の docstring を実測値に直す**(A3-18)
   - 「横幅が1.78倍なので12字→26字」は誤り。実収容量は 縦10.5字 / 横29.5字 で比2.81倍
   - 「縦型52ptは1920pxの3.8%」は実測3.75%で概ね正しい。「横型40pt=4.9%」は実測**5.19%**
   - 縦の12字の出どころはループ20(`iteration-log-2.md`)。ただし
     `SUB_BLOCK_FIT=0.70` と一度も突き合わされておらず、実際には上限を14%超えている
     (値を動かしても測定上の利得は1.3ポイントしか無いので、値は変えない)

**保留にしたもの(第2ラウンドで「変更」から降格)**

- **`draw_subtitle()` の話者ラインの左右分け**(A3-19 案③) → **AB-S4 に送る**。

## 変更しないと決めたもの(と、その理由)

- **`SUB_WRAP` の値(縦12 / 横26)**: 掃引したが効かなかった(A3-18)
- **字幕のハードカット**: 表示秒1.48〜6.19秒は外部の目安の内側で、
  変える必要の証拠を測れなかった(A3-16)
- **ルビ**: 落とす決め手は 360p の可読性(暗部 1.4→**32.1**、枠内コントラスト
  19.16→**16.28**)と、2行字幕では上の行と重なること。
  帯の余白は31.8px、20ptの字は27.8pxで、**幾何だけなら1行字幕には入る**(A3-17)
- **話者別の字数上限**: めたん22.7字 / ずんだもん22.6字で、直す対象が無い(A3-19)
- **`EMPH` の色**: 実フレームの帯 RGB(18,17,16) に対して **10.28:1** で AAA 超え(A3-20)。
  ただし `GOLD` `#c98500` は **6.14:1** で AA 止まりなので、細い字に単独で使わない
- **`goi_futsu.txt` への専門語の登録**: 登録すると `check_goi.py` が素通りさせ、
  台詞での定義忘れに気づけなくなる(A3-17)

## 測れなかったこと(正直に書く)

- 視聴者が実際にどう読むか(読了率・視線)は、この環境では**一切測れていない**。
  したがって「読みやすさ」を理由にした変更は1つも入れていない。
  入れた変更の理由はすべて、**フォントが縮む・語が割れる・話者の色が判別できない**という
  物理的に確認できる事実である。
- 外部の一次資料(放送事業者の字幕ガイドライン、Netflix の Japanese Timed Text Style Guide、
  W3C/WCAG の原文)は**1本も読めていない**(第2ラウンドの検証員も同じ。
  partnerhelp.netflixstudios.com / w3.org は EGRESS_BLOCKED)。外部の話はすべて検索結果のスニペットであり、
  確度Bを超えない。とくに Netflix の日本語の読み速度の上限は、
  スニペットからは具体的な数値を確認できなかった(確度C相当なので判断に使っていない)。
- `hard_split` の発火が将来どれくらい増えるかは、台本の書き方しだいなので予測できない。
  縦型の句長 p99=15字に対して閾値が16字という**余裕1字**の事実だけを記録しておく。
