## A6-1 キーワード強調

- **現状**:
  - 実装 = `shortlib.py:767` `_EMPH_RE = re.compile(r"【(.+?)】")` → `parse_rich()` →
    `draw_rich_line()` が該当セグメントだけ `EMPH`(既定 `#fab219`)で描く。
    非強調は `INK`(`#f2f1e9`)。縁取りは両方 `outline_for(fontsize)` = 文字サイズの10%。
  - **L001 での使用は 0 箇所**。S001〜S009 は 10〜14箇所/本、**S010・S011 が 2箇所**、
    **S012 以降は全部 0**(検証員が全 render.py を数え直した。研究員の記述は S010/S011 が
    抜けていた)。**12〜14 → 2 → 0 と段階的に捨てられた**ので、
    「一度も使わなかった」ではなく「途中で使うのをやめた」が正しい。
  - **SEとの結合は存在しない。** `Unit.se` は「そのユニットで鳴らす音」、`【】` は
    字幕内のマークアップ。どちらも相手を参照していない。「【】黄+SE」は事実ではない。
- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | ① 0箇所のまま | 強調機構を使わない | — | 落ち着く。色数が増えない | **強調という手段が無い**。「色は絞る」を通り越して0 |
  | ② 色替えを本数制限つきで復活 | 1本5箇所 | [黄色=注目・警告。動画全体で色の意味を統一](https://omniweb.jp/m25/) / [テロップは4色以内、うち2色は無彩色、残りをアクセントに](https://coconala.com/magazine/25667) / [Strategic emphasis rather than constant visual noise](https://www.opus.pro/blog/tiktok-caption-subtitle-best-practices) | 定石の「絞る」に最も近い。長尺は置き場所が構造で決まっている | 効果の実証は無い |
  | ③ 色ではなくサイズ・太さで強調 | 該当語だけ 1.15倍 | [装飾を盛り込みすぎると読めなくなる](https://freedoor.co.jp/blog/video-telop-design-guide/) | 色数が増えない | 1行内で高さが揃わず `block_fit` の縮小計算が崩れる(実装コスト大) |
  | ④ カラオケ式(発話同期で1語ずつ点灯) | Captions/CapCut系の定番 | [Word Highlighting Subtitles](https://www.vocallab.ai/blog/word-highlighting-subtitles) / [Highlight Keywords in Captions](https://captions.ai/help/guides/engagement/highlight-keywords) | ショート系で最も普及。視線が文字に貼りつく | **8分×113ユニットで常時点滅**は Mayer の一貫性の原則に真っ向から反する。VOICEVOX の `audio_query` からモーラ時刻は取れるので実装は可能だが、フレーム数が跳ね上がる(現行 20fps → 全ユニット30fps 必須) |
  | ⑥ 既存の「ポン」(字幕スケール)を強調に使う | `draw_subtitle(pop=1.06)`。`shortlib.py:1245` が **anim ユニットの先頭フレームだけ**字幕を6%大きく描く。既に実装され、L001 の54ユニットで発火している | 当リポ現行(**研究員の選択肢表から漏れていた**) | 実装ゼロ。色数が増えない | **ユニット単位**でしかかからない。語を指せない |
  | ⑤ 強調語に背景マーカー(蛍光ペン) | 塗り + 濃色文字 | [囲みたい時は枠線より背景の塗りつぶし](https://sp-jp.fujifilm.com/future-clip/document/vol12.html) | 図の中の `table` highlight と作法が揃う | 字幕帯(`#0b0b0a` alpha 0.52)の上にもう1層の帯 = 3層重なり |

- **比較の軸**: 定石(絞る)との距離 / このパイプラインでの実装コスト / 長尺の構造との整合 /
  Mayer の一貫性の原則 / 権利(全案とも自前描画で権利問題なし)
- **決定**: **変更**。
  1. `【】` を長尺で復活。**1本5箇所**(冒頭40秒の答えの金額1 + 各章の出口の判定文の
     金額または率4)。上限は `check_long.py` に **1本8箇所 / 1ユニット1箇所**として入れる。
     ※ この本数と置き場所は `elements/subtitle.md` の A3-10 の決定と同一。二重に決めない。
  2. **強調の手段は「色替え1つ」だけにする。** サイズ・太さ・背景マーカー・カラオケ式は
     採らない(装飾は1〜2つが上限、という定石に対し、色替え+既存の縁取りで既に2つ)。
  3. **`【】` と `se` を結合しない。** 「【】黄+SE」という記述を撤回する。SEの本数は
     A7-3 で別に決める。
- **根拠**:
  - 0箇所は「絞る」ではなく「無い」。定石側は一貫して「絞れ」であって「使うな」ではない
    ([omniweb](https://omniweb.jp/m25/)、[ココナラ](https://coconala.com/magazine/25667)、
    [VIDEO SALON テロップ大学](https://videosalon.jp/series/telop_vol1/))
  - 装飾の重ねすぎを戒める記述は複数で一致
    ([freedoor](https://freedoor.co.jp/blog/video-telop-design-guide/) ※本文はegress遮断で
    スニペットのみ、[テロップ大百科](https://varietytelop.com/2025/04/21/telop_rules/))
  - カラオケ式は「常時動く画面」を作る。長尺8分に対しては
    Mayer の一貫性の原則(`longform-design.md` §7 が確度Aで引いている)に反する
  - **「強調があると視聴維持が上がる」という根拠は見つからなかった。**
    `hold-rate-2026-08.md` が「見た目だけの変更を維持率施策と呼ばない」と明記している。
    これは見た目の変更であり、維持率の施策ではない
- **確度**: ⚠ **検証員が B → C に下げた。**
  研究員は「『絞る』の定石は複数一致」を根拠に B としたが、
  **その「複数」の中身(omniweb / ココナラ / VIDEO SALON / opus.pro)は
  検証員が1本も本文に到達できなかった**(全ドメインが egress 遮断)。
  相互に独立かどうかも、書いてある内容が引用どおりかも確認できていない。
  `research-standards.md` は「行動を変える主張は独立ソース5本以上+一次資料1本以上」
  としており、**到達不能な二次ブログ3〜4本は B の要件を満たさない**。
  したがって **C**。「0箇所は『絞る』ではなく『無い』」という**内部観察のほうが強い根拠**で、
  復活させること自体は妥当だが、**本数(5)も上限(8)も外部根拠ゼロ**である

## A6-2 ヒーロー数字

- **現状**:
  - `shortlib.py:735 draw_glow_text()` は3層:
    1. 影 = `y-0.007`、`#000000`、alpha 0.5、`Stroke(linewidth=12)`
    2. グロー = 同位置、色 `EMPH`、alpha 0.28、`Stroke(linewidth=30)`
    3. 本体 = `stroke_fx(color, outline=fontsize*0.10, fatten=4)`
  - **長尺では1回も呼ばれていない。** 長尺の大きい数字は `sl.card()` / `sl.hero()` 経由の
    `draw_rich_text` で、装飾は `stroke_fx(outline=fontsize*0.10, fatten=2)`。
    ※ 厳密には `cover()` の bottom だけ `fatten=2.5`(`scenes_long.py:97`)なので
    「1系統だけ」は不正確(検証員)。
  - 長尺の主役文字サイズ: `hero` main 96 / `card` main 76 / `cover` main 190 /
    `chapter` の章題 92。字幕は `SUB_FS=40`。
- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | ① 現状維持 | 長尺は縁取り1層のみ | — | 一貫している。実装ゼロ | 「答えの数字」と「ふつうの見出し」が同じ見た目。見せ場が無い |
  | ② 3層グローを長尺にも入れる | `draw_glow_text` を `sl.hero`/`card` から呼ぶ | 当リポのショート S006/S008 | 実装済み。立体感 | **装飾3つは定石の上限超え**([freedoor](https://freedoor.co.jp/blog/video-telop-design-guide/):「装飾は1〜2つの組み合わせが上限。基本のエッジ+ドロップシャドウが鉄板」) |
  | ③ 2層(縁取り+影)にする | グロー層を外す | 同上「エッジ+ドロップシャドウが鉄板」 | 定石ど真ん中 | **背景が `SURFACE = #1a1a19`(ほぼ黒)なので、黒い影も黒い縁取りも視覚的にほぼ効かない。**「鉄板」は明るい実写背景を前提にした助言 |
  | ④ 装飾は増やさず、色とサイズで差をつける | 数字だけ `EMPH`、単位・ラベルは `INK_2`、文字サイズを見出しの1.6〜2倍 | [Big Number は「1つの値+ラベル」。値の text scale を上げるだけで視覚的インパクトを作る](https://www.beautiful.ai/templates/big-number-template) / [Adobe Spectrum Big Number](https://spectrum.adobe.com/page/big-number/)(※egress遮断で本文未読) | 暗背景で確実に効く軸(輝度差・面積差)だけを使う。実装が軽い | 「立体感」は出ない |
  | ⑤ 数字を図の上でだけ大きくする | 独立した数字カードを作らない | `longform-design.md` §5「数字は図の上で言う」(確度A) | 既存ルールと矛盾しない | 図の中に 150pt は置けない(レイアウトが破綻する) |

- **比較の軸**: 暗背景(#1a1a19)で実際に効くか / 装飾の数の定石 / 既存ルール
  (「数字は図の上で言う」)との衝突 / 実装コスト
- **決定**: **変更 — ④**。`scenes_long.py` に `hero_number()` を追加する。具体値:
  - 数字本体 fontsize **150**(`card` の main 76 の約2倍、`hero` の main 96 の1.56倍)
  - 色は `EMPH`。単位・ラベル・注記は `INK_2` **36pt**
  - 装飾は **`stroke_fx(EMPH, outline=15.0, fatten=2)`**。
    **影(alpha 0.5 / linewidth 12)もグロー(alpha 0.28 / linewidth 30)も足さない**
  - ⚠ **検証員の修正**: 研究員はこれを「装飾1層のみ」と書いたが、**実態は0層**である。
    `stroke_fx()` の第1ストロークは `foreground="#000000"` **固定**(`shortlib.py:752`)。
    **`#1a1a19` に対する黒のコントラスト比を実際に計算すると 1.206**(検証員が WCAG 式で算出)。
    つまり研究員は、自分が根拠欄で「暗背景では機能しない」と論じたその黒縁取りを、
    **唯一の装飾として指名していた**。決定は自己矛盾していた。
    実際に残るのは `fatten=2` の**同色**ストローク(=字を太らせるだけ)なので、
    **正しくは「装飾なし。輝度差(`EMPH` は `SURFACE` に対し 9.49:1)と面積差だけで見せる」**。
    `outline` を残す意味は**図やドリフト円の上に数字が乗る場合の保険**だけ。
    無地の `SURFACE` 上では効かないと承知したうえで残す
  - 使うのは**1本5箇所まで**(A6-1 の `【】` と同じ置き場所)
  - `draw_glow_text()` は削除しない。**ショート専用**として残す(S006/S008 が公開済み)
- **根拠**:
  - 3層は定石の「1〜2つ」を超える。ただしこの「1〜2つ」は
    [freedoor](https://freedoor.co.jp/blog/video-telop-design-guide/) のスニペット由来の
    **単一ソース**で、本文は egress 遮断で読めていない
  - **暗背景では黒い影・黒い縁取りが機能しない**のは当リポの実測から言える:
    `SURFACE = #1a1a19` と `#000000` の**コントラスト比は 1.206**(検証員が WCAG 式で計算。
    研究員は「輝度差はごくわずか」と定性的に書いただけで数字を出していなかった)。
    対して `EMPH #fab219` は `SURFACE` に対して **9.49:1**。
    縁取り10%ルール(`outline_for`)はショート(実写風の明るい図の上に文字が乗る)から
    引き継いだもので、長尺の暗い一様背景ではほぼ無効。**ここは他所の定石ではなく、
    自リポの配色から導いた**(確度A)
  - 「値を1つだけ大きく」は Big Number コンポーネントの共通仕様
    ([Beautiful.ai](https://www.beautiful.ai/templates/big-number-template)、
    [Adobe Spectrum](https://spectrum.adobe.com/page/big-number/) ※未読)
- **確度**: **C**。「3層が多すぎる」の外部根拠が単一ソース。
  150pt という具体値にも外部根拠は無い(既存サイズからの比で決めた)。
  **効果は自チャンネルで A/B すべき**(L002 で導入し、L001 と 50%地点以降の維持率を比べる)

## A6-3 ズーム/パン

- **現状**: **不採用**。動きは3系統だけ:
  1. 図の `anim`(54/113ユニット、ほぼ全部 `anim=1.4` の `fps=20`)。
     painter が `t`(0→1)を受け取り、棒が伸びる・行が順に出るなどの**段階表示**
  2. リッチ背景の円貨ドリフト(`DRIFT_FPS = 4`、`_draw_rich_layers` が `t` で円を流す)
  3. 立ち絵の口パク(`CHARA_FPS`)
  - カメラの押し込み・寄り(Ken Burns)は**1箇所も無い**
- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | ① 不採用のまま | 段階表示だけ | 当リポ現行 | 図が読める。実装ゼロ | 「画面が動かない」印象 |
  | ② 全編ゆっくり押し込み | ffmpeg `zoompan` を結合時に1回かける | [Ken Burns は静止画に動きの錯覚を与える定番](https://en.wikipedia.org/wiki/Ken_Burns_effect) | **実装が一番安い**(`shortlib.py:615` の `-vf` に1フィルタ足すだけ) | **全ユニット一律にかかる**。図が拡大されて右端の立ち絵が切れる。8分間ずっと動くのは一貫性の原則に反する |
  | ③ ユニット単位の寄り | painter が `t` で軸範囲を狭める | [解説動画では図の一部への緩やかなパンが注意を誘導する](https://www.capcut.com/create/ken-burns-effect-educational-images) | 意味のある寄りだけ作れる | **11個の painter を全部書き直す必要がある**。`fig.text` の figure 座標が大半で、軸のズームでは動かない。実装コスト最大 |
  | ④ 段階表示を強くする(=現状の延長) | `anim` を持たないユニット59本のうち、数字が増えるものに `step` を足す | `longform-design.md` §5「絵を差し替えるのではなく `step` で数字を足す」 | 既存の仕組みで足りる。図が読める | 「動き」としては地味 |

- **比較の軸**: 実装コスト(painter 11個の書き直しが要るか) / Mayer の一貫性の原則 /
  YPP 量産型規制(静止画+合成音声だけは「繰り返しコンテンツ」と判定されうる) /
  横型レイアウト(右端 x>0.78 は立ち絵の領域)との衝突
- **決定**: **維持(不採用)**。
- **根拠**:
  - Ken Burns が学習・維持に効くという主張の出どころは**動画編集ツールのマーケティング記事のみ**で、
    査読研究は見つからなかった
    ([Cloudinary](https://cloudinary.com/guides/image-effects/ken-burns-effect-complete-guide-and-how-to-apply-it)、
    [CapCut](https://www.capcut.com/create/ken-burns-effect-educational-images)、
    [Filmora](https://filmora.wondershare.com/video-creative-tips/what-is-ken-burns-effect.html))。
    しかもどの記事も「説明を追うのに役立つときだけ」と条件を付けている
  - YPP の「静止画背景で合成音声が喋るだけ」への懸念は
    [ゆっくり解説の作り方](https://dc.wondershare.jp/editing-tips/how-to-make-yukkuri-explanation-video.html)
    が指摘しているが、**L001 は既に該当しない**: 図の段階表示が47.8%、背景ドリフトが常時、
    立ち絵の口パクがある。ズームを足す理由が量産型対策にはならない(確度A、自リポの実測)
  - **案②の全編ズームは、右端の立ち絵が切れるので採れない。**
    `scenes_long.py` は「図は x<0.78 に収める / 立ち絵は x 0.798〜0.990」で組んである。
    中心から拡大すると立ち絵の外側が画面外に出る(確度A、レイアウト定義から自明)
- **確度**: **C**(「入れない」ことの積極的根拠は無い。「入れる根拠が無い」だけ)。
  **定石は存在しない → 自チャンネルで A/B テストする対象**。ただし案③のコストが
  他の全項目より一桁大きいので、優先度は最下位に置く

## A7-3 転換SE

- **現状**: `shortlib.py:464 synth_se_track()`(研究員は 465 と書いた)。全部 numpy で自前合成(権利問題なし)。
  - `pop`: 0.09秒。620Hz → 1100Hz の上昇ブリップ、`exp(-t*34)` 減衰、振幅 0.5
  - `don`: 0.28秒。`130*exp(-t*7)+46` Hz の低音、`exp(-t*11)` 減衰、振幅 0.9
  - `puchun`: 0.34秒。60 + 3400*`exp(-t*22)` Hz の下降スイープ + 冒頭の断線ノイズ、振幅 0.85
  - `impact`: `production/assets/se/impact.mp3` の実ファイル(唯一の外部素材。
    `production/assets/se/` には他に README.md しか無いことを検証員が確認)
  - トラック全体は **peak が 1.0 を超えたときだけ**正規化(`if peak > 1.0: track /= peak`)、
    そのあと **×0.5**。研究員は「peak 正規化のあと ×0.5」と無条件のように書いたが、
    **条件つき**である(`shortlib.py:528-531`。検証員が訂正)。
    この条件が下の `switch` の設計に効いてくる
  - 現行の各SEの実測(検証員が numpy で再合成して測定):
    `pop` peak 0.493 / rms 0.143、`don` peak 0.886 / rms 0.256、
    `impact` は `_load_se_file` が peak 1 に正規化してから ×0.9 = peak 0.9。
    **どれも 1.0 を超えないので、現状は正規化が発火していない**
  - **L001 の使用: pop 9 + don 5 + impact 4 = 18箇所 = 全113ユニットの 15.9%**
  - **章札4本はすべて `se="pop"`** = テロップ音と同じ音を転換にも使っている
- **選択肢**:

  | 案 | 内容 | 採用例・出典 | 長所 | 短所 |
  |---|---|---|---|---|
  | ① 現状維持 | 18箇所 / pop を転換にも流用 | 当リポ現行 | 実装ゼロ | **自リポの「SEは9%が上限」を 15.9% で超えている**。同じ pop が9回鳴るので転換の合図として立たない |
  | ② 本数を絞る | 18 → 10箇所(9%以下) | [効果音の入れすぎはうるさいだけ](https://mobunikomiudon.com/se-kotsu/) / [まず冒頭・最重要点・まとめの3箇所から](https://tadaoto.com/blog/how-to-add-sound-effects-to-video/) | 残った音が効く | 「メリハリが減った」と感じる可能性 |
  | ③ 転換専用の音を1種足す | 章札だけ別の音 | [同じスウッシュを40カット全部に使うと3カット目で意味を失う](https://soundgrail.com/blog/shape-movement-and-flow-in-modern-sound-design) / [場面転換の効果音は新しい場面への好奇心を高める](https://hoshizora-sketch.hatenadiary.jp/entry/2023/07/13/181605) | 「章が変わった」が音だけで分かる = ラジオテストにも効く | 音が1種類増える |
  | ④ 外部のスウッシュ素材を買う/落とす | 定番のトランジションSE | [各種SFXパック](https://www.flexclip.com/learn/transition-sound-effects.html) | 質が高い | **外部素材のダウンロードは原則不可**という当リポの制約に反する |
  | ⑤ SEを全廃 | 音は声とBGMだけ | Mayer の一貫性の原則 | 最も「抜く」方向 | 転換の合図が止めだけになる。実測の裏付けなしに捨てるのは行き過ぎ |

- **比較の軸**: 自リポの9%ルールとの整合 / 同じ音の反復による摩耗 / 権利(自前合成か外部素材か) /
  ラジオテスト(耳だけで章の切れ目が分かるか) / 実装コスト
- **決定**: **変更 — ②と③を両方**。具体値:
  1. **SEの総数を 18箇所 → 10箇所以下**(113ユニットの 9% = 10.2箇所)にする。
     残す優先順位は「冒頭の答え / 各章の出口の判定 / 章札 / 締め」。
     `check_long.py` に **「SEを持つユニットが全体の9%を超えたら不合格」**のゲートを足す
  2. **章札専用の SE `"switch"` を `synth_se_track()` に追加**する。
     章札4本を `se="pop"` → **`se="switch"`** に変える。

     ⚠ **研究員が書いた仕様は実測で反証された。却下し、下の修正版に差し替える。**

     研究員の原案:
     ```
     env = sin(pi*ts/dur)**2
     nz  = default_rng(11).normal(0,1,len(ts))
     sig = 0.35 * nz * env              # 「振幅 0.35 は pop の 0.5 より小さい」
     ```
     検証員が実際に合成して測った結果:

     | 音 | peak | rms |
     |---|---|---|
     | pop | 0.493 | 0.143 |
     | don | 0.886 | 0.256 |
     | **研究員案の switch** | **1.184** | **0.216** |

     **転換の音が `don` より大きい。** 研究員の「振幅 0.35 だから小さい」は
     **係数の意味を取り違えている**: `pop`/`don` の 0.5・0.9 は
     **有界な `sin()`(±1)**に掛かる係数だが、`normal(0,1)` は**非有界**で
     0.22秒 ≒ 9700 サンプルなら ±3.4σ 程度まで出る。0.35×3.4 ≒ 1.19。

     しかも **peak が 1.0 を超えるので `if peak > 1.0: track /= peak` が発火し、
     同じ動画の他のSE全部が 1.184 で割られる**(`don` 0.886 → **0.748**)。
     章札の音を足したせいで、オチの `don` が痩せる。**副作用のほうが大きい。**

     **修正版(検証員。雑音を先に peak 正規化してから係数を掛ける)**:
     ```
     dur = 0.22
     ts  = np.arange(int(dur*sr))/sr
     env = np.sin(np.pi*ts/dur)**2           # 山型の包絡。頭も尻も立たない
     nz  = np.random.default_rng(11).normal(0, 1, len(ts))
     nz  = nz / np.abs(nz).max()             # ★ここが原案に無かった
     sig = 0.45 * nz * env                   # 「シャッ」という短い雑音
     ```
     実測: **peak 0.397 / rms 0.072**。`pop`(peak 0.493 / rms 0.143)より
     peak も rms も下、`don` の半分以下。**1.0 を超えないので正規化も発火しない**。
     係数 0.45 は「peak を pop の 0.493 より確実に下、rms は pop の約半分」から選んだ
     (広帯域雑音は同 rms の正弦より大きく聞こえるので、rms は余裕をみて下げてある)。
     **`np.random` は `puchun` が `default_rng(7)` で既に使っている**ので依存は増えない
  3. `impact.mp3`(唯一の外部素材)は残す。ただし4箇所 → **2箇所以下**に絞る
- **根拠**:
  - **`longform-design.md` §7 が「SEを増やさない(9%が上限の目安)」と書いてあるのに、
    L001 は 15.9%**(確度A、`grep -c` で確定)。自分のルールを守っていないだけ。
    ただし**この「9%」自体の出どころは文書内に書かれていない** = 数字の根拠はC
  - 同じ音の反復が意味を失うことは制作側で一致
    ([soundgrail](https://soundgrail.com/blog/shape-movement-and-flow-in-modern-sound-design)、
    [Sonilo](https://sonilo.com/blog/guides/transition-effect-sound-video-edits))。
    `pop` を9回鳴らして、そのうち4回が章札 = 転換の合図として立っていない(確度A)
  - 「まず3箇所から始めて、必要を感じてから増やす」という順序は
    [tadaoto](https://tadaoto.com/blog/how-to-add-sound-effects-to-video/) と
    [モブニコミウドン](https://mobunikomiudon.com/se-kotsu/) で一致
  - 転換SEが「新しい場面への好奇心を高める」という主張は
    [星降る夜に綴る](https://hoshizora-sketch.hatenadiary.jp/entry/2023/07/13/181605) 単独。
    **効果の実証は無い**ので、これは「章を音でも区別する」という
    ラジオテスト側の理由で採る
- **確度**(検証員が分割):
  - **SEを 18 → 10箇所以下に絞る = A**。`longform-design.md` §7 が
    「9%が上限の目安」と書いてあるのに L001 が 15.9% という**自リポ内部の違反**。
    外部根拠が要らない。ただし**9%という数字自体の出どころは不明のままなのでC**
  - **`switch` の追加 = C**。転換SEの効果を示す外部根拠は
    hoshizora-sketch の単独記事のみ(しかも egress 遮断で研究員も検証員も本文未読)。
    音色の仕様は検証員の実測で**一度反証されて書き直されている**。
    `research-standards.md` の「確度Cで行動を変えない」に従うなら、
    **`switch` は L002 で試して耳で判断する対象であって、いま確定させる話ではない**
