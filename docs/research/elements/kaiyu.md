## KY-1 長尺の締めがショートを名指しする設計

### 現状(測定値と測り方)

`grep -E "ショート版|1分版|概要欄のショート|長尺版" videos/*/script.md` を全**30本**に実行(`videos/` のディレクトリは33個だが、S024〜S026 に script.md が無い)。

| 動画 | 締めでショートに触れるか | 位置(`uploads/L001.srt` の時刻) |
|---|---|---|
| **L001** | ○ 2行 | 06:27.881〜06:36.525(字幕111・112) |
| **L002** | **× 0件** | — |

L001 の該当行:

> 111 税金の20.315%は、概要欄のショート版でも見られるのだ。
> 112 ショート版なら、利益と手取りの図だけをさっと見られるわ。

`ffprobe` で L001 = **400.704秒(06:40.704)**。名指しは終端の **12.823秒前**に始まり、
**4.179秒前**に終わる。

**ただし「名指し」になっていない。** 言っているのは「ショート版」という一般名詞だけで、
**動画のタイトルも番号も言っていない**。キット側の `■ 終了画面 / 次の動画` は
L001=S017 / L002=S013 と別に持っており、**発話と設定が同期していない**
(S017 の問題は KY-3 を参照)。

> **検証員の追記(2026-08-22・確度A)**: 規格そのものは**既にキットに書かれていた**。
> `uploads/L001_投稿キット.txt:80` に
> 「※ナレーションで**その動画の名前と、見ると何が分かるか**を言う」とある。
> つまり KY-1 で足すのは新しい方針ではなく、**書いてあるのに守られなかったものを機械で見る**
> ゲートである。L001 はこの指示に従わずに焼き上がり、それを止めるものが無かった。

### 選択肢

| 案 | 内容 |
|---|---|
| A 現状維持 | L001 だけが「ショート版」と一般名詞で触れる。L002 は触れない |
| B 両方に入れる | L001/L002 の締めで、次に見るショートの**タイトル**を言う |
| C 発話をやめる | 締めでは言わず、終了画面のカードだけに任せる |
| **D 規格化** | 締めユニットで**タイトルを言う** + 概要欄の上部にリンクを置く(KY-4)+ 終了画面の長さを発話に合わせる |

### 比較

| 指標 | A | B | C | **D** |
|---|---|---|---|---|
| 名指しのある長尺 | 1/2 | 2/2 | 0/2 | **2/2** |
| 動画のタイトルを言う | ×(一般名詞) | ○ | — | **○** |
| 終了画面(10〜15秒)と発話の重なり | 10秒設定だと発話開始が **2.8秒はみ出す**(6:27.9 発話 vs 6:30.7 カード出現) | 同左 | 完全 | **13秒設定で重なり100%** |
| クリックできる行き先 | 0 | 0 | 1(カード) | **2(カード+概要欄リンク)** |
| L001 の焼き直し | 不要 | **必要** | 必要 | **不要**(既に納品済み・8/22 18:00 公開) |

### 決定

**D に変更する。ただし L001 の mp4 は焼き直さない。**

1. `docs/research/longform-design.md` と `production/check_long.py` に
   **「締めユニットで、次に見る動画のタイトルを言う」** を足し、
   **まだレンダリングしていない L002 から適用する**(L002 は output/ が存在しない = 未レンダリング)。
2. **L001 の終了画面の長さを「10〜15秒」から `13秒` に確定する。**
   発話開始が終端の12.823秒前なので、これを覆う最小の整数秒が13。
   `make_upload_kit.py` の `long_kit()` の該当行を、動画ごとに秒数を出す形にする。
3. L001 の発話「概要欄のショート版」が嘘にならないよう、**概要欄側を直す**(KY-4)。
   台本ではなく概要欄を直すので、焼き直しが要らない。

### 根拠

- 発話位置(06:27.881)・尺(400.704秒)・差(12.823秒)は**自分で測った**。
- 終了画面が長尺のみで最大20秒・10〜15秒が目安、という枠は前ラウンドの `channel.md` と
  キット本文に既にある。ここでは**その窓に発話を収める**という幾何の話しかしていない。
- L001 を焼き直さない判断は、mp4 が既に納品済みで公開が 8/22 18:00 という日程の事実による。

### 確度

- 発話位置・本数・尺 = **A**(ffprobe と srt の実測)
- 終了画面が長尺専用・上限20秒 = **B**(前ラウンドで support.google.com 系スニペット3件一致)
- **「タイトルを言うとクリックが増える」= C。** だから「言う」ことは規格に入れるが、
  **効果は約束せず A/Bテストに送る**(下記 AB-3)

### 根拠

- **枠が1つしか無い**(確度B)ので、外したときの損が最小なのは「その長尺の中身をそのまま
  1分にした本」だけ。C の平均4.25語に対し、**D は1.06語・B は0.79語で 4〜5倍の開き**がある。
  (**検証員による訂正**: 初稿は D=0.61語・B=0.50語・「7〜8倍」と書いていたが、

  そのまま再実行しても再現しなかった。実測は B(各本を近いほうの長尺へ)=22/28=**0.79**、

## KY-7 回遊が効いているかの測り方

### 現状(測定値と測り方)

`grep -rn "トラフィックソース|関連動画からの|再生リストから|チャンネルページ"` を
リポジトリ全体に実行。

| 測ったもの | 値 |
|---|---|
| 回遊系の指標を**記録する欄** | **0箇所** |
| リポジトリ全体の言及 | `demand-2026-08.md` L146(トラフィックソース「YouTube検索」192回)が**実測の記録としては唯一**。他は `channel.md` L560-561 と `plot-playbook.md` L104 で、いずれも**調査文書の中の言及**であって記録欄ではない |
| ショートのキットの48時間チェック | スワイプ継続率(目標60%+)/ 平均再生率 |
| 長尺のキットの48時間チェック | 平均視聴率 / 平均視聴時間 / 30秒残存率 / 章別維持率 / 終了画面クリック率 |

**KY-1〜KY-6 の変更は、いまのところ効いたかどうかを見る器が無い。**

**依頼された測定(3)の結果 — 負の結果を正直に書く。**
「関連動画リンクを設定した本とそうでない本に差があるか」を測ろうとしたが、
**out-degree は 28/28 で全部設定済み。対照群が存在しないので、この比較は成立しない。**
代わりに in-degree(被リンク数)と `demand-2026-08.md` 追記4 の平均視聴率14本で見た:

| 群 | n | 平均視聴率 | 標準偏差 |
|---|---|---|---|
| 被リンクあり | 8 | 64.4% | 14.7 |
| 被リンク0 | 6 | 63.3% | 20.5 |

**差 1.1pt、Spearman rho = +0.160。ばらつき(標準偏差 14.7 と 20.5)に完全に埋もれている。**

> **検証員の訂正(確度A)**: 初稿の **rho = −0.125 は再現しない**。
> 本文が宣言したとおり「被リンク数 × 平均視聴率」を14本で順位相関にかけると
> **rho = +0.160**(タイあり平均順位)。被リンクの有無を0/1にしても **+0.036**、
> 出所不明の「旧S010」を除いた13本でも **+0.098 / −0.042** で、
> **どの組み方でも −0.125 にはならない**。符号が逆なのは読み手を誤らせる
> (「被リンクが多いほど視聴率が低い」と読めてしまう)ので直す。
> **結論は変わらない**: n=14 で |rho|=0.16 は無相関と区別できず、群平均差 1.1pt は
> 標準偏差の10分の1以下。**手元のデータでは判定できない**。
> なお群平均(64.4 / 63.3)と標準偏差(14.7 / 20.5、いずれも不偏)は初稿どおり再現した。

**しかもこの比較は、そもそも指標が間違っている。**
関連動画リンクは動画の外(ハンドルの下)に出るもので、**平均視聴率(動画の中の維持)を
動かす道具ではない。** 動くとしたら「関連動画」トラフィックソースのほうで、それは測っていない。
**手元のデータでは、回遊が効いているかは判定できない。**

参考として、被リンクの集中先は S004(7本)と S001(6本)で **28本中13本(46%)**。
S004 の平均視聴率は 59.2%(14本中8位)。**一番多くの導線が向かっている先が、
維持率で真ん中の本**という状態になっている。

**外部仕様**(スニペット。support.google.com のアナリティクスヘルプ + 複数の解説記事が一致):

| 項目 | 内容 | 確度 |
|---|---|---|
| トラフィックソースの種類 | YouTube検索 / 関連動画 / ブラウジング機能 / 外部 / 通知 / **再生リスト** / **チャンネルページ** / 広告 / その他 | **B** |
| 「関連動画」の定義 | 他の動画の横や再生後に出る関連動画 **+ 動画の説明内のリンクからのトラフィック** | **B** |
| 「再生リスト」の定義 | 自分の動画が含まれる再生リストからのトラフィック | **B** |

**「関連動画」に説明欄リンク由来が含まれる**のは重要で、KY-4 の長尺概要欄リンクと
KY-2 の関連動画リンクが**同じ行に合算される**ということ。分離できない。
