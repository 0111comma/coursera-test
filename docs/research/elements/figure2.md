**そして、調査員が見落としていた、より重い破綻を3つ見つけた。**

- **`timeline` は n≥6 で6箱目以降が「薄い」のではなく一切描かれない。** `a = clamp01(t*2.2 - k*0.5)`
  が k=5 で 0 になり、`if a <= 0: continue` で飛ばされる。実効上限は **5**。
- **`table` は rows≥8 で8行目以降が描かれない。** 実効上限は **7**。
- **`barsN` は N≥10 で10本目以降が描かれない。** 実効上限は **9**。

いずれも stagger を割る修正(#1〜#3)で消える。消えたあとに効いてくるのは幾何の上限なので、
ゲートの値はそちらに合わせて取り直した(table 行数 ≤6 → **≤7**、列数 ≤5 → **≤6**)。

**確度を落として決定を取り下げたのは1件。** card の使用率 35% ゲートは、閾値の根拠が
「2本しか実績が無い」ままなので確度C。`docs/research/research-standards.md` の
「確度Cで行動を変えない」に従い、**ゲート追加を取り下げて AB-F3 に統合した。**

  size の自動決定と2行化は**採らない**(既存2本の見た目が変わる/立ち絵と干渉する)。
- **根拠**: 10字目から縮み始めることを自分で測った(4〜18字を総当たり)。

## A5b-8【横断】数値ラベルの pt がバラついているのは意図か、不統一か

課題文の宿題:「barsN 30pt / table 34・30pt / timeline 36pt / curve 27pt のバラつきは
意図的な設計か、単なる不統一か」。**測って判定する。**

- **現状(測定値)**: 主役の数値ラベルの pt は **26 / 27 / 30 / 32 / 34 / 36** の6段階に散っている。
  「設計されている」なら、pt は**その型で1つのラベルに与えられる幅**の関数になっているはずである。
  そこで型ごとに「典型的な要素数でのスロット幅」と「そこに置かれるラベルの実測幅」を出し、
  占有率(ラベル幅 ÷ スロット幅)を計算した。

  **調査員の表は型ごとに違う文字列で測っていた**(compare2 だけ「益20万」、timeline は「引けない」、
  他は「40,630円」)。文字列が違えば占有率も違うので、比較になっていない。
  **反証側で「40,630円」1本に揃えて取り直した**のが下表である。

  | 型 | 典型のスロット幅 | 数値ラベル | 「40,630円」の実測幅 | 占有率 | 調査員の値 |
  |---|---:|---:|---:|---:|---:|
  | F-compare2(m=2) | 288px | 26pt | 153px | **0.53** | 0.40(「益20万」で測っていた) |
  | F-table(3列) | 346px | 34pt | 202px | 0.58 | 0.60 |
  | F-table(4列) | 288px | 30pt | 181px | 0.63 | 0.63 |
  | F-barsN(N=6) | 230px | 30pt | 181px | 0.79 | 0.79 |
  | F-timeline(n=5) | 216px | 36pt | 216px | **1.00** | 0.93(「引けない」で測っていた) |
  | F-curve | 制約なし(自由空間) | 27pt | 160px | ― | ― |

  **占有率は 0.53 から 1.00 まで 1.9倍ばらけている**(調査員の「2.3倍」は文字列の取り違えで
  膨らんだ値)。**そして順序が逆である**という結論は、揃えたあとでも変わらない:
  いちばん狭いスロット(timeline 216px)にいちばん大きいラベル(36pt)が入り、
  いちばん広い自由空間(curve)にいちばん小さいラベル(27pt)が入っている。
  **幅で決めた形跡は無い。**

  一方、**型の内側の階層は揃っている**。「値 ÷ その型の見出し」の比は:
  barsN 30/25=**1.20** / timeline 36/30=**1.20** / compare2 34/26=**1.31** /
  table(3列) 34/26=**1.31** / curve 27/22=**1.23** / band 32/30=1.07。
  band を除けば **1.20〜1.31 に収まる**。

- **判定**: **型の内側の「見出し < 値」の階層(約1.2〜1.3倍)は意図的な設計。
  型をまたいだ絶対値(26〜36pt)は不統一。** 幅・要素数・重要度のどれとも相関せず、
  唯一の例外が table の `NUM_FS = 34 if ncol<=3 else 30`(これは幅から来ている)。
  **要するに、揃える基準そのものが実装のどこにも書かれていない。**

- **選択肢**:

| 案 | 内容 | 根拠・採用例 | 長所 | 短所 |
|---|---|---|---|---|
| 維持 | 26〜36pt のまま | 現行 | 既存2本が変わらない | 揃える基準が無いまま増える |
| 役割→pt の表を決める | 値=34 / 見出し=26 / 注記=26 に統一 | 自前測定の階層1.31 | 型が増えても迷わない | timeline 36→34, barsN 30→34 で既存が変わる |
| 幅から自動決定 | `pt = min(上限, スロット*0.85/字数/1.389)` | text_fit と同じ考え | 占有率が一定になる | ユニット間で数字の大きさが揺れる(ちらつく) |
| 外形基準に合わせる | 全要素を 40px(29pt)以上に | 検索スニペット | 360pで読みやすい | **一次資料ゼロ。しかも出典は「字幕・本文」の話であって図のラベルの話ではない** |

- **比較**: 外形基準について、**反証側で WebSearch を6回投げ直した**。出てくる数字は
  「FHD 1920×1080 の本文は最小 40〜60px」(extron / legibility.info)、
  「FHD なら最低でも 40px 以上」(omniweb)、「1080p のテロップは画面縦の6〜8%、約50pt」
  (video-knowledge)で、**下限は 36px ではなく 40〜60px に集まる**。
  調査員の「4件が 36〜43px で一致」は再現しなかった。
  **さらに重要なのは、これらが全部「字幕・本文」の基準だという点である。**
  このリポジトリの字幕は 40pt = 55.6px で、すでにその帯の中にいる。
  図の中の目盛りや棒の見出しに同じ下限を当てる根拠は、6回の検索では1件も出てこなかった
  (プレゼン資料側のガイドは「軸ラベルは最低18pt」のように**スライドの pt** で書かれており、
  動画の px には換算できない)。**したがってこの外形基準の確度は B ではなく C である。**
  仮に 40px 線を当てると、現行で下回るのは4つではなく **6か所**:
  **barsN の棒下見出し 25pt(34.7px)・barsN の単位 22pt(30.6px)・compare2 の注記 24pt(33.3px)・
  curve の目盛り 22pt(30.6px)・curve の軸ラベル 24pt(33.3px)・curve の水平線ラベル 24pt(33.3px)**、
  さらに 36〜40px の帯に **table ヘッダ 26pt(36.1px)・timeline 注記 26pt(36.1px)・
  compare2 の棒ラベル 26pt(36.1px)・curve の印ラベル 27pt(37.5px)・card の sub 28pt(38.9px)** が並ぶ。
  つまり「外形基準に合わせる」は**7型のほぼ全部を書き換える**話になる。
  自前の360p測定でも「読めない」ことは確認できなかった(局所コントラストは縮小フィルタで
  ±30%動き、LANCZOS ではむしろ1080pより上がる。**この測定はそもそも判定に使えない**)。
- **決定**: **A/Bテスト送り(現状は据え置き)**。
  型をまたいだ絶対値を動かす根拠は、自前測定からは出てこない(占有率の不統一は
  「基準が無い」ことの証明であって「34ptが正しい」ことの証明ではない)。
  外形基準は**一次資料0本**で、しかも**図のラベルではなく字幕の基準**なので確度Cである。
  `docs/research/research-standards.md` の「確度Cで行動を変えない」に従い、**動かさない。**
  代わりに **AB-F1** を設計する(下)。
  ただし **明文化だけは変更**する: `scenes_long.py` の冒頭に
  「値は見出しの1.2〜1.3倍」「値は字幕(40pt)を超えない」という**現状を記述した表**を置き、
  新しい型を足すときの拠りどころにする(数値は1つも変えない)。
- **確度**: 不統一であるという**判定は A**(占有率と階層比は反証側でも再現)。
  外形基準は **C**(スニペットは 40〜60px で一致するが、全部「字幕・本文」の基準であり、

## 測れなかった・分からなかったこと(正直に)

- **外部の一次資料は1本も読めていない。** 反証側で WebSearch を6回投げ直しても、
  出てくるのは 40〜60px という**字幕・本文**の下限だけで、しかも本文は読めていない。

  だからこの数字で実装を動かしていない。
- **色覚シミュレーションの ΔE は実装で1〜2割動く。** Viénot 1999 の LMS 行列・線形化の有無・
  ΔE の式(CIE76 か CIEDE2000 か)で値が変わる。調査員の値と反証側の値が食い違ったのはこれが原因で、
  どちらが正しいかは決められない。**だから ΔE で行動を変えていない**(band の区切り線の根拠は
  ΔE ではなく WCAG のコントラスト比である)。
- **360p の「局所コントラスト」は判定に使えない。** 縮小フィルタ(LANCZOS / BILINEAR / BOX)で
  値が±30%動き、LANCZOS ではリンギングで元の1080pより上がる。
  実機で見る工程がこの環境に無い以上、この測定は「読めるか」の代わりにならない。
- **「どのpt が正しいか」は測れていない。** 測れたのは「いまの値に基準が無い」ことだけである。
  実機のスマホで見て判断する工程がこの環境には無い。
- **視聴データが無い。** 維持率・離脱率は1本も手元に無いので、上の A/B はすべて**設計だけ**で、
  結果は出していない。
- **`F-curve` は7型の一覧に入っていないが実装にはある**(L002 で2本)。
  上では A5b-8 の比較材料として測っただけで、curve 単独の項は立てていない。
  27pt という値は自由空間に置かれており、幅の制約が無いぶん**いちばん理由が無い**。
- **checklist は7型に含めなかった**(課題文の一覧に無いため)。実使用は L001 9本・L002 5本ある。
  stagger は `2.4t - 0.15k` で10項目まで1.0に届くので、この型のアニメは壊れていない(実測)。
