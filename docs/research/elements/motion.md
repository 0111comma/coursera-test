  sig = sig + sum(0.36 / k * np.sin(2 * np.pi * f * k * ts) * np.exp(-ts * (12 + 4 * k))
                  for k in (2, 3, 4, 5, 6))
  sig = sig / np.abs(sig).max() * 0.9   # ピークは現行と同じ 0.9 に揃える

  どの資料にも無い。案B' は RMS を保ったまま HPF600 の落ちを 15dB 縮める。
  **HPF600 の改善量だけを最大化したいなら案Bが上**(-16.5 対 -24.2)なので、
  この2案の選択は **AB-SE-1 で耳とコメントで決める**。

  倍音を中域に置く手法(virtual bass / missing fundamental)も検索3件一致(B)。
  各案の改善量はすべて**自前測定(A)**。
- **確度**: **B**(改善策の効果はA、前提の「スマホは低域が出ない」はB、

        `check_long.py` にはすでに「図のユニットのうち立ち絵ありが50%以下」がある。

        その実験そのものが不合格になる。初版が「現行ゲートは通ることを実測済み」と
        書いていたのは**現行**ゲートの話で、自分が足そうとしているゲートではなかった。
     d. 「非FIGURE の scene で `chara == "none"` を落とす」半分には、
        測定も文献も1つも無い。

  2. **A/Bテスト送り**: 案C(遮蔽率 3% 未満は立ち絵を戻す/19ユニット・69.4秒)と
     案D(連続不在30秒上限)。AB-CH-1 / AB-CH-2。
     **案B(ビルダー判定の明文化)も、いったんここに合流させる。**
     L002 を直したうえで「2本とも同じ形になった」ことを確認してから、
     WARN として入れるかを決める。
- **根拠**: **「判定基準が未定義のまま人の勘で決まっている」という前提は、
  L001 の中では間違いだった**(113/113 でビルダーと一致・検証で再現)。
  だが **リポジトリ全体では前提のほうが正しかった**(L002 は 53件違反)。
  一方、その基準が**正しいか**は別問題で、遮蔽率で見ると
  19ユニットは「消す理由が遮蔽では説明できない」。
  残る理由は CLAUDE.md の「立ち絵は図への注視を奪う」。
  **検証で文献側も当たった**: 視線計測の研究では、講師が画面に出ると
  図への注視は確かに減る(注視を奪うのは本当)が、
  **同時に事後テストの成績が上がる**という報告もあり、
  「消せば学べる」とは言えない(独立3件。確度B)。
  **どちらが自チャンネルの視聴維持に効くかはこの環境では測れない**
  (視線計測もアナリティクスも無い)。だから確度Cとして A/B に送る。
- **確度**: **A**(L001 内のビルダー判定の一致・遮蔽率・不在時間・現行ゲート通過)/

## 測れなかったこと(正直に)

1. **impact の 2.2秒が長すぎるか。** 尾は発話より +3dB 出ているが、
   中心40Hzで声の帯域とほぼ重ならない。マスキングとして害があるかは判定できない。
2. **視聴者の再生環境の内訳。** 「スマホ内蔵スピーカーは低域が出ない」は
   検索スニペット3件で一致したが(B)、**このチャンネルの視聴者の何割が
   内蔵スピーカーで見ているかは分からない**。YouTube Studio のデータが無い。
3. **注視の奪い合い。** 「立ち絵は図への注視を奪う」は測れない。
   代わりに測れたのは遮蔽率だけで、これは注視の一部でしかない。
4. **転換の映像表現が視聴維持に効くか。** 画面変化量は測れたが、
   その大小が離脱率にどう効くかは、公開後のデータでしか分からない。
5. **puchun を長尺で使わなかった理由。** コードにもドキュメントにも残っていない。
   意図的なのか書き忘れなのか、この環境からは判別できない。
6. **「拍」の正しい定義。** 定義を5通り試したら最大無拍は 19.6〜102.5秒まで動いた。

   HPF600 の生き残りと全体RMSがトレードオフになる。**耳で比べる手段がこの環境に無い。**(検証で追加)

## A/Bテストの設計について(このチャンネルの現実に合わせる)

長尺は **L001 の1本しか公開していない**。動画を単位にした A/B は
片群8本×2群=16本が要り、月2本のペースでは8か月かかる。現実的でない。

そこで **1本の中の複数の継ぎ目を使った被験者内比較**にする。
YouTube Studio の視聴維持グラフは秒単位で読めるので、
**同じ動画の中で「印を付けた継ぎ目」と「付けない継ぎ目」の落ち込みを比べる**。
L001 は継ぎ目が5つ(43.2 / 149.7 / 224.0 / 284.2 / 384.5 秒)あるので、
1本で 2群×2〜3箇所が取れる。判定に必要な視聴回数は下の表に書いた。

### この設計で守ること

- **1本の動画で変える項目は1つだけ。** 上の7件を同じ動画に詰めこむと、
  どれが効いたか分からなくなる。順番は **AB-CH-3(前提整備・視聴データ不要)→**
  AB-SE-1 → AB-CH-1 → AB-BEAT-1 → AB-TR-1。
- **A/Bで決まるまで `check_long.py` にゲートを足さない。** 検証ラウンドで却下した2件
  (A7-7 の拍ゲート、A4-13 のビルダー判定ゲート)は、どちらも
  「測れた事実」から「まだ測れていない規則」へ飛んでいた。
  ゲートは**測り終わってから**入れる。
- **視聴回数 1,000回に届かない動画では判定しない。** 維持グラフのノイズが
  継ぎ目の差(2ポイント)より大きくなる。届かない場合は次の動画に持ち越して合算する。
- **判定できなかったものは「効果なし」ではなく「未判定」と書く。**
