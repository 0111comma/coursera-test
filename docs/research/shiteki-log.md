# 指摘ログ — 生のまま貯める場所

ユーザー指示(2026-08-31):
> 「今回出た指摘とかはちゃんと貯めておいてね。あとで貯められた指摘を
>   抽象化してルールにするとかできるから」

**ここは抽象化する前の生の指摘を貯める場所。**
`design-rules.md` / `kotoba-rules.md` は蒸留した後のルール集で、
そこに載せるかどうかを判断する材料がここに溜まる。

## 使い方

- **審査・テストで出た指摘は、その日のうちにここへ追記する。**要約しない。
  「誰が」「何を見て」「何と言ったか」を残す。言い回しを丸めると、
  あとで抽象化するときに元の温度が分からなくなる
- ユーザーの生の言葉は**引用符で原文のまま**残す。これがいちばん価値がある
- 「どう直したか」と「直した結果どうなったか」まで書く。
  直して悪化したものは、それ自体が知見
- 3回以上くり返し出た指摘には ⚠️ を付ける。ルール化の第一候補

## 抽象化の判断(いつルールにするか)

1. **2本以上の動画で出た** → ルール化を検討する
2. **同じ動画で2回以上再発した** → ルール化する(直し方が定着していない証拠)
3. **機械で判定できる** → ゲート化する(`check_*.py`)。
   ただし偽陽性を出すゲートは信用を壊すので、実測で検証してから入れる
4. 1本きりの事情 → ここに置いたままにする

### 2026-09-04 「今日の言い方を直すか、明日の一言を決めるか」→「は? 日本語?」(ユーザー)

冷読の読者4人は「言い方を直す」を意味が通るものとして通した。**LLM の読者は圧縮された言い回しに寛容すぎる**——
「ああ言えばよかった、と考え続ける」を「言い方を直す」に縮めた書き手の語を、そのまま復元してしまう。
人はそうは言わない。**言った後の言葉は直せない。**

直し: 「上司にああ言えばよかった、ってまだ考えてる?」/「今日のことはもういい。明日、上司になんて言うかを決めよう。」
