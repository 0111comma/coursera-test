# 量産型規制(YPP inauthentic content)対策とフォーマット・バリエーション設計

作成: 2026-08-13(deep-loops ㉚)。ユーザー指示「AI活用リスクへの対策を調べてループ改善」による。

## 1. 規制の実態(調査結果の要点)

- **2025-07-15改定**: YPPの「繰り返しの多いコンテンツ」が「非本質的なコンテンツ(inauthentic content)」に改名され「大量生産された(mass-produced)」が明示対象に。YouTube公式(Rene Ritchie)は「既存ポリシーの明確化。AI・リアクション動画の取り締まりではない」と説明。[公式ヘルプ](https://support.google.com/youtube/answer/1311392?hl=ja) / [Social Media Today](https://www.socialmediatoday.com/news/youtube-clarifies-monetization-update-inauthentic-repeated-content/752892/)
- **公式の線引き**: 「イントロ・アウトロが毎回同じ」「シリーズもの」「毎回レビュー動画」はOKと明記。**NGは各動画の中身が実質的に変わらない(not materially varied)こと**。
- **執行実態**: 収益化停止の分析(327件)では、境界は個々の動画の品質でなく「**チャンネル全体を俯瞰したとき、同じ型の差し替えに見えるか**」。2026年1〜2月にショート・ゆっくり/ずんだもん系で大規模なBAN波。停止されたのは観測対象の約2割で、「合成音声だから」ではなく「テンプレ量産だから」。[327件分析](https://note.com/nyosunyosunomi/n/n4083f633dbbf) / [SS@ゆっくり編集効率化](https://note.com/yukkuri_auto/n/n2bb8ecad08a6)
- **復活事例**: ずんだもん系ガジェットチャンネル(電子レンジマン)が「繰り返しの多い量産型」判定→独自素材・自前キャラ等への転換で約3ヶ月後に復活。再審査では「制作プロセスを見せる動画」が決め手になった例が複数。[電子レンジマン一次報告](https://denshirangeman.com/youtube-ban/)
- **AI音声の扱い**: VOICEVOX等のTTS自体は収益化不可の理由にならない(Google日本法人も明言)。ずんだもんのようなキャラクター音声は「実在人物の模倣」でないためAltered/Synthetic開示の必須対象外(開示してもペナルティなし)。金融=YMYLでは「AIペルソナが専門家を装う」形がNG(2026年7月改定で明文化)→ ずんだもんは「一緒に計算する案内役」であり専門家を名乗らない。
- **技術的フラグ(言説ベース)**: 同一素材の使い回し率、サムネ・冒頭数秒の類似、台本のテキスト類似度、機械的な投稿頻度(1日複数本×連続)の複合。

## 2. このチャンネルのリスク評価

| リスク | 状態 |
|---|---|
| 合成音声+静止画+テンプレ構成の三点セット | **該当していた** → 立ち絵(自作アニメーション)導入で軽減(㉙) |
| 毎回同じBGM・同じレイアウト | **該当していた** → BGM3バリエーションのローテーション導入(㉚) |
| 台本構成の固定(数字フック→クイズ→リベール) | 部分該当 → 構成テンプレ6種のプール化(下記) |
| 中身の反復 | 非該当(毎本独自計算・verify.py・出典。公式の「materially varied」を満たす) |
| 人間の関与の証明 | 強い(plan/script/verify/renderのgit履歴=制作証跡そのもの) |

## 3. 3層ルール(固定/ローテーション/毎回変える)

### 層A: 固定する(チャンネルの識別子)
- A-1 「1動画=1つの数字」の編集方針(これは柱であってフォーマットではない)
- A-2 配色パレット・フォント・ずんだもん(声+立ち絵)・ブランド表記
- A-3 コンプライアンス構造(出典・時点表記・仮定明示・verify.py)
- A-4 「独自計算の早見表」というペイオフ(量産型判定への反証材料)

### 層B: ローテーションする(プールから選ぶ。連続する2本で同じものを使わない)
- B-1 構成テンプレート(下記6種+現行クイズ型)。backlogの各ネタに構成タグを付け、投稿順で同タグを隣接させない
- B-2 冒頭3秒のフックの型(数字カウントアップ/クイズ問いかけ/誤解否定/比較提示/シナリオ導入)
- B-3 BGM(shortlib BGM_VARIANTS 3種: Am9系86bpm / Dm9系92bpm / Em9系80bpm。既定は動画IDから自動ローテ)
- B-4 サムネ/カバーのレイアウト(数字の位置・図の有無で2〜3種)
- B-5 尺(45秒/50秒/55秒のクラスを意図的に散らす)

### 層C: 毎回変える
- C-1 数字・計算の切り口(前回のverify.pyのコピーで済まない計算式レベルの差分)
- C-2 台本の言い回し・ユーモア・具体例の人物設定(コンプラ定型文以外のn-gram重複を避ける)
- C-3 グラフ・図解の形式(毎本1点以上の新規描画関数)

### 運用
- 投稿頻度は機械的にしない(1日≤2本、間隔を揃えすぎない)
- 概要欄に「出典+確認日+独自計算である旨」、チャンネル概要に制作体制(台本・計算・図解は人間が検証/音声はVOICEVOX)を明記
- 再審査に備えてリポジトリ(plan/script/verify/renderの段階的コミット履歴)を制作証跡として維持

## 4. 構成テンプレートのプール(7種)

| タグ | 名前 | ビート構造 | 向くネタ |
|---|---|---|---|
| T1 | クイズ型(現行) | 数字フック→常識のフリ→クイズ→フリーズ→リベール→展開→早見表→質問→サゲ | 意外な数字 |
| T2 | 誤解訂正型 | 通説提示→「実は違う」→一次資料/正しい数字→なぜ誤解が広まったか→早見表 | 俗説・SNS誤情報が多い制度 |
| T3 | 比較型 | 2択提示→視聴者に選ばせる→両パターン並走計算→差額ドン→条件別早見表 | 条件で答えが変わるネタ(一括vs分割等) |
| T4 | 人生タイムライン型 | 具体人物(視聴者と同属性)→選択→5年後/20年後/65歳の数字を順に開示→分岐点→早見表 | 時間が効くネタ(複利・年金・iDeCo) |
| T5 | ワースト型 | 「損してる順ワースト3」→3位→2位→1位(最も意外)→合計損失の独自計算→回避チェック | 小ネタの束(手数料・未使用控除) |
| T6 | ビフォーアフター型 | 変更前の数字→「やったことは1つ」→手続き→アフターの数字→対象条件 | 行動1つで数字が変わるネタ |
| T7 | 原文型 | 「この1行読める?」→官公庁の原文を画面に→1語ずつ翻訳→「つまり」→早見表 | 制度の原文が難解なネタ(独自性最強) |

使い分け: **ネタの性質がテンプレを決める**(恣意的なローテにしない)。比率は T1=70%目安から始め、20%をプール内ローテ、10%を実験に。
