## 3. 繰り返し出てきた3つの型

### (a) 自分で作ったゲートが、自分で内容を悪くしていた

**2回起きた。**

1. **`check_video` の「8分以上」を不合格にした結果**、L002 は3.65分で書き終えたあと
   **尺の理由だけで+89ユニット足した**(フェーズ1)
2. **`check_flow` が「各文の頭に接続語」を要求した結果**、
   `接続語 + 読点 + 本文` が最も安い通し方になり、**読点の78%が主題の直後**になった。
   本多勝一の読点2原則のどちらでもない(フェーズ4b)

→ `check_long.py` はこれを設計に織り込んだ。
**「量を増やせば通る判定」は WARN、「量を増やしても通らない判定」だけを不合格。**

### (b) 比率では人の合否を分けられない。分けるのは「回数」

| | L001(**ゴミ**) | S012(**OK**) |
|---|---|---|
| 字数の変化率 | 0.14 | 0.13 |
| 同じ長さ帯の最長連続 | 7 | 7 |
| 文末「のだ」の割合 | 54% | **72%** |
| 「その」始まりの割合 | 36% | 33% |
| **「その」の最長連続** | **4** | **2** |

**比率はどれも合否を分けない。** 18回では単調と知覚されず、157回では知覚される。
効いているのは**繰り返しの絶対回数**。

→ **比率をゲートにしなかった。** 「のだ」を直しに行っていたら、
ユーザーが合格させたものを壊していた。

### (c) 測る道具が無かったから見えていなかった

ユニット単位のゲートは9つあったのに、
**「30秒時点で何が出ているか」「章の出口に答えがあるか」を測る道具が1つも無かった。**

→ `timeline_long.py`(目で見る)→ `check_long.py`(落ちる)の順で作った。

## 6. まだ分かっていないこと(正直に)

### いちばん大事な限界

> **`check_long.py` の15の不合格条件は、人の合否で検証されていない。**
> ユーザーが合格させた長尺は1本も無い。
> **「全部通れば合格する」とは言えない。**

閾値の出どころを分けて書く。

| 根拠の強さ | 項目 |
|---|---|
| **確度A の研究から** | 数字を図の上で言う / 図なし25秒 / 章の出口の判定 / 図の上の立ち絵5割 / 終了画面の枠 |
| **確度B の実務ソースから** | 冒頭の数値15秒・図20秒 / 45〜75秒の切れ目 / 話速290〜360 / 止め3箇所 / 継ぎ目の重なり / 次の動画の名指し |
| **確度C + 実測から決めた設計判断** | 章の数5以下 / 各章60〜150秒 |

### 確度Cで採用しなかったもの

- 5〜10分の維持率31.5% / 60秒で55%離脱の具体値
- チャプターで維持率12〜18%増
- 節は3〜5分(フェーズ3の「1章100〜130秒」と食い違うため却下)
- 終了画面のクリック率3〜7% / 到達率30%
- 立ち絵の位置を動かす / 性別による効き方の違い
- 「図の中の短い語句が効く」を根拠に章札へ問いを戻すこと
  (静止スライドの実験で、動画での検証がない)

### 自チャンネルで検証すること

1. **30秒地点の残存率**(冒頭の型が効いているか)
2. **チャプター別の維持率**(章の長さ・順序が効いているか)
3. **話速と維持率**(329字/分が妥当か)
4. **BGMあり / なし**(確度Aの研究はテストの点で、視聴時間ではない)
5. **終了画面のクリック率**
