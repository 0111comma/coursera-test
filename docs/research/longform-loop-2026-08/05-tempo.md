# フェーズ5: 話速と間

自己診断 H2「話速がショートのまま。SPEED_SCALE=1.3 で8分は疲れる」と
H8「間が無い。ショートの詰め方のまま」を潰す。

このフェーズは**調べて、実測して、数字を決めて、コードに入れた**。

## 調べたこと

### 日本語の話速の目安

| 区分 | 速さ | どういう場面か |
|---|---|---|
| ゆっくり | **200〜250字/分** | 落ち着いた朗読、高齢者向けの説明、情緒的なスピーチ |
| **標準** | **300〜350字/分** | **アナウンサーのニュース読み、ビジネスプレゼン** |
| 速め | **400字/分〜** | YouTubeの解説系、テンポ重視のTikTok、情報を詰めるプレゼン |

「NHKの1分300文字ルール」が最も伝わる速さとされ、
時代とともに速くなって350字で読むアナウンサーもいる。

(確度**B**。話速の帯は複数の独立ソース(NHK関係の記事・ナレーション制作会社・
読み上げ時間の算出ツール)で数値が一致する。ただし維持率との関係を示した実験ではない)

### 間(ま)は、強調したい語の前後に置く

> 文章の中で重要な部分に鍵かっこをつけるように、
> ナレーションでも**重要な部分の前後に少し間を作る**ことで、
> その単語が強調され、視聴者の印象に残る。
> 間の位置を間違えるとニュアンスが変わるので、**どこで間を置くか事前に決めておく**。

(確度**B**。ナレーション制作の実務ソース複数で一致。**秒数は書かれていない**)

**秒数の根拠が無いので、そこは自分で決めて記録する。**(後述)

## L001 のどこが、それに反しているか

```
声だけ   481.6s / 3197字 → 398字/分
無音込み 505.2s          → 380字/分
1文の速さ: 平均406字/分 最速509 最遅275 変化率0.12
無音の合計 23.6s(4.7%) = 1ユニットあたり0.15s
speed の分布: [1.0, 1.05, 1.1, 1.15]  → 実効 1.30〜1.495
pad の分布 : [0.15, 0.2]
```

### 1. 長尺のほうがショートより速い。順序が逆

| | 声だけ | 無音込み | 区分 | ユーザー判定 |
|---|---|---|---|---|
| **S012**(55秒のショート) | **352字/分** | 335字/分 | 標準の上限 | **「S12OK」** |
| **L001**(8分25秒の長尺) | **398字/分** | 380字/分 | **速め** | **「ゴミ」** |

**8分の動画を、55秒のショートより13%速く読んでいた。**
ショートは押し付けられるので速さで指を止める必要があるが、
長尺は**選ばれて再生される**(フェーズ1)。速くする理由が無い。

しかも**「速め(400字/分〜)」はTikTok・ショート向けの帯**であって、
8分の解説はその帯で通すものではない。

### 2. 8分25秒で、無音の止めがゼロ

- `pad` は **0.15 と 0.2 の2値だけ**。無音の合計は 23.6秒(4.7%)で、
  これは全ユニットに機械的に付いている0.15秒の合計にすぎない
- **章の出口の判定の直前に間が無い**
  (#29「そのNISAは、増やす仕組みではないのだ」/
  #73「その裏側で、引けるはずだった損が消えているのだ」/
  #118「だからその年は、小さいほうの額の20.315%を余分に払う」)
- 研究が言う「重要な部分の**前**に間を置く」を一度もやっていない

### 3. 話速がユニット単位でばらついているだけで、塊になっていない

`speed` は 1.0/1.05/1.1/1.15 の4値だが、**1文ごとにばらついている**ので
「ゆっくり説明する区間」と「速く畳む区間」という**塊が無い**。
1文の速さの変化率は0.12。研究の言う「速い区間のあとに遅い区間」になっていない。

## 何を変えるか

### 1. 長尺の話速を 1.3 → 1.15 に下げた(**実装済み**)

`production/shortlib.py`:

```python
LONG_SPEED_SCALE = 1.15
# use_landscape() が、環境変数の指定が無いときにこれへ差し替える
```

**実測で確認した。** L001 の20ユニットを新しい倍率で合成し直して測ると:

```
use_landscape 後の SPEED_SCALE = 1.15
ユニットの speed [1.0, 1.05, 1.1, 1.15] → 実効 [1.150, 1.208, 1.265, 1.322]
20ユニットの実測: 文字409 / 70.9s → 346字/分
```

**398字/分 → 346字/分。「標準」の上限に入った。**
S012(352字/分)よりわずかに遅く、8分の動画としては妥当な位置。

**ショートは 1.3 のまま**(ループ58でユーザーが「もうちょっと早く」と言った結果なので触らない)。

### 2. 話速の判定を `timeline_long.py` に入れた(**実装済み**)

```
話速の判定(05-tempo.md):
  380字/分(無音込み 505.2s / 3197字)   ← 速すぎる。8分続けると疲れる(速めは400字/分〜)
```

- **360字/分を超えたら NG**(「速め」の帯に入るため。400ではなく360で切るのは、
  標準の上限350にわずかな余裕を足した位置)
- **290字/分を下回ったら NG**(標準の下限300に余裕を足した位置)
- フェーズ11で `check_long.py` に移す

### 3. 間の秒数を決めた(研究に数字が無いので自分で決めて記録する)

| 場所 | pad | 理由 |
|---|---|---|
| ふつうのユニット | **0.15s** | 現状のまま。詰め気味が定石 |
| **章の出口の判定の直前** | **0.6s** | 研究の「重要な部分の前に間」。フェーズ4の「止め」の実装 |
| 章の出口の判定のあと | **0.4s** | 判定を置いたまま黙る |
| 章札の直前 | **0.5s** | 章が変わることを音で示す |

**0.6秒の根拠は研究には無い。** 4分の1拍〜半拍ぶんの黙りが
「置いた」と分かる最短だという判断で、**次の長尺で聞いて調整する**前提の値にする。
フェーズ13(検証)で実際に聞いて、この表を更新する。

### 4. 話速は塊で変える(台本の手順)

- **章の前提を説明する区間は `speed=1.0`**(実効1.15 = 311字/分)
- **判定と畳みは `speed=1.15`**(実効1.322 = 約357字/分)
- 1文ごとにばらつかせるのではなく、**章の中で前半遅く・後半速く**

### 5. 見つけた不具合を直した(**実装済み**)

**署名に `SPEED_SCALE` が入っていなかった。**
`render_video` の再開判定は `u.speed` を見ているが全体倍率を見ていないので、
**話速だけ変えたときに古い音声をそのまま使い回す**。
今回まさにその変更をしたので気づいた。`SPEED_SCALE` と `W, H` を署名に追加した。

| # | 何を | どう | いつ |
|---|---|---|---|
| 1 | `shortlib.py` | `LONG_SPEED_SCALE=1.15`、`use_landscape()` で差し替え | **済** |

122ユニット前後になり、**約8.5分**に収まる見込み。

### 仮説として記録(確度Cなので行動を変えない)

- **346字/分が長尺の最適値かどうか**は分からない。
  帯(標準300〜350)は確度Bだが、**この帯が維持率に効くという実験は見ていない**。
  長尺が3本たまった時点で、自チャンネルの維持率と話速を突き合わせる
- **0.6秒の止め**も自分で決めた値。フェーズ13で聞いて調整する
