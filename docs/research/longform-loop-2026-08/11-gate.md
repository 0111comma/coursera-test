# フェーズ11: ゲート — 通しで落ちる機械チェックを作る

自己診断 H9「長尺用の機械ゲートが無い。ショート用の8ゲートを流用しているだけで、
通しの単調さを誰も見ていない」を潰す。

## なぜ必要だったか(事実)

**L001 を「ゴミ」と判定されたとき、ショート用の9ゲートは全部通っていた。**
1ユニットずつの品質は基準内なのに、通して見ると成立していない。

フェーズ2〜10で測る道具を `timeline_long.py` に足してきたが、
**あれは目で見る道具で、通らなくても走ってしまう。**
だから同じ判定を、**落ちるゲート** `production/check_long.py` にした。

## 設計で効かせた反省(フェーズ1)

フェーズ1の発見はこうだった:

> `check_video.py` に「推定尺 8分以上」を不合格条件として入れた。
> そのゲートのせいで L002 は66ユニット(3.65分)で書き終えたあと
> **尺の理由だけで+89ユニット足している。**
> **自分で作ったゲートに自分で内容を薄められた。**

だから今回は分けた。

| 種類 | 扱い | 理由 |
|---|---|---|
| **量を増やせば通る判定** | **WARN(落とさない)** | 飾りを足して通してしまう |
| **量を増やしても通らない判定** | **不合格** | 置き方を直さないと通らない |

具体例:

- 「**図が6割以上**」→ **WARN**。意味のない図を足せば数字は上がる
- 「**数字を図なしで言わない**」「**図なしが25秒続かない**」→ **不合格**。
  図を足すだけでは通らず、**どこで何を言うかを直さないと通らない**

同じ理屈で「各章の図が4割以上」も WARN、「表情の偏り」も WARN にした。

## もう1つの設計判断: レンダリング前に走る

`timeline_long.py` は `output/work/*.wav` から秒を読むので、
**一度レンダリングしないと使えなかった。**
2〜3時間焼いてから落ちるのでは、フェーズ1の失敗と同じ構造になる。

`check_long.py` は音声があれば実測、無ければ**字数から推定**する。

```python
# 長尺の1文字あたりの秒。ショートの 0.152 は SPEED_SCALE 1.3 のときの実測値で、
# 長尺は 1.15 に下げた(05-tempo.md)ので 1.3/1.15 倍する
SEC_PER_CHAR_LONG = 0.152 * (1.3 / 1.15)
```

**推定の精度を確認した**: L001 は実測505.2秒。同じ式の推定は509.5秒(誤差0.9%)。
L002(未レンダリング)は推定519.9秒・334字/分 で、**話速の判定を通った**。
新しい定数が妥当だと確認できた。

### 不合格になるもの

| 判定 | 基準 | 根拠 |
|---|---|---|

| 止め | pad≥0.5s が3箇所以上 | 04(確度B) |
| 話速 | 290〜360字/分 | 05(確度B) |
| 数字が図の上にない | 1割以下 | 06(確度A) |
| 図なしの連続 | 25秒以下 | 06(確度A) |
| 各章の出口の判定 | 全章にある(問いは判定に数えない) | 07(確度A) |
| 全体量の予告 | 冒頭60秒までに | 07(確度B) |
| 図の上の立ち絵 | 5割以下 | 09(確度A) |
| 終了画面の枠 | 最後の20秒に免責・退出の言葉なし | 10(確度B) |
| 次に見るものの名指し | 最後の20秒に1本以上 | 10(確度B) |

### WARN(落とさない)

| 判定 | 基準 | なぜ落とさないか |
|---|---|---|
| 図の割合 | 6割以上 | 飾りの図を足せば通る |
| 各章の図 | 4割以上 | 同上 |
| 表情の偏り | 8割以下 | 表情を散らせば通る。置き所が大事 |

### 入れなかったもの

**フェーズ4で測った「字数の変化率」「同じ長さの連続」「12字以下の短文の割合」は入れない。**
ユーザーが「OK」と言った S012 と「ゴミ」と言った L001 で値が一致してしまい、
**人の合否と一致しないため**(ループ51の約束)。参考値として
`timeline_long.py` に残してある。
