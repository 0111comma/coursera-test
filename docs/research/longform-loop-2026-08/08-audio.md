# フェーズ8: 音 — BGM・SE・無音

自己診断 H7「BGMが1本で通し。章が変わっても音が変わらない」を潰す。

**H7 は方向が逆だった。** 研究は「章ごとにBGMを変えろ」ではなく
**「余分な音は減らせ」**と言っている。しかも効果量が非常に大きい。

## 調べたこと

### 一貫性の原則 — 余分な音は学習を下げる。効果量1.66

> 一貫性の原則: **余分な語・絵・音を除いたほうが、入れるよりよく学べる。**
> 認知理論の枠では、**BGMを含む「そそる細部」が作業記憶を無駄に占め、学習を妨げる。**

Moreno & Mayer (2000) が雷とブレーキの教材で行った2つの実験:

> **BGMと環境音の両方を受けた群は、どちらも受けなかった群より
> 保持・転移の両方で成績が悪く、効果量は 1.66 と非常に大きかった。**

Mayer (2021) も「音楽は余分な認知負荷を生み、学習を妨げるだろう」としている。

(確度**A**。効果量つきの実験で、複数の独立ソース(ERIC の2023年論文・
ResearchGate・複数の教育工学の教材)が同じ数値と結論を引いている)

### ただしこれは「テストの点」の話で、「視聴時間」の話ではない

**ここを混ぜてはいけない。**

- 研究が測っているのは**保持テスト・転移テスト**の成績
- このチャンネルが要るのは**視聴時間**と、**ユーザーが面白いと判断すること**
- **公開済みの11本はすべてBGM入りで、ユーザーはBGMについて一度も指摘していない**

だから **BGMを外すことはしない。** 外せば確度Aの研究には沿うが、
**ユーザーが通した11本を否定する**ことになる(ループ51の約束に反する)。

代わりに、**衝突しない範囲でだけ**一貫性の原則を適用する(後述)。

---

## L001 のどこが、それに反しているか

### 1. 実測: BGMは声より26.9dB下で、ほぼ問題になっていない

完成した `L001.mp4` の音を、ユニットごとに切って測った。

```
声のある区間の RMS : -14.7 dBFS (n=157)
pad(声なし)の RMS : -41.7 dBFS (n=157)
→ BGM は声より 26.9 dB 下
pad区間のばらつき   : 最小 -52.9 / 最大 -23.7 dBFS
完全な無音(RMS < -60dBFS)の pad: 0箇所 / 157
```

`shortlib` にはすでにサイドチェインのダッキングが入っている
(`sidechaincompress=threshold=0.015:ratio=6:attack=8:release=300`)ので、
**BGMは喋っている間ほぼ聞こえない**。
一貫性の原則から見て、いまのBGMの扱いは悪くない。

### 2. **8分25秒に、完全な無音が1箇所も無い**

157個の pad すべてでBGMが鳴っている。
フェーズ4で「止めがゼロ」、フェーズ5で「間がゼロ」と書いたが、
**音の側から見ると「無音がゼロ」**でもある。

### 3. **これが一番大事** — 0.6秒の「止め」は、実装すると逆効果になるところだった

フェーズ4で「章の出口の判定の直前に pad 0.6秒の止めを置く」と決めた。
**ところがダッキングの release は300msなので、0.6秒黙ると
その間にBGMが戻ってきて盛り上がる。**

同じフィルタ構成で、止めありの区間を作って測った:

| | 声あり(1.0〜1.8s) | **止め(2.35〜2.55s)** |
|---|---|---|
| **BGMを切らない** | -21.0 dBFS | **-25.6 dBFS** |
| **BGMを切る** | -21.0 dBFS | **無音** |

**切らない場合、止めの最中のBGMは声より4.6dB下しかない。**
つまり「黙って聞かせる0.6秒」を作ったつもりが、
**「BGMだけが急に大きくなる0.6秒」**になる。

L001 の現状は pad が 0.15秒しかないので(release 300ms より短い)
BGMが戻る前に次の声が来る。**だから今は起きていないが、
フェーズ4の変更を入れた瞬間に起きる不具合だった。**

### 4. SEの密度は9%。増やす理由が無い

```
SE: 14箇所 / 157ユニット = 9%  内訳 {'pop': 6, 'impact': 3, 'don': 5}
puchun: 5箇所
```

環境音が学習を下げる(効果量1.66の実験に含まれる)ので、**増やさない。**
9%はむしろ適量とみなす。

## 何を変えるか

### 1. 止めの間はBGMを切る(**実装済み**)

`production/shortlib.py`:

```python
LONG_STOP_PAD = 0.5   # これ以上の pad は「止め」。その区間はBGMも切る
```

`render_video` が `pad >= 0.5` のユニットから区間を作り、`assemble` に渡す:

```python
if bgm_mute:
    windows = "+".join(f"between(t,{a:.3f},{b:.3f})" for a, b in bgm_mute)
    filters.append(f"[bg]volume=0:enable='{windows}'[bgq]")
```

**実測で確認した**(上の表)。止めの区間が本当に無音になる。
`pad < 0.5` の動画では区間が空になり、**従来とまったく同じミックス**になる。
公開済みの11本には影響しない。

### 2. **章ごとにBGMを変えるのはやめる**(H7 の却下)

自己診断では「章が変わっても音が変わらない」を欠点として挙げていたが、
一貫性の原則(確度A・効果量1.66)から見ると、
**章ごとに音を変えるのは余分な変化を足すことになる。**

- **BGMは1本で通す。** いまの `bgm_variant` を動画ごとに1つ選ぶ形を維持する
- 章の切れ目を音で示すのは、**BGMの切り替えではなく「止め」と `don` のSE**で行う
  (音を足すのではなく、音を抜くことで切れ目を作る)

### 3. SEは増やさない

9%を上限として扱う。**「盛り上げるためにSEを足す」ことをしない。**

### 4. BGMを外すことはしない(確度Aの研究に沿わない判断を、理由つきで残す)

研究は「BGMなしが最良」と言っている(効果量1.66)。それでも外さない理由:

1. 研究が測っているのは**テストの点**で、このチャンネルが要るのは**視聴時間**
2. **公開済み11本はすべてBGM入りで、ユーザーは一度も指摘していない**
3. 現状のBGMは声より**26.9dB下**で、ダッキングも効いている(実測)

**この判断は仮説として検証できる。** 長尺を2本作るとき、
1本をBGMなしにして維持率を比べる。フェーズ13で提案する。

### 変えるファイル

| # | 何を | どう | いつ |
|---|---|---|---|
| 1 | `shortlib.py` | `LONG_STOP_PAD`、止め区間のBGMミュート | **済** |
| 2 | `L001 / L002 の render.py` | 章の出口の直前に pad 0.6(フェーズ4)。これで1が効く | フェーズ12 |
| 3 | `docs/research/longform-design.md` | 「音は足さずに抜く」を節にする | フェーズ14 |
| 4 | `docs/strategy.md` | BGMを外さない判断と、その検証計画を残す | フェーズ14 |

### 仮説として記録(確度Cなので行動を変えない)

- **BGMなしのほうが維持率が高いか。** 研究(確度A)はテストの点では「なしが良い」と言うが、
  視聴時間での検証は見ていない。長尺2本でA/Bして比べる
- **BGMの音量をさらに下げるか。** いま声より26.9dB下。
  これを32dB下にしても気づかれないかもしれないが、根拠が無い
- **外向性で効き方が変わる**という研究(「そそる細部か、有益な効果か」)があるが、
  視聴者ごとに出し分けられないので使えない
