# 長尺動画の改善プログラム(2026-08-17)

ユーザー指示:
> ゴミ。長尺動画をどう作ったらいいのか、前行ったみたいに要素に分解して
> 一つずつリサーチを行なって。改善ループを立ち上げて。

## 何が起きたか(言い訳なしの事実)

L001(NISA・8分25秒)を出したが、判定は「ゴミ」だった。

**私がやったのは、ショートの作り方を155ユニットぶん並べただけ**である。
`docs/research/longform-design.md` は書いたが、中身は
「ショートのルールを持ち込む」「章=ショート1本」という**引き伸ばしの設計**で、
**長尺そのものを要素に分けて調べていない**。

ショートで通用した8ゲートをそのまま横型に通したので、
1文1画面・同じ話速・同じ立ち絵・同じBGMが8分続く。
1本ずつの文は基準を満たすのに、**通して見ると単調**になる。
これは各ユニットの品質の問題ではなく、**長尺という形式を調べていない**問題である。

## 着手前の自己診断(仮説。各フェーズで潰す)

L001 を自分で通して見て、疑わしい所を先に列挙する。

| # | 疑い | なぜそう思うか |
|---|---|---|
| H1 | **リズムが一定すぎる** | 155ユニットすべて「1文=1画面」。8分間ずっと同じ拍 |
| H2 | **話速がショートのまま** | SPEED_SCALE=1.3。押し付けられるショート用の速度で8分は疲れる |
| H3 | **画面が文字カード中心** | 図のあるユニットは4割強。残りは語を大きく出しているだけ |
| H4 | **章の切れ目が機械的** | 「では第N章」で6回。切れ目に演出も間もない |
| H5 | **進んでいる感じがない** | 40,630円が何度も出るが、どこまで来たかが分からない |
| H6 | **立ち絵が8分間同じ** | 位置・大きさ・出番が一定。いる意味が薄い |
| H7 | **BGMが1本で通し** | 章が変わっても音が変わらない |
| H8 | **間(ま)が無い** | ショートの詰め方のまま。8分ぶん息継ぎが無い |
| H9 | **長尺用の機械ゲートが無い** | ショート用の8ゲートを流用しているだけ。通しの単調さを誰も見ていない |

**このプログラムは、H1〜H9 を1つずつ調べて潰す。**

## 進め方の約束(前回のプログラムと同じ形)

- **1フェーズずつ**。トリガーが発火したら、下の表で状態が「未」の一番上を**1つだけ**実行する
- 各フェーズは**成果物のファイルを1つ以上残す**。残っていなければ未完了
- 各フェーズの終わりに、この表を更新してコミット・プッシュする
- **1フェーズでトークンを使い切らない。** 調べることを絞る
- 判断が要る所は決めて、理由を「判断ログ」に書く
- **調査は `docs/research/research-standards.md` に従う。**
  行動を変える主張は独立ソース5本以上+一次資料1本以上。確度A/B/Cを必ず付ける
- **確度Cで行動を変えない。** 自チャンネルで検証する仮説として記録する

## 各フェーズで必ず答えること

調べっぱなしにしない。どのフェーズも、最後にこの3つを書く。

1. **何が分かったか**(確度つき)
2. **L001 のどこが、それに反しているか**(具体的なユニット番号・秒数で)
3. **何を変えるか**(コード・台本・ドキュメントのどれを、どう)

3が書けない調査は、調べ方が悪い。やり直す。

## 判断ログ

### フェーズ3(2026-08-17 09時台)

- **`longform-design.md` の「章 = ショート1本」が構成の間違いの元だった。**
  研究側では「**60〜90秒ごとの拍**」と「**章という話題のまとまり**」は別物で、
  拍は**章の中に**置く(確度B)。私は拍の間隔を章の長さにしたので、
  **話題のリセットが90秒ごとに6回**起きている。
  → **章は4つ・1章100〜130秒**に決めた。拍は章の中に置く。
- **継ぎ目で同じ問いを2回言っていた。28.5秒(全体の6%)。**
  6つの継ぎ目のうち5つが重なり60%以上、ch5 は**100%**
  (出口「では、この不利はいくらまで効くのだろうか」→ 章札「この不利は、いくらまで効くのか」)。
  研究は「閉じる前に次を予告する」と言っているのに、**開いて開き直していた**。
  → **章札は問いを繰り返さず、答えの側を予告する**に変える。
- **章の長さが計画と一致していなかった。** plan.md は各章120〜140秒なのに実物は44〜84秒で、
  **計画に無い ch1 が増え、締めが ch6 に埋まっていた**。書きながら章を増やしたため。
  → templates/plan.md の構成表を4章+冒頭+締めの枠にし、章ごとに図の予定も書かせる。
- **図の割合が前半21〜36%、後半54〜61%。離脱する側が薄い。**
  → 各章40%以上を基準にし、timeline_long.py で章ごとに測るようにした。
- **L002 も同じ形だった**(6章・継ぎ目3つが重なり50%以上・ch4は逆にループを開いていない)。
  フェーズ0でレンダリングを止めた判断は正しかった。フェーズ12で両方直す。

### フェーズ2(2026-08-17 08時台)

- **冒頭は3段構え**(0-5秒 割り込み / 5-15秒 具体的な約束 / 15-30秒 引っかけ。確度B)。
  実務側が挙げる「やってはいけないこと」の3番が
  **価値の約束より先に前提を置く**で、L001 はそれをそのままやっていた。
  5.3〜17.1秒が全部前提と定義で、数値が1つも出ていない(最初の数値は22.3秒)。
- **冒頭30秒に動きのない画が続くと離脱率が上がる**(確度B)。
  L001 は **0〜19.9秒がすべて文字カード**(hero 2枚 + card 5枚)だった。
- **冒頭の勢いを本題に橋渡しし、リセットしない**(確度B)。
  L001 は 53.0秒に「では第1章。NISAは、お金を増やしてくれるのか」を置いており、
  離脱の山のど真ん中で別テーマに移っている。研究が「やるな」と言う崖そのもの。
- **道具が無かったことが原因だと分かった。** ユニット単位のゲートは8つあるのに、
  「30秒時点で何が出ているか」を測る道具が1つも無かった。
  → `production/timeline_long.py` を作った(秒単位のタイムライン + 冒頭3項目の判定)。
  フェーズ11でこれを機械ゲートにする。

### フェーズ1(2026-08-17 07時台)

- **8分はミッドロール広告の条件で、視聴者のための数字ではなかった**(確度A)。
  そして私は `check_video.py` に「推定尺 8分以上」を**不合格条件**として入れていた。
  そのゲートのせいで、L002 は66ユニット(3.65分)で書き終えたあと
  **尺の理由だけで+89ユニット足している**。自分で作ったゲートに自分で内容を薄められた。
  → **尺の下限をゲートから外し、WARNに落とした。** 判定は企画の段階に移し、
  plan.md に「尺の見込み」を書かせる(check_yokkyu で必須化)。
- **60秒で55%以上が離脱する**(確度B)。L001 は **53.0秒に第1章の切れ目**を置き、
  しかもその第1章は損の話ではない寄り道だった。本題(第3章)は180.8秒。
  → フェーズ12で章の順序を組み替える。
- **答えの金額(40,630円)が出るのは30.3秒**。15秒以内に価値が出ていない。
  15秒までの6文のうち2文が用語の定義に使われている。
  → フェーズ12で冒頭を組み替える。定義は答えの後ろへ。

### フェーズ0(2026-08-17 06時台)

- **L002 のレンダリングは止める。** 同じ作り方で2本目を焼いても、同じ判定になる。
