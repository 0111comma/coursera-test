# 欲求の地図 — どの欲求に訴求するかを先に決める(2026-08-17)

ユーザー指示(ループ67):
> 「人のどの欲望・欲求に訴求すべきなのか、まず設計してからプロットを書くという
>   プロセス自体はかなり今後も重視してね」

このドキュメントは**企画の一行目に何を書くか**を決めるためのもの。
`ideas/backlog.md` も `plan.md` も、ここで選んだ欲求から書きはじめる。

---

## 1. 順序 — これを逆にすると必ず雑学になる

```
欲求  →  場面  →  決定  →  数字
```

**数字から始めない。** 面白い数字を見つけて、それに合う視聴者を後付けすると、
出来上がるのは「へえ」で終わる動画になる。

実際にそうなった例が S012 だった。「会社は年収400万円の人に460万円出している」という
面白い数字から企画を立て、視聴者を後付けした。結果は2回とも却下:

> 「会社が出してるから何なの?っていう。ただの雑学ですか?っていう。
>   会社が払ってくれてんだね、ありがとうで終わる動画をわざわざ見続けようと思わなくない?」

**しかも2回とも「オチを鋭くする」方向で直していた**(会社も同じ額 → 69%しか残らない)。
出発点が数字である以上、オチをいくら鋭くしても雑学のままだった。
直すべきは**出発点**だった。

同じ社会保険料でも、欲求から立て直すとこうなる:

| | 数字から立てた版 | 欲求から立てた版 |
|---|---|---|
| 出発点 | 「460万円」という面白い数字 | 「残業代で手取りを増やしたい」という欲求 |
| 場面 | (無い) | 4〜6月に残業した |
| 決定 | **無い** | 残業を寄せる月を選ぶ |
| 数字 | 460万円 / 145万円 / 69% | 68,112円 / 2,631円 / 91歳 |
| 判定 | 「面白くない」×2 | — |

## 2. このチャンネルが使う欲求(A〜D)

強い順に並べてある。**損失回避のほうが獲得より強い**(確度B。行動経済学の通説で、
自チャンネルのアナリティクスで検証する仮説として扱う)。

### A. 取られたくない — 知らないうちに引かれるのが嫌だ

- **場面**: 給与明細を見た / 手数料を取られた / 税金の通知が来た / 更新の案内が来た
- **決められること**: 減らす・時期をずらす・止める・確かめる
- **このチャンネルの例**: S012(4〜6月の残業)/ S014(ATM手数料)/ S015(住民税)
- **note**: いちばん強い。「自分の財布から、自分の知らないうちに出ている」が核

### B. 大きな選択を間違えたくない

- **場面**: 家を買う / ローンを組む / 保険に入る / 口座や商品を選ぶ
- **決められること**: どちらを選ぶか
- **このチャンネルの例**: S013・L002(変動金利と固定金利)
- **note**: **金額が大きいので、判定を1つの数字に落とせると強い**。
  「3.83%」のような分かれ目は、この欲求のためにある

### C. 持っているものを無駄にしたくない

- **場面**: 含み損がある / 枠が余っている / 使わないまま期限が来る
- **決められること**: 使うか・動かすか・放っておくか
- **このチャンネルの例**: L001(NISAの含み損)/ S005(ふるさと納税の上限)
- **note**: すでに持っている人だけが対象なので、母数は小さいが刺さり方が深い

### D. 先の不安を減らしたい

- **場面**: 老後・病気・失業を考えたとき
- **決められること**: 備えの量を決める / 繰下げるかどうかを決める
- **このチャンネルの例**: S011(年金の元が取れる年齢)/ S009(高額療養費)
- **note**: 不安を煽らない。**数字を出すと不安はむしろ下がる**、という方向で作る

## 3. 単独では使わない欲求

### E. 自分の位置を知りたい(人と比べたい)

- 例: S008(平均919万円と中央値130万円)
- **決められることが弱い**。「比べる相手を変える」しか出てこない
- 使うなら **A〜D のどれかと組む**。単独だと雑学に落ちる

### F. 賢く見られたい・人に言いたい(雑学欲)

- **使わない。** これが「へえ」で終わる動画の正体
- 旧 S012 はここに落ちていた。会社の支出額は、話のネタにはなるが、
  聞いた人の身には何も起きない

## 4. 企画を立てるときに順に答える4つ

`plan.md` の一行目から、この順で書く。

1. **この人の欲求** — 何をしたい / したくないのか。**「〜したい」「〜したくない」の形で書く**
   - ×「社会保険料について知りたい」(それは欲求ではなく主題)
   - ○「残業代で手取りを増やしたい。でも知らないうちに引かれるのは嫌だ」
2. **場面** — その人がいつ、何をしているときにこの動画に出会うか
3. **視聴後に決められること** — 見終わったあと何を決める・何をするのか
   - **ここが「知る」「分かる」で終わるなら、その企画は雑学**。捨てるか、立て直す
4. **その決定を支える数字** — 自前計算で出せるか。出せないなら企画を捨てる

`production/check_yokkyu.py` が 1 と 3 を機械で見る。
2 と 4 は目で見る(企画書の「想定視聴者」と verify.py)。

## 4b. 「話題の近さ」を「場面の近さ」と取り違えない(ループ71)

伸びた動画の**隣**を狙うとき、隣り合っているのが**話題**なのか**場面**なのかを分ける。

旧 S016 は S003(NISA枠1800万・視聴率64.1%)の隣を狙った。
話題は同じ「NISAの投資枠」だった。だが場面は「**売る**」で、
S003 の視聴者がいまやっているのは「**積み立てる**」だった。

ユーザーの指摘は一言だった。

> 「だから何って思う。これは**どの欲求に訴求している動画なの?**」

`demand-2026-08.md` に自分で書いた分かれ目(上位3本=視聴者がいまやっていること /
下位3本=やっていないこと。差40ポイント)を、企画の側で外していた。

**確かめ方**: その動画の損得が発生するのは、視聴者の何%か。
旧 S016 は「生涯投資枠1800万円を使い切りそうな人」だけだった。
埋めている途中の人には、簿価で戻ろうが戻るまいが**何も変わらない**。

`check_yokkyu.py` は企画書に欲求の**文字があるか**しか見ないので、ここは通ってしまう。
**目で見るしかない。** 見るのは1つ、「この動画の損得は、誰の身に起きるのか」。

## 5. 落ちているかどうかの判定法

書き上がった企画を、この一文に入れて読む:

> **この動画を見た人は、見る前と何が変わるのか。**

- 「◯◯を知った」しか出てこない → 雑学。落ちている
- 「◯◯するかどうかを決められる」「◯◯が自分の身に起きると分かった」 → 通っている

既存作をこれに通した結果が、ユーザーの合否とそのまま一致した:

| 本 | 見る前と何が変わるか | ご判定 |
|---|---|---|
| S014 手数料 | 下ろす時間・回数・口座を変える | 「流れとても良い」 |
| S015 住民税 | 辞める前に、来年ぶんを残しておく | 「良いね」 |
| S011 年金 | 自分の寿命で損得が決まると分かり、繰下げを判断できる | 合格 |
| S012 旧 社保 | **何も変わらない**(会社の支出額を知っただけ) | 「面白くない」×2 |
| S013 金利 | **何も変わらない**(3.83%という数字を知っただけ) | 「意味わかんない」 |

## 6. 確度と限界(research-standards.md)

| 主張 | 確度 | 根拠 |
|---|---|---|
| 数字から立てた企画は雑学になりやすい | **B** | 自チャンネルの合否5本と一致。ただしn=5 |
| 損失回避のほうが獲得より強い | **B** | 行動経済学の通説。自チャンネルでは未検証 |
| A〜Dの強さの順序 | **C** | 上の推論。**アナリティクスで検証する仮説**として扱う |
| 「決められること」の有無が合否を分ける | **B** | 5本すべてで一致。**次の5本でも一致すればAに上げる** |

確度Cは企画の**優先順位づけ**にだけ使う。どれを先に作るかの順番であって、
「この欲求は使わない」と切り捨てる根拠にはしない。
