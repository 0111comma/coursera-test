# 見た目をどう変えるか(2026-08-23)

ユーザー指摘:「そろそろ同じ背景にただ図とかが出されるスタイルに限界を感じてきた」。
あわせて「Claude Code が私のPCを使って、Gemini などのAPIを使わずに動画生成する方法」と
「そうでなくとも視覚的に視聴維持率を高められる方法」を調べる。

**先に結論**: 測ったボトルネックは「背景の写実性」ではなく **画面が止まっていること**。
AI動画生成より先に、**カメラを動かす**ほうが効く。しかもGPUもクラウドの外も要らない。

---

## 1. 診断(自分のショート30本を実測)

`anim=0.0` で同じ場面が続く区間の長さを、全ショートで数えた。

| | 最長の静止 | 5秒超の静止が占める割合 |
|---|---|---|
| **S001〜S015(旧型)** | 3.1〜4.0秒 | **0%** |
| **S016〜S031(新型13本)** | 9.1〜17.6秒 | **81〜95%** |

調べた基準(下記ソース):

- **同じカットが5秒以上続く動画は視聴完了率が下がる。**
  カメラアングル・テロップ・BGMのいずれかを**3秒ごとに**変えるのが鉄則
- **静止画・ロゴから始まる動画は3秒以内に90%がスワイプ**
- 最初の1秒で「動き」を入れる

**新しく作った13本が、すべてこの基準に違反している。**
しかも旧型は偶然満たしていたので、**時間とともに悪化した**。

原因ははっきりしている。「数字は図の上で言う」ゲート(自分で足した)を通すために、
同じ図へユニットを積み上げた。長尺でも同じことが起きて、
字幕帯より上の画素が **15〜20秒 0.00%** しか変わらない区間ができていた。
**ゲートを通すいちばん安いやり方が、見た目を壊していた。**

## 2. 選択肢の比較

| | 効果 | コスト | GPU | いま動くか | ポリシー risk |
|---|---|---|---|---|---|
| **A. カメラを動かす**(ffmpeg zoompan) | **大**(静止をゼロにできる) | 小(+20秒/本) | 不要 | **動く** | なし |
| **B. 場面転換をつける**(ffmpeg xfade) | 中 | 小 | 不要 | 動く | なし |
| C. 文字と図を動かす(キネティックタイポグラフィ) | 中 | 中 | 不要 | 動く | なし |
| D. 背景を動画ごとに変える(非AI) | 中(不満に直接効く) | 小 | 不要 | 動く | なし |
| E. ローカルAI動画生成(Wan 2.2 等) | 小〜中 | **大** | **要** | ユーザーPCのみ | **あり**(下記) |

### A の裏付け(実際に作って測った)

S030 の場面を1枚書き出し、いまと同じ「静止3.5秒」と、
3.5秒で1.00→1.06倍に寄る版を作って画素を比べた。

| | 隣接フレームの変化 | 先頭→末尾 |
|---|---|---|
| いまと同じ(静止) | **0.00%** | **0.00%** |
| 寄り(Ken Burns) | 2.11% | 5.38% |

生成コスト: 1ユニット3.5秒あたり **+1.2秒**。17ユニットの動画で **+20秒**。
いまのレンダリング時間(1本10〜15分)に対して誤差。

**これだけで「同じカットが5秒以上」を構造的にゼロにできる。**
寄り/引き/横パンを場面の型ごとに割り当てれば、同じ図でも毎回ちがう見え方になる。

## 3. ローカルAI動画生成(RTX 4070 / 12GB)の現実

調べた結果、**動くことは動く**が、使い道は限られる。

| モデル | 12GBで動くか | 備考 |
|---|---|---|
| **Wan 2.2 5B**(fp16 9.3GB) | **動く** | ComfyUIの自動オフロードで可。720p・24fps向け |
| Wan 2.2 14B | 条件つき | GGUF量子化 + T5エンコーダをCPUに逃がして **480pまで** |
| HunyuanVideo 1.5(8.3B) | 厳しい | 下限14GB。オフロード前提でも12GBは苦しい |
| LTX-2.5 | 不可 | FP8でも32GB(5090級) |

速度の実測例: 640×640の5秒で約1分43秒。

**ここから出る結論**:

- 50秒のショートを丸ごと生成するのは非現実的(1本あたり30〜75分、しかも
  カット間で絵がつながらない)
- 現実的な使い道は **「背景ループの素材を一度だけ大量に作って、使い回す」**。
  3〜5秒のシームレスループを20本作れば、当分の背景に困らない
- ただし **Claude Code をユーザーのPCで動かす必要がある**。
  いまのセッションはクラウドのコンテナなので、そこにGPUは無い

### ポリシーのリスク(無視できない)

- 2026年1月以降、**「AIスロップ」の一斉取り締まり**で収益化停止が多発。
  停止はチャンネル横断で波及しうる
- **金融は名指しの分野**: 「AI生成の人物が人間の専門家として振る舞う」コンテンツは
  医療・健康・法律・**金融**・政治で収益化不可
- ただし禁止されているのは**人物ペルソナ**であって、背景素材の生成ではない。
  判定軸は「制作者が独自の価値を足しているか」。本チャンネルは独自計算があるので
  その点は満たす
- とはいえ **わざわざ名指しの分野で、判定の曖昧な要素を増やす理由が無い**

## 4. 推奨

**A(カメラ)→ D(背景の作り分け)→ B(場面転換)→ C(文字の動き)の順で、非AIから進める。**
E(ローカル生成)は「背景素材ライブラリ」としてあとから足せる。急ぐ必要はない。

理由:

1. 測ったボトルネックは静止であって、背景の写実性ではない。**Aだけで違反81〜95%→0%**
2. GPUもユーザーPCも要らず、**いまのクラウド環境で完結する**(=今日から手が動く)
3. ポリシーのリスクをゼロのまま進められる
4. Eは前提(ローカル実行環境)が要り、効果はAより小さく、リスクは大きい
