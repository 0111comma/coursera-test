# 新デザイン(自前キャラ)1本目の検収記録 — S032

2026-08-23。競合(@bankacademy)の分解から起こした新デザインで、
初めて1本を通した。**焼く前にフレームを1枚ずつ目で見た**ときに出た欠陥と、
その直し方を残す。次の1本で同じ穴に落ちないためのもの。

## 1. ゲートが自分の作った装飾に誤爆した

新テーマ(`fplib.use_fp_theme`)は**全フレーム共通で**上部の帯とバッジを描く。
これを `check_figure` が「図の中の文章」と数え、`check_align` が数値として拾い、
16件の不合格になった。**本当の指摘がその中に埋もれる。**

直し方: 帯とバッジの Text/Patch に `gid = "fp_chrome"` を付け、
図のゲート3本がその印を見て集計から外す。位置(アンカー)で判定していた
旧テーマの方式は、テーマを増やすたびに壊れる。

## 2. 切り抜きPNGの透明な余白が「画面外」を鳴らしていた

立ち絵は1024×1024の中に人物が浮いている。人物の幅は約720px(70%)しかないのに、
`draw_pose` は1024のまま軸を置いていたので、軸の枠だけが画面の外に出た。
**絵は見えていないのに、毎シーン「画面外(左右)」が出る。**

直し方: `pose()` の読み込み時にアルファのバウンディングボックスで切る。
ゲートが黙るだけでなく、`cx` が人物の中心と一致するようになる。

## 3. カバーの帯が、カバー自身の文字の上に乗っていた

カバーは全面を黄色で塗る(zorder 1.5)。テーマの帯は zorder 3.0 なので**上に来る**。
1フレーム目、いちばん見られる絵で文字が重なっていた。

直し方: `F.hide_chrome(fig)` をカバーの先頭で呼ぶ。zorder で殴り合わない。

## 4. 大きい数字のユニットで、立ち絵が打消し表示を隠していた

`hero()` は立ち絵を `top=0.90` に置いていた。仮定バッジは y≈0.876 にある。
つまり**「※ 利回りは仮定。元本保証ではありません」が髪で隠れていた**。
コンプライアンス表示なので、見えないのは欠陥。
加えて、赤い数字が立ち絵の胴を横切っていて、絵が切れて見えた。

直し方: 図が主役のユニットは立ち絵を消す(既存の規則どおり)。
`hero()` に立ち絵を渡す場合も、バッジより下(`top=0.845`)に小さく置く。

## 5. 締めのボタンが、置き忘れた灰色の板に見えた

`cta(show_button=True)` は角の立った灰色の矩形だった。しかも立ち絵の体に重なっていた。
角丸の黒(#1f1f1f)+ 白文字にして、立ち絵を上に寄せて体から外した。

## 6. VOICEVOX は「空」を**ソラ**と読む

「82歳で空です」は「ハチジュウニサイデ**ソラ**デス」になった。
`check_yomi` は辞書に無い複合語しか見ないので、この手の**一語の読み違い**は
台本を書いた時点で `audio_query` に投げて確かめるしかない。
今回は全22ユニットを投げて、他に読み違いが無いことを確認してから焼いた。

## 7. ゲートに合わせて台本を曲げると、台本が壊れる

`check_flow` は漢字・数字の一致しか見ない。言い換え・並列・対句を繋がりと認識しない。
そこに台本を合わせにいった結果、「16年を、65歳から始めるとします。」のような
日本語が生まれ、ユーザーに「プロットがよくわからん」と言われた。

**出した結論**: 台本を先に自然に書き、ゲートの誤検出は
`production/gate_exempt.txt` に**理由を書いて**外す。理由の無い行は無効。

そして**不要になった免除は消す**。今回、台本を直したら13件のうち4件は
自然に通るようになった。残したままだと理由が腐り、次に読む人が信用しなくなる。

## 追記(2026-08-23夜): 文字数の上限を外したら、ゲートの穴が3つ出た

ユーザー指示:

> 「文字制限かけて何言ってるかよくわからない文章になるなら文字制限かけない方がいい。」

冒頭をユーザーの33字案「老後資金の1000万円。毎月5万円ずつ使うと、何歳で尽きる?」に戻した。
字幕が3行になるので、**文を削るのではなく描画側を直した**
(`fplib._subtitle` が3行以上のとき**上へ**伸ばす。下に伸ばすと Shorts のUI に入る)。

そのうえで全ゲートを走らせたところ、**ゲートの側に3つ穴が見つかった。**

### 穴1: check_toi — WARNに降格したのに、まだ落としていた

`MAX_CHARS = 20` を「問いが長い(WARN)」に降格したが、`main()` で
`total += len(issues)` と数えたままだった。**表示だけ直して判定は直っていない。**
WARNを数えないようにした。

### 穴2: check_video — 「字幕2行以内」が裸の定数だった

根拠が書かれていなかった。実測するとこうなっている(1080×1920・新テーマ):

| 行数 | インク上端 | 立ち絵(h=0.44 top=0.855)の下端 |
|---|---|---|
| 1行 | 1403px | 1123px |
| 2行 | 1434px | 1123px |
| 3行 | 1213px | 1123px(余白90px) |
| 4行 | 約1077px | **重なる** |

**3行は通し、4行で落とす**に変えた。3行のときはWARNを出して、
基準を緩めた場所が黙って隠れないようにした。横型は行送りが違うので2行のまま。

### 穴3(いちばん重い): check_overlap の字幕帯が固定値だった

`SUBTITLE = (0, 0, 1, 0.245)` という**2行ぶんの固定値**。
ところが実測の上端は 1行 y=0.2693 / 2行 y=0.2531 / **3行 y=0.3682**。
つまり3行字幕は禁止領域より **0.12(約236px)高いところ**に出ていた。

そのせいで、S032 の hero「300か月」に3行字幕が**丸かぶりしたフレームが
check_overlap を通過した**。見つけたのは機械ではなく、焼く前のフレーム目視。

```
[NG] kikan  字幕帯に重なる: 「300か月」   ← 直したあとのゲートはこう出る
```

直し方は定数の足し算ではなく、**その文をその場で描いて外接箱を測る**。
行数の効きは block_fit の縮小と絡むので、式では当てられなかった。

### ついでに見つかった穴: 全動画スイープが S032 で止まっていた

`check_overlap.py` を引数なしで走らせると

```
AttributeError: module 'verify' has no attribute 'MONTHS_0'
```

で落ちる。動画ごとの `verify.py` が**どれも "verify" という名前**なので、
1本目の verify が `sys.modules` に残り、2本目以降が別の動画の verify を掴む。
**S032 より後ろの動画が1本も検査されていなかった。**
`_load` で動画ディレクトリのモジュールを読む前後に片づけるようにした。
