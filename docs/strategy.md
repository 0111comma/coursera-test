# チャンネル戦略: お金・金融リテラシー

最終更新: 2026-08-12 / テーマ選定の経緯と市場調査は [research/theme-candidates.md](research/theme-candidates.md) を参照。

## 1. コンセプト

**「数字で見るお金の教科書」— すべての主張に出典と計算根拠がある、日本一検証可能なマネー教育チャンネル**

競合大手(リベ大、中田大学など)は「経験談・意見・生き方」型。本チャンネルは真逆の
**「公的データ + 実計算シミュレーション」型**で差別化する。

- 動画内の数字はすべて Claude Code が実際に計算・検証したもの(複利、手取り、税額、年金…)
- グラフ・図表はすべて公的統計(金融庁、国税庁、厚労省、総務省、日銀)から独自生成
- この「毎回オリジナルの計算とチャートを含む」構造自体が、YouTubeの量産型コンテンツ規制への防御になる

## 2. ターゲット視聴者

**主: 20〜35歳の社会人。「NISAやiDeCoって聞くけど、実は仕組みを分かっていない」層**

- お金の不安はあるが、何から学べばいいか分からない
- 長い動画・難しい本は続かない → Shortsで「1つの数字」から入ってもらう
- 特定の商品を売り込まれるのは警戒している → 「制度と数字の解説だけ、勧誘なし」が刺さる

## 3. 提供価値と差別化

| | 競合大手(意見・経験談型) | 本チャンネル(データ・計算型) |
|---|---|---|
| 根拠 | 個人の経験・思想 | 公的統計と実計算(全て出典明記) |
| スタンス | 「こうすべき」 | 「制度はこうなっている。計算するとこうなる」 |
| 検証可能性 | 低い | 全ての数字が再計算可能 |
| 商品への言及 | 特定サービス紹介あり | 個別商品・銘柄には一切言及しない |

## 4. コンテンツピラー(4本柱)

1. **制度解説** — NISA、iDeCo、ふるさと納税、社会保険、税金の仕組み(事実ベースで正確性を担保しやすい主戦場)
2. **シミュレーション** — 「月1万円を20年積み立てたら?」「年収400万の手取りは?」(Claude Codeの計算力が最も活きる)
3. **統計で見る日本のお金** — 平均貯蓄額、年金の実態、物価の推移(公的統計の独自可視化)
4. **制度改正ニュース** — 税制改正、制度変更の速報解説(ネタの自動供給源、Shorts向き)

## 5. フォーマット定義

### ショート動画(毎日1本、30〜55秒)
- **プロット: [research/plot-playbook.md](research/plot-playbook.md) に準拠**(敵・賭け金・フリオチ・感情アーク・チェックリストD1〜D22)。ジャンル共通の物語原則なので、将来の哲学・教養系にもそのまま使う
- **型: 「1動画 = 1つの数字」**。フォーマット面の制作ルール(R1〜R14)は [research/short-video-format.md](research/short-video-format.md) に準拠する
- **クラスタ設計**: ショート3〜4本と解説動画1本を同一トピックで束ねる(相互送客と型の学習)
- 冒頭1秒: 数字のカウントアップ(ミュートでも伝わる・動きで親指を止める・第一声で言い切る)
- 本体: 1文=1画面変化の2秒ルール。グラフは「動いて積み上がる」見せ方で種明かし
- 結び: 冒頭につながるループ(別パターンの数字)+視聴者への質問でコメント誘発
- 画面: 太字テロップ(縁取り+数字だけ黄色強調)+ずんだもんナレーション(VOICEVOX、話速1.2)+小音量BGM

### 解説動画(週1本、5〜15分)
- **型: 「教科書の1章」**。その週のShortsで反応が良かったトピックを深掘りする
- 構成: 結論先出し → 制度の仕組み → シミュレーション(複数パターン) → 落とし穴・注意点 → まとめ
- Shorts が集客、解説動画が再生時間(収益化条件の4,000時間)を稼ぐ役割分担

## 6. コンプライアンスルール(全動画で厳守)

YMYL領域 × AI制作の組み合わせは炎上・規制リスクが高い。以下を企画テンプレートのチェックリストに組み込み、例外なく適用する。

1. **投資助言をしない**: 個別銘柄・特定の金融商品・特定の証券会社を推奨しない(金融商品取引法上、投資助言は登録業者のみ可能)
2. **断定しない**: 「儲かる」「必ず」「〜すべき」を使わない。利回りは常に「仮定」と明示(例:「年利5%と仮定した場合」)
3. **出典必須**: 動画内のすべての数字・制度説明に出典(官公庁の一次資料を優先)を付け、概要欄に記載する
4. **計算検証必須**: 動画内の計算はすべてコードで再計算し、検証スクリプトを企画に添付する
5. **制度の時点を明示**: 「2026年8月時点の制度です」を必ず入れる(税制・制度は毎年変わる)
6. **免責を入れる**: 概要欄に「本動画は情報提供を目的としており、投資助言ではありません」を常設

## 6.5 制作・投稿の運用ルール(検証ループ第2〜30で確立。iteration-log-2.md参照)

- **デザイン規格**: 黒背景×白テロップ×金アクセント(検証済みパレット)、Noto Sans CJK JP Black、字幕52pt・12字折り返し。運用益・お金の系列色は金(#c98500)
- **音声規格**: ずんだもん話速1.2・強調ユニットは抑揚1.1〜1.15、BGMは本編の15%、SEは強調4〜5箇所限定、書き出しは-14LUFS。オチのリベールは「プチュン→インパクト音」の音だけのフリーズ演出を1箇所まで(映像の暗転はしない。assets/se/impact.mp3)
- **冒頭**: 完成形カバーフレーム(=サムネ)を0.07秒先頭に挿入。thumbnail.pngをサムネ設定に使う
- **投稿時間・頻度**: 火・木・土 19:30固定の週3本、1日1本まで(詳細スケジュール・根拠は[posting-plan.md](posting-plan.md)。㉛で改訂)
- **A/Bテスト**: 公式「テストと比較」でサムネ最大3案・1要素ずつ変更・CTRより維持率を優先
- **公開前チェック**: `python3 production/check_video.py videos/<ID>-<slug>` が ALL PASS であること(尺・音量・解像度・禁止語・クレジット等14項目)。物語面はplot-playbook.mdのD1〜D22を人が照合
- **キャラ利用**: 概要欄に「VOICEVOX:ずんだもん」(音声・必須)+「立ち絵: 坂本アヒル 様」を記載(素材readme: クレジット任意だが慣行として記載)([公式ガイドライン](https://zunko.jp/guideline.html))。立ち絵の演出規格はdeep-loops㉙(口パク=RMS連動・目パチ3.5秒±1.5・表情2〜4種/本・字幕最前面)。禁止: 政治宗教・個人非難・ずん虐
- **概要欄・固定コメント**(深掘りループ⑪): 概要欄は1行目に検索語・タグ3〜5個を末尾(タイトルに入れない)・免責/出典/時点表記を常設。固定コメントは動画のCTA質問を選択式で再掲して投稿直後に固定し、初動1〜3時間は返信を最優先。コメント欄にURLは貼らない(スパム自動保留対策)

## 7. 収益化ロードマップとKPI

| フェーズ | 目標 | 主要KPI |
|---|---|---|
| 0〜3ヶ月 | フォーマット検証 | Shorts視聴維持率50%以上の「型」を見つける / 週次で企画→投稿サイクルが回る |
| 3〜6ヶ月 | 登録者1,000人 | 登録者数、解説動画の平均視聴時間 |
| 6〜12ヶ月 | 収益化達成 | 総再生4,000時間(解説動画ルート優先。Shortsの1,000万回/90日は狙わない) |

- 収益化は**長尺ルート(登録者1,000人+4,000時間)を本線**とする。Shortsは集客装置と割り切る
- 初期3ヶ月は数字を追わず、「1動画=1つの数字」フォーマットの改善に集中する

## 8. 量産型コンテンツ規制への対策(再掲・最重要)

収益化審査・維持で「独自性なし」と判定されないため、全動画に以下の**いずれか2つ以上**を含める:

- [ ] 独自に計算したシミュレーション結果(検証コード付き)
- [ ] 公的統計から独自生成したグラフ・図表
- [ ] 制度の原文(法令・官公庁資料)に基づく独自の噛み砕き解説
- [ ] 複数パターンの比較(年収別・年齢別など、視聴者が自分事にできる切り口)

「AI音声 + ストック画像 + どこかで見た話」の組み合わせだけの動画は**作らない**。

2026年8月追記(量産型規制の深掘り=[research/format-variation.md](research/format-variation.md)):
- 公式の線引きは「フォーマット固定はOK、中身と見た目の複合的な同一性がNG」。**固定(パレット・1動画1数字・コンプラ)/ローテ(構成テンプレ7種・BGM3種・フック型・サムネ構図・尺)/毎回変える(計算・台本・図解)の3層**で管理する
- ずんだもんの立ち絵は坂本アヒル様のPSD素材(ユーザー提供・自由利用/商用可/改変可)。口パク・表情切替・呼吸・ジャンプはzunda.pyが音声連動で自動合成=静止画の使い回しでない動きのある映像
- 概要欄に制作体制(台本・計算・図解は人間が検証)を明記。リポジトリのコミット履歴=再審査時の制作証跡
- 投稿は機械的にしない(1日≤2本・間隔を揃えすぎない)。ずんだもんは「一緒に計算する案内役」であり専門家を装わない(YMYL×AIペルソナ規制)
